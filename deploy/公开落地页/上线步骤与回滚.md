## 现网核对到的事实（2026-10-08 22:05–22:35，全部只读命令）

1. `systemctl cat wtsj-api` → `ExecStart=.../uvicorn app.main:app --host 0.0.0.0 --port 8000
   --proxy-headers --forwarded-allow-ips=127.0.0.1`。限流那 6/小时要按访客真实地址分桶，
   前提的一半（uvicorn 侧）已经成立。
2. `/etc/nginx/sites-enabled/agentsbin-cn` 里 `agentsbin.cn` 那个 server 块是
   `root /var/www/agentsbin-cn;` + `location / { try_files $uri $uri/ /index.html; }`，
   **没有** `/n/` 这条，也**没有** `.well-known` 那条。所以今天 `https://agentsbin.cn/n/xxx`
   回的是水印站首页那张 HTML，状态码 200。
   后端只在 `api.agentsbin.cn/wtsj/` 这个前缀下可达。
3. `sudo find /var/www -name "apple-app-site-association*"` → **0 个结果**，这台机器上从来没有过 AASA。
4. `sudo grep -c association /etc/nginx/mime.types` → **0**；`nginx.conf:26` 是
   `default_type application/octet-stream;`。所以 AASA 必须显式 `default_type application/json`。
5. 现网 `alembic current` → `a9d3e5c7f218 (head)`，和本地活动树一致；
   `TuMaiBiJi-1.9.30` 那份快照的 head 停在 `a7d2e5b8c310`，**落后 3 条**。
   这就是这批改动必须落在 `TuMaiBiJi` 而不是快照里的硬理由：
   在快照里写迁移会造出第二个 head，`alembic upgrade head` 直接报 multiple heads。
6. 现网库是 **SQLite**（`engine.url.get_backend_name()` → `sqlite`），不是 Postgres。
   `shares` 18 行、`expires_at` 非空 **0 行**、同一 `note_id` 多行的组数 **3**、
   `is_active=0` 的行 **4** → "撤掉之后可以重新分享"这条在现网是**已经在发生**的事，
   而 `ux_shares_one_active_per_note` 的实际定义是
   `CREATE UNIQUE INDEX ... ON shares (note_id) WHERE is_active = 1`，确实是部分索引。
   （顺带把 `is_expired()` 那句"只有上线前建的那批带 expires_at"钉成待核：现网 0 行带，
   那句话要么已经过期、要么那批行早被删了。）

## 你要点头的那三件事，按这个顺序做

下面每条都写了"跑什么"和"跑完看什么才算成"。**第 1 步不做完，第 2、3 步都是白做**：
AASA 指向的是 `/n/*`，那条路不通的话装了 App 也进不去。

### ① 后端上现网（会改数据库：建一张新表）

```bash
cd /Users/zlfmac/Documents/TuMaiBiJi/backend && ./upload.sh
ssh agentsbin && cd /home/ubuntu/wtsj-backend && ./deploy.sh
```

`deploy.sh` 自己会跑 `alembic upgrade head`，所以新表是它建的，不用手动执行 SQL。

跑完在**这台 Mac 上**验（`/n/` 还没接进 nginx，所以先打 api 子域那条已通的路，
它和后端是同一个进程，能证明"代码真的上去了、路由真的挂上了"）：

```bash
curl -s -o /dev/null -w '%{http_code} %{content_type}\n' \
  'https://api.agentsbin.cn/wtsj/n/一个现网真实token'
```

期望：`200 text/html; charset=utf-8`，且响应头有 `cache-control: no-store`。
**404 也可能是对的**——如果那个 token 已经被作者撤掉。判"上没上"要看的是
它回的是**落地页那张 HTML**（里面有"这是作者当时生成的快照"这句），不是官网首页。

### ② nginx 两段 + AASA 文件（这一步才让 `agentsbin.cn/n/` 真的通）

```bash
# 先备份，再改
ssh agentsbin 'sudo cp /etc/nginx/sites-enabled/agentsbin-cn /root/agentsbin-cn.bak.$(date +%Y%m%d-%H%M%S)'
# 把 deploy/公开落地页/apple-app-site-association 传到服务器
scp deploy/公开落地页/apple-app-site-association agentsbin:/tmp/
ssh agentsbin 'sudo mkdir -p /var/www/agentsbin-cn/.well-known && sudo mv /tmp/apple-app-site-association /var/www/agentsbin-cn/.well-known/apple-app-site-association'
# 再把 nginx-agentsbin.cn.片段.conf 那两段贴进 agentsbin.cn 那个 server 块
ssh agentsbin 'sudo nano /etc/nginx/sites-enabled/agentsbin-cn'
ssh agentsbin 'sudo nginx -t && sudo systemctl reload nginx'
```

`nginx -t` 不过就**别 reload**，把备份拷回去即可，现网会一直跑旧配置。

验（这三条是"上线"这件事唯一的判据，部署完必须回来跑）：

```bash
# 1) AASA 存在、状态 200、内容类型必须是 application/json
curl -sI https://agentsbin.cn/.well-known/apple-app-site-association | grep -iE 'HTTP/|content-type'
# 2) 落地页走的是后端不是官网首页
curl -s https://agentsbin.cn/n/<真实token> | grep -c '这是作者当时生成的快照'
# 3) 撤掉的码与不存在的码回同一张纸（两个都 404 且正文逐字节相同）
curl -s https://agentsbin.cn/n/<已撤token> | shasum; curl -s https://agentsbin.cn/n/乱写的 | shasum
```

第 3 条两个 shasum 必须相同。不同就是"能探测谁曾经公开过"，撤回等于没生效。

### ③ App 侧（另一条线，见 iPhone 那边那两份账）

`project.yml` 里给 target 加 `com.apple.developer.associated-domains: ["applinks:agentsbin.cn"]`，
**必须写进 `properties`**——XcodeGen 会按 properties 重新生成 entitlements 文件，
只改文件不改 yml，下一次 `xcodegen generate` 就把它清空（这条在 macOS 那边踩过，
`xcodegen-clobbers-info-and-entitlements`）。

## 还没做、也不在这三份文件里的（要拍）

1. **Apple 1.2 那三件里"屏蔽"这一件做不到，而且不是偷懒**：公开页上的作者只有一个
   `author_name` 字符串，没有可指向的账号身份，所以"屏蔽这位发布者"没有对象可屏蔽。
   甲 = 等 iPhone 侧账号（SIWA）落地、作者有稳定 ID 之后再做"不再看到这位的内容"；
   乙 = 现在就做"按关键词/来源过滤"那一件（Apple 原话里的 content filtering），
   它不需要作者身份。**建议甲＋乙同时排**，因为乙本来就是 1.2 的另一半，跟身份无关。
   代价：乙要在只读页加一层本机过滤设置，约半天。
2. **`og:image` 故意没给**。服务器有没有中文字体没核过，现画的卡图很可能是一堆豆腐块，
   一张错图比没图更糟。补之前要先在服务器上装/确认 CJK 字体，那是第 4 件要点头的事。
3. **iPhone 自己建的笔记拿不到 token**：`POST /api/shares/` 要微信 JWT，而 `note_id` 是外键，
   本机笔记在服务器上根本没有行。这一条卡在身份方案（甲 SIWA / 乙 设备密钥），
   是"两端都能出码、都能被扫"这个需求的最后一块，也是唯一还堵着的一块。
