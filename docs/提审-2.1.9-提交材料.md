## 二、这一版相对线上那一版（2.1.8）的差

基线 `10e64a6`（2.1.8 那一趟的最后一刀）→ HEAD `85aa47e`，动 `miniprogram/` 的 17 个文件（+560／−287）。用户看得见的六条，逐条对着代码：

1. **私密笔记换一篇就要再验一次密码**。判据从「这一屏问过没有」换成「服务端认得的那把凭证＋这一篇的号」（`utils/privateGate.js` 新增 `needsUnlock`／`unlockOn`）。原来首页是常驻 tab，问过一回整个会话都不再问；同一篇从编辑那一趟回来仍不重复问（这条是他 10-12 拍的口径）。
2. **重置密码后原加密笔记打不开、又不提示输密码——修掉了**。他报的那条死路：换／重置密码会把凭证清掉（`api.js` 里那两位跟着 `clear`），页面那个布尔没人清，于是既不弹框、又只看到标题。现在作废手上那把再问。
3. **没设过密码时给得出门**：后端那句给日志看的「尚未设置私密密码」原来被当吐司直发，人就卡在既进不去又不知道去哪儿；现在认这一种失败，弹一层「去『我的』设置」，确认直接 `switchTab` 过去。
4. **两个密码框统一**：解锁那一框从系统 `wx.showModal({editable:true})`（六位密码明文摆在屏上）换成「我的」设／改／重置同一层模板（`templates/pwd-sheet.wxml`＋`styles/pwd-sheet.wxss`＋`utils/pwdSheet.js`，三页共用一份实现），输进去的每一位画成一枚点。
5. **不输密码就只看标题**：列表那一趟永远不带解锁凭证（`api.js` 加 `noUnlock`）。带着它，服务端会把这一页**所有**私密篇的摘要一起发下来并留在 `data.notes` 里——症状是"验过一次之后别的私密篇不问就露摘要"。
6. **新建笔记拍完一张能继续加拍**：那一枚 ➕ 补 `data-source="any"`（`pages/create/create.wxml`）。漏了它 `pickImage` 读到 `undefined`，发出去是 `sourceType:[undefined]`，第二张再也进不了相机。

另有两条不改变画面但改口径的：`app.js` 注销时把私密解锁凭证跟着身份清掉（与卡片、名片那两处 `signOut` 同一口径）；`cardCloud.dropServer` 里 `known` 声明挪出 `try`（原来 catch 那一支自己抛 `ReferenceError`，那句"失败就撤"从来没执行过）。

**不提的一条**：后台那一趟弹的「接口未配置在 app.json 文件中且无权限」——见第四节，这是平台申报口径，不是功能。

## 五、「接口未配置在 app.json 文件中且无权限」那一层弹窗（本版新撞到的）

现象：点「提交审核」弹这一层，正文「以下接口未正确配置在 app.json 文件中且暂无权限，勾选协议可继续提交，该版本发布后，用户将无法使用相关接口能力。」，接着是一行「接口未正确配置：」——**冒号后面是空的**，HTML 里那一段是 `<p><span data-component="translate">接口未正确配置</span>：</p>` 后面什么名字都没渲染出来。唯一的勾选项是「已阅读并了解《地理位置接口新增与相关流程调整》，该版本无法使用未正确配置接口。」勾上之前「继续提交」是灰的（`weui-desktop-btn_disabled`），另有一枚「申请权限」。

**我们的实情（10-12 这一批现核，不沿用上一版结论）**：全仓 `getLocation`／`chooseLocation`／`scope.userLocation`／`requiredPrivateInfos` **零命中**；`miniprogram/app.json` 的顶层键只有 `pages`／`sitemapLocation`／`style`／`tabBar`／`window`，既无 `permission` 也无 `requiredPrivateInfos`。⇒ 那句「该版本无法使用未正确配置接口」对我们**是真话且无害**：本来就不用位置类接口，发布后也用不上，用户不受影响。勾掉这一条不构成虚假申报（这一版确实没把任何位置接口写进 app.json）。

要留个影的两点：① 弹窗里那份接口名单**在我们这一侧读不出来**（渲染成空），所以不能报成"某某接口没配"；② 这一层是 10-12 才见到的，10-11 那一趟的记录里是开发版本卡片上同一句话，形态不同——别拿旧笔记当这一趟的实据。

## 六、这一趟自动化踩到的（已并进记忆）

- **标签序号会漂，而且漂得比我上次记的更凶**：11:2x 我按「窗口 1／标签 4」去 reload，结果 reload 了站长那枚豆包对话页（他中途动过 Chrome，那两枚后台标签已经搬到**窗口 2**）。⇒ 只按 URL 片段找标签，且**每次调用都重新找**，别把序号存下来复用；要写操作（reload／点按钮）前再一次确认命中的是 `getcodepage` 那一枚。
- **驱动里那句 `activate` 有风险**：AppleScript 注 JS 前把 Chrome 抱到前台，人正按键盘时就会把回车送到焦点按钮上。这一趟 11:21:32 那次提交**是不是**我这一把 `activate` 连带出来的，我证不了——所以第三节只报"没核实"，不报"没影响"。下次跑提审自动化：**不 activate，不 reload，纯读**。
- 后台正文读顶层 `document.getElementById('app').innerText`（`<wujie-app>` 那棵 shadowRoot 是右下角客服挂件，里面有枚看不见的「请使用微信扫码」，照它判"登录掉了"会误诊）；`/wxamp/wacodepage/getcodepage` 是菜单里那个锚点的真 href，`/wxamp/newversion/devversion` 是旧路由。
- 那两类按钮对 `element.click()` 静默无反应，要派完整一串 `pointerdown → mousedown → pointerup → mouseup → click`（这一趟实测派在「提交审核」上**确实开了后续流程**）。
- 判"这版有没有真提上去"只看**整页 reload 后**的审核版本那一格；未 reload 的标签会一直挂着旧状态（11:2x 两枚标签一格有一格没有，就是这个）。
