## 一、他这两句拆成四个动作

1. 「能否根据 URL，拉起页面」⇒ 需要一次**真渲染**（执行 JS），不是现在那一路 httpx 拿静态 HTML。
2. 「如果无法获取图片，自动截图」⇒ 截图是**兜底**，排在"图能正常取到"之后，不是每次都截。
3. 「并写入笔记」⇒ 那张 PNG 要走已有的压缩／进桶／`assets` 登记，最后能在笔记里看见。
4. 「单独做一个功能，和现有的 URL 文字提取功能分开。单独做一个 API 功能」⇒ **新路由、新任务、新开关**，
   不挂在 `process_url_task` 上、不改它任何一行行为。

第 4 条是他 10-19 14:0x 补的，把这一条从我原先设想的位置（贴图那条链的最后一格兜底）挪走了。
**挪走之后有两处跟着变**，写下来免得下一个人当"顺手加一段"：
① 黑名单那条判据（"200 但正文 0 字"记一次站点失败）不再被这条链碰到——它不提炼文字、不该拿渲染结果去改记账；
② 这条链要自己建一篇笔记（还是往已有笔记里加图），是一个新问题，见第六节末那一格（**我没替他定**）。

## 二、这把量了什么（两把新尺子，都能重跑）

- `docs/工具/诊断-0字那一族的HTML里有什么.py`——**静态**：只用 httpx 打外网，数"正文与图地址在不在 HTML 字节里"。
  本机与现网各跑一次，**对现网零写**（不碰库、不给黑名单记账；跑完 `source_blocklist` 仍 1 行／`xhslink.cn` 仍 2 次）。
- `docs/工具/诊断-浏览器渲染比静态多什么.mjs`——**渲染**：本机 Chrome `--headless=new` 起一个无 cookie 的新 profile，
  在页面里只读 DOM（不点、不填），数渲染后的正文字数与"自然尺寸 ≥200 的图"有几张。
  ⚠ 现网那台机器跑不了这一把（现量：chrome／chromium／firefox／playwright／wkhtmltoimage **一个都没有**，
  `.venv` 里也没有渲染库）。

## 三、由这两把尺子定死的三条口径

### ① 渲染的第一价值是**取到图地址**，不是截图

微博那两行的读数摆着：渲染完之后屏上就挂着 `wx1/wx2/wx3.sinaimg.cn/orj360/xxxx.jpg`。
**拿到地址之后，走的是现成那一整条链**（下载 → Pillow 压 → 穿 `image_store` 进桶 → 登记 `assets`），
存下来的是**原图 32 KB**，而整页截一张是 3,692～14,917 px 高的一整条长图。
⇒ 所以"截图"只能是**这一张确实拿不到地址**时的兜底，不能当主路。
（这一条和站长原话"无法获取图片，自动截图"完全一致，我只是把它排在了"渲染取地址"后面。）

### ② 微博的图**必须带 Referer**，而现网那条规则写的是"永远不带"

现网实测（同一张 `wx3.sinaimg.cn/orj360/….jpg`，从服务器打，生产 UA）：

| 带不带 Referer | 结果 |
|---|---|
| 不带 | **403**，238 B `text/html` |
| 带 `https://m.weibo.cn/` | **200／32,298 B／image/jpeg**，`file` 解回 `JPEG 360x540` |
| 带 `https://weibo.com/` | **200／32,298 B**，同一张 |

而 `note_images.py` 模块头与 `tests/test_note_images.py:232 test_下载那条路不许带任何Referer` 钉的是
「**一个 Referer 都不许有**」——那是为**微信**那一族立的（带任何 Referer → `200 ＋ 2,090 B` 的 140×140 占位图，状态码抓不出来）。
⇒ **两族方向相反，第三条方向也相反（微博：不带就 403）**，所以这一条**不许做成全局开关**。
落法：新模块里**先按现网规矩不带 Referer；只有这一张回了 4xx 才带"页面自己的 origin"重取一次**，
重试上限 1 次、且 Referer 只许取自这一次渲染落点的 scheme+host（不许从图 URL 里倒推、不许写死域名表）。
现有那条判据**不动**（它扫的是 `note_images.IMAGE_HEADERS`／`_download`／`archive` 三处），
但**它的 docstring 里"唯一对的做法是不带"这半句要改成实话**：不带是默认，微博那一族不带就是 403。

### ③ 渲染过不了"要登录"那一档，也过不了"IP 风险"那一档

小红书那句 `IP存在风险，请切换可靠网络环境后重试 300012` 是在**本机浏览器、无 cookie**打回来的——
换真浏览器也一样；知乎那行是 `/signin`。⇒ 这一条 API 的**能力边界**要说人话：
**能过"页面自己用 JS 拼出来"和"访客态 JS 换 cookie"这两种闸；过不了"必须登录"和"我们这个出口被判定为风险 IP"两种闸。**
这一句要照抄进帮助文档与后台那栏的说明，不许写成"链接打不开就截图"这种承诺。

## 四、这条 API 长什么样（单独一条，与文字提取零交叉）

```
POST /api/url-shot            { url }                     → 202 { task_id }
GET  /api/tasks/{task_id}     （现成那一把任务口，不改）  → processing / completed / failed
```

- **新任务** `app/tasks/shot_tasks.py:process_shot_task(task_id, user_id, url, generation)`——
  与 `process_url_task` 同名不同人，不 import 它、不改它、不共用自己的那一段失败文案。
  链路：闸门验链 → 渲染（见第五节）→ **取图地址（有就逐张走 `note_images.archive()`）**
  → 一张都没有／全失败 → 截**可见视口分段**（不追整页长图，见第八节那条 4MB）→ 压 → 进桶 → 回计数。
- **复用**现成的三样，一行不重写：`scraper._validate_url`（SSRF 闸）、`note_images`（压＋进桶＋登记）、`tasks` 那套状态机。
- **开关** `URL_SHOT_ENABLED`（缺省关）＋`URL_SHOT_BROWSER`（Chrome/Chromium 可执行文件路径）。
  与 `POSTER_TEMPLATES`／`IMAGE_STORE_CF_*` 同一个纪律：**没配就整条不做、屏上一句不报**，
  起不来的是这一条功能，不是这台服务。
- **黑名单只读、不写**：命中就照现有那句拦下；但这一条链的失败**一律不给 `note_site_failure()` 记账**
  （截图这条链的"0 字"不是站点的错，是我们没渲染动——记了就是把我们的故障算到网站头上，
  那条教训在 `source_blocklist.py` 模块头第 1 条）。
- **张数与配额**：仍吃 `MAX_ASSETS_PER_NOTE`（9）与 `assets` 那一套账，**不在新模块里再打一个 9**。

## 六、风险清单（我认为必须先说的，不是走流程）

1. **SSRF 面比 httpx 大一个量级**。现在那道闸只判**我们自己发的**请求；浏览器会执行页面里的 JS，
   自己再发请求、跳内网、读 `file://`、打 `169.254.169.254`。`_validate_url` 拦不住它。
   ⇒ 必须**在浏览器外面拦**：起一个只放行公网 IP 的出口（proxy allowlist），或给浏览器加
   `--host-resolver-rules` 把私网段与元数据地址直接拒掉。**这条不做完不许上现网。**
2. **内容检的缺口被放大**。贴图那条链的 R10 已经写明"图侧不过任何内容检"（个人主体拿不到 `imgSecCheck`）。
   截图等于把**整页**搬进一个可分享的对象里，比单张正文图重。他 10-18 拍过"公众号来源允许分发"，
   **没有拍过"任意站点整页截图允许分发"**——这一格我不自己套上去。
3. **版权／页面皮**。截到的那张带着广告、Cookie 条、「下载App」那一堆（知乎那行的读数就是这一种）。
4. **配额与孤儿**。按现有纪律：进桶一张就登记一行，登记写在 try 外面（R7 那条），不许出现"桶里有对象、库里没行"。
5. **计时**。贴图那条链的 R6（9 张只有每张超时、没有整条总预算）在这条链上会更疼：渲染 30 秒＋9 张下载＋一张截图，
   全挤在同一个 job 里。
6. **他没拍过的一格，我不替他定**：这条 API 建**新笔记**（`source_type` 要新起一枚，还是复用 `screenshot` 那一档），
   还是**往已有笔记里加图**。今天库里 `screenshot` 那一档已经有 26 篇在用；新起一枚会把
   列表／详情／配额那几处"按 source_type 分支"的地方全部点一遍。**这一格必须他拍。**

## 九、他问的第二句：「小红书还有其他技术手段解决吗」（10-19 14:4x 查，四条里有两条是硬的）

先给结论：**没有既便宜又干净的手段。** 四条路里三条已经关死（一条是官方硬限制、一条要企业认证、一条是"对抗"我不做），
剩下的一条是**花别人的钱买别人抓来的数据**——那是合规决策，不是技术决策。

| 这一条路 | 今天量到／查到的 | 这一格定性 |
|---|---|---|
| **服务器直打笔记页** | 现网打 `discovery/item/6ad40f01000000002203c359`：**302／348 B** → `/404/sec_…&error_code=300031&error_msg=当前笔记暂时无法浏览`（**今天早些时候同一条是 302 进 `/login`**） | 两趟回的都**不是数据，是闸**，而且闸的形态会换 ⇒ 任何"按某一形状写解析"的实现都撑不住 |
| **它自己的 JSON 接口** | `edith.xiaohongshu.com/api/sns/web/v1/feed?source=note&note_id=…` 无签名：**404／18 B `404 page not found`** | ⚠ **这一格原来那句"这一族要端上生成的签名头"已被第十节作废**：404 只说明**那个端点形状不对**，本机零 cookie 零签名用现网那套头就把真笔记取回来了（短链 4/5）。"我不去打那个签名"那半句仍然成立——现在也不需要打了 |
| **官方开放平台** | `openaccount.xiaohongshu.com` 首页那句能力是「通过标准 **OAuth 2.0** 协议为你的应用提供小红书账号登录能力」；角色那一页（镜像）写着「**一个开放平台帐号，对应唯一一套企业认证资质**」，角色只有「软件服务商／商家自研」 | **个人主体这一档申请不到**，而且那份清单里**没有"读任意公开笔记正文/图片"这一项**。⚠ 诚实口径：`open.xiaohongshu.com/document/developer/file/32` 抓回来只有一段 JS，正文没取到 ⇒ 这一句是**两条读数的推断**，不是我核实的官方声明 |
| **在用户手机上打开页面**（小程序 `web-view`） | 官方组件文档原话：「**个人类型的小程序暂不支持使用。**」 | **硬的，不用测**——这一扇门对我们这一主体直接关着 |
| **第三方付费"详情／笔记解析"接口** | 阿里云开发者社区、CSDN 上那些"小红书详情 API"教程都是第三方服务 | 要钱；且**用户粘进来的那条链接要交给第三方**（它自己怎么拿的数据我们看不见）⇒ 这是合规与隐私决策，要他拍，我不自己走 |
| **换出口／塞用户 cookie** | 他 10-19 08:2x 已拍**乙**（不给服务器换出口）；cookie 那条要存他本人账号、封号风险在人身上 | **已定死，不再列成待拍** |

**唯一还值得花一次实验的**（**10-19 15:0x 已跑完，读数与结论在第十节**；5 分钟、**不改服务器出口**）：拿一台国内**住宅**出口的机器把同一条链接打一次，
只回答一个问题——**那道闸卡的到底是 IP，还是签名。**
这一枚数决定"值不值得为它花钱／换出口"。现在我知道的只有：本机这一趟拿到了笔记（69,039 B／41 字／5 张）、
另一趟同一把脚本落到 `/login`（36,211 B／0／0），**本机无 cookie 的浏览器还挨了一句「安全限制 IP存在风险…300012」**
⇒ 本机读数自己就不自洽，撑不起结论。

同一条压缩尺子、同一个桶、同样算进那 9 张（库里 10-19 14:0x 现读：`screenshot` 那一档 26 篇在用）。

## 十、住宅出口那一刀跑完了（10-19 15:0x，新尺子 `docs/工具/探-小红书闸卡IP还是签名.py`，两种入口 × 5 次 × 两台）

**先报出口身份**（不报这一枚，后面的分布数字归不了因）：

| 这台机器／这条路 | 中文站看到的出口 | 它是什么 |
|---|---|---|
| 本机 httpx 直连（进程里没有 `*_proxy`） | `〈本机家宽出口 IP·已抹〉`＝中国 广东 广州 **移动** | 家宽／移动网络 CGNAT 出口 |
| 本机 Chrome（默认吃 macOS 系统代理 `127.0.0.1:7897`） | `〈本机代理出口 IP·已抹〉`＝境外机房 | 上一趟那句「安全限制 IP存在风险 300012」是**这个出口**挨的 |
| 现网服务器（境内境外两枚回显同值 ⇒ 没走代理） | `〈现网服务器出口 IP·已抹〉`＝中国 广东 广州 电信（腾讯云 IDC 段） | **机房 IP** |

### 分布（三种地址各打 5 次）

| 这一种入口 | 本机（移动出口） | 现网（腾讯云出口） |
|---|---|---|
| 裸笔记页 `discovery/item/<id>` | **5/5 `sec` 拒绝页**（96,397 B，`error_code=300031 当前笔记暂时无法浏览`） | **5/5 同一枚 96,397 B `sec` 拒绝页** |
| 裸笔记页 `explore/<id>` | 5/5 同上 | 5/5 同上 |
| App 里"复制链接"那种**短链** `xhslink.cn/o/…` | **4/5 真笔记**（标题对、正文 41 字、图 **5** 张、作者有）＋ 1/5 落登录壳 36,211 B | **5/5 登录壳页** 36,211 B／0 字 0 图 |

**浏览器那一刀补量到了**：本机 Chrome 加 `--no-proxy-server`（＝强制走那个移动出口）再打同一条短链，
**笔记整页渲染成功**——标题「芭蕾现在衣服穿这么透，没人管管吗？第二集 - 小红书」、正文 84 字、
图已加载 `sns-webpic-qc.xhscdn.com/202610191434/…`；同一把脚本**不加这个开关**（＝走境外机房出口）回的是
`website-login/error`「安全限制 IP存在风险…300012」。**同一台机器、同一个浏览器，只换出口，两趟结果相反。**

### 三条由此定死（含我自己上一节的一处改口）

1. **不卡签名**——我第九节那句「这一族要端上生成的签名头」**推断过头，今天作废**：
   本机零 cookie、零签名、用现网那一套头，短链 **4/5 直接拿到真笔记**。
   那条 `edith.xiaohongshu.com/api/sns/web/v1/feed` 无签名回 404／18 B 只说明**那个端点形状不对**，
   不能用来证明"必须签名"。（这一格记下：我当时把"一个接口没打通"读成了"这一族需要签名对抗"。）
2. **卡的是出口 IP 的类型与名誉**：机房 IP（腾讯云）5/5 全败；移动 CGNAT 4/5 成；境外机房 IP 连浏览器都吃 300012。
3. **还卡入口形状，这一条与出口无关**：裸 `discovery/item/<id>` 与 `explore/<id>` **两台都是 100% `sec` 拒绝**。
   ⇒ 就算换了住宅出口，用户从浏览器地址栏复制那种"裸笔记地址"**照样一条都拿不到**；
   走得通的只有 App 里「复制链接」给的那种带一堆参数的短链。这一条要落进帮助文档那句实话里。

### 所以"换住宅出口值不值"这句实话

技术上**确实通**（4/5 有真读数），但它**撑不起一句承诺**：本机同一把脚本 5 趟里就有 1 趟落登录壳，
而且裸地址那一档换谁都过不了。代价是引一个国内代理出口＝钱＋**把用户粘进来的链接经过第三方机器**，
并且这一格的内容就是他 10-19 08:2x 拍**乙**（不给服务器换出口）那一格——**我不把它重列成新的待拍**，
只把新读数摆在这儿；他要重看乙就重看，他维持乙就维持乙。

### 一件今天会在现网发生的事（别到时候当 bug 查）

按现网 **5/5 失败**这一枚读数，下一个用户粘一条小红书短链，就把 `xhslink.cn` 从**现读 2 次刷到 3 次**
⇒ 自动进黑名单，此后所有粘小红书短链的用户读到的都是那句「这个网站读不到内容，已停用」，
而**不再是**「未能从 URL 提取到有效内容」。拦与不拦是他的决定（那一栏在 `/ops`，手工移出连账一起删）；
我只是把"它今天就会发生"写在这儿。
