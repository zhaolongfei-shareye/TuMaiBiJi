## 一、这一屏现在长什么样

代码：`miniprogram/pages/share/view.wxml` ＋ `view.wxss` ＋ `view.js`（页面路径 `/pages/share/view?token=…`，
小程序码、好友那条、朋友圈那条三个入口开的都是它）。

**整块照列表那扇详情窗那一份抄，这一屏不自有一套骨架**（站长 10-24 第二句「你干嘛要自己重新设计……
无论是自己看笔记，还是别人看笔记，打开的风格布局要一致性。不要另外设计」）。从外到内四层：

1. **壁纸那一层**（`.sv-bg`）＝`poster.homeBg()`：本机「背景」槽 → 后台下发的运营图 → 空。
   取不到就**不画这一层**（与首页 `.head-img` 同一个 `wx:if`，同一条规矩）。
2. **窗外面那档暗纱**（`.sv-veil`）＝`--glass-veil-dim`（`rgba(8,10,14,.45)`）＋ `--glass-bf`（`blur(23px) saturate(1.8)`）、
   `z-index:100`、铺满整屏。**这一层永远画，不带任何条件**——它跟着"这一屏有窗"走，不跟着"有没有壁纸"走。
   ⚠ 10-25 之前它和壁纸**共用同一枚 `wx:if="{{bgSrc}}"`**，于是读者那台机没铺图时纱跟着没，
   整屏退成一层平米白——就是他那句「不能接受，外面没有毛玻璃，我都说了要一比一复刻」。
   没壁纸时纱底下糊不出花纹，但暗档照压（这台机实测窗外那条均色 rgb(116,113,107)、亮度 113.3，
   与列表那扇在同一个人在同一台机上**逐字同值**）。
3. **顶上那条导航条**走全站唯一出口 `app.applyTheme()` → `applyNav()`（＝该档心情那支面板皮 ＋ 按皮的亮度挑 `#ffffff`／`#000000` 那两枚字色之一）。
   这一页原来漏了这一句 ⇒ 窗外是暗的、导航那一条停在 `app.json` 那枚写死的 `#f4f2ec`，一整条断层。
   **没有为这一页单开第二条出口**，其余每一页走的都是这一句。
4. **那张窗**（`.sv-sheet`）：`left/right 24rpx`、`top 130rpx`、`bottom calc(24rpx + env(safe-area-inset-bottom))`、

   底边那一枚**故意不照抄**列表那扇的 `192rpx`：那 192 里有 128 是给底栏让的位，这一屏没有底栏。
   窗里只有 `.sv-body`（`scroll-view`）滚，动作条 `.sv-dock` 钉在窗底。

窗内从上到下（**窗外一个字都不留**）：作者行（圆形墨底标记取昵称首字＋「原创作者：×××」）→
**大标题 → 标签一排（灰字、无底色、无加粗，每枚前面带 `#`）→ 通栏配图 → 「摘要」＋正文 → 「核心要点」＋小黄点逐条 →

## 二、配图那一块（这一轮唯一的新交互）

原来是九格 150rpx 小方格（`.sv-shots`／`.sv-shot`，`aspectFill` 裁着放），现在换成图二那种**通栏大图轮播**：

- 一格两层：底＝同一张放大到 112% 且左上各外挪 6% 后 `blur(30rpx)`（不外推会把模糊带出的半透明渐隐圈露在四边上），
  上＝`aspectFit` 完整放进 395rpx 那个盒子（不裁；被留白盖不住的部分由底那一层铺）。
- 点上面那张还是拉全屏大图（`wx.previewImage`，`urls` 给整排，与详情页同一个动作）。
- 张数与那一排点都吃**同一个数** `figAt`（`swiper` 的 `bindchange` 是唯一写口）；只有一张时数字与点都不画。
- 换 token 时 `figAt` 归零（这一页会被复用：好友那条与朋友圈那条开的都是本页）。
- ⚠ 这一排画不画得出来**不取决于这一页公不公开**，取决于云开发存储「读」那一档：
  默认「仅创建者可读写」时别人打开就是空白（10-12 站长报的那条 BUG，当天由他在控制台放开）。

这是这一屏与那张图之间剩下的唯一一处**字**不一样——不在他这三句里，所以没动，**要不要跟着改成固定一句等他一句话**。

**10-24 服务端那一头多了一道闸，屏上口径跟着变**（他原话「为什么自己可以转存自己的，这个不合理，要限制，

自己的那张码落地页照读不误，别人存进来照旧通。这条推翻的是 `test_share_snapshot.py` 里原来那条

**转存不带配图那一条已于 10-24 深夜翻案**（他一句「转存必须带图。乙，复制一份到自己名下」）。
先记清它为什么原来不带：`shares` 那份快照只有六栏（`SNAPSHOT_COLUMNS`＝标题/摘要/标签/关键链接/要点/来源），
**图从来不在里面**——落地页那排图是**现读原篇的 `assets`**（`LIVE_PUBLIC_FIELDS = {"assets"}`）。

现在长这样：转存成功之后，原篇那几张（≤9，按 `order_by_note()` 那序）在**云开发环境里逐张复制一份**，
新对象落在转存者自己那一层（`images/{userId}/{YYYYMMDD}/…`），账记进他这一篇的 `assets` 行 ⇒
屏上那一排图立刻读得到，**客户端一行不用改、不用出包**。三件刻意的形状：

- **各有一份对象，不共用 fileID**（这就是他挑的乙）：`delete_note` 删笔记时把 `cloud://` 交回客户端去删，
  两人挂同一个对象＝谁先删就把另一个人正在用的那张一起删。
- **不重压、不改格式、不重新送内容安全**：源那一张本来就压过也检过，复制不新增暴露。
- **一张没跟过来不许把整篇转存变成一次失败**：笔记照建、分照结，其余那几张照落。

代价三条（响应慢几秒／桶里对象翻倍／超 4MB 那一张只算没跟来）与全部证据在 §8.479。
**后端那一半已于 10-24 23:34 上现网**（第六十五次，五只文件、探针 68/68＋18/18＋49/49，读数在 §8.480）⇒

**云函数那一半已于 10-25 00:0x 上现网**（第六十六次，只走 `cli cloud functions deploy` 那一条通道，读数在 §8.481）
⇒ **「带图」这一腿现在成立**，而且是**从桶里逐字回读**证的、不是拿函数自己报的字节数糊过去：
现网真跑两趟（3 张各 91 字节／9 张各 500 KB）都**红 0、零残留**——副本名下逐张落账、地址与源**零重合**（＝真复制），
每张新对象下载回来的 md5 与源那张**一字不差**，9 张那一趟他点完那枚按钮要等的整段是 **7918ms**。
