# 交接：master 上那四条红判据（10-06 立，欠着的一天照抄）

**这笔债是什么**：跑 2.0 回归时抓到**四条从 10-04 起就一直红着的旧判据**。四条都是**判据过时、实现没错**——
代码在 10-04 那几轮里合法地动了，判据没跟着改，于是红一直躺在那儿，谁跑谁以为"这轮改坏了"。
修法只写进了 `release/2.0` 这一支（`b82e01c`），**master 上今天仍然红**。

**为什么不能靠 merge 带回去**：这一支还带着 2.0 的东西（`appInfo.VERSION = 2.0.0`、图片那条链、张数常量）。
把分支 merge 回 master 去修四条尺子，等于顺手把没做完的 2.0 一起塞进 1.9.x 的出包线上。
所以载体是一份补丁：`docs/补丁-master四条红判据-20261006.patch`（94 行，只碰那四个 `docs/工具/` 文件，一行产品代码都不动）。

## 四条各自红在哪

1. **`验-列表D2` 那条"点开大图取的是台账里那一张"**：判据拿包内 `poster.TEMPLATES` 去"认不认"那个模板 id。
   实现早就换成合并后的 `templateList()`（包内十套 ＋ 下发的）。台账里那一格完全可能指着一条远端模板，
   照旧判据会把真存在的模板判成不认识。改判据，不改实现。
2. **`验-列表D2` 那条"删除只动本机这本账"**：原来是一条 240 字符窗口的长正则。10-04 给 `onDropCard` 加了三行注释
   （说的是"按钮一律用系统默认那对"），把距离撑过了窗口——**红的是尺子，代码一个字没错**。
   改成位置比较：取函数体、剥掉注释、钉"`dropNote` 在 `_closeTemplate` 之前"＋"整段没调过 api"。
3. **`验-列表头部铺图` 那条"三块都在容器里"**：判据要求 `class="sheet"` 紧挨着 `">`，而那一格后来多了"加宽"那一档
   （`sheet {{listWide ? 'ix-wide' : ''}}`）。要钉的是**先后与归属**，不是那个 class 一字不变。
4. **`验-录入面板沉底-真跑` 那条"原文区仍是 300rpx 高"**：`.face-area` 在 10-04 下午已经从 300 降到 228
   （按钮行上面加了「原文翻译」那一行，56 + 16 = 72，正文让出那 72；`create.wxss` 的 `.wr-body` 注释里写的就是 228）。
   判据两天没跟着改。

另外还搭了一条小的：`验-关于页版本号` 默认端口写死 9420，用 `跑尺子.sh`（统一 9431）跑就是连接红——
连接红不是判据红，但它会让人误以为回归跑过了。

## 顺带一条纪律（这四条就是这么攒下来的）

改完界面那一轮，收尾动作必须包含"**把受影响的尺子当场再跑一遍**"。
这四条全是 10-04 那几轮攒的，隔了两天才被 2.0 回归第一次抓到。
还有一条：这四条红**不许用"重生成基线"糊过去**——`验-模板配方等价.js` 那种基线才是"改一下就要解释"的东西，
判据写错了就改判据，别把实现改去迁就旧尺子，也别把旧的错值重新钉一遍。
