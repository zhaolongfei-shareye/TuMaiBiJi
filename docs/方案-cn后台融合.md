## 1. 先说清楚"融合"卡在哪一件事上

两个后台**不在同一个后端服务里**，但**在同一个 origin 上**（实测：根路径 `/health` 404、`/wtsj/health` 200；`/admin.html` 200／23,872 B、`/wtsj/ops` 200）。这句话决定了什么能做、什么不能做：

- **能**：一个壳页面同时调两边的接口；cookie／localStorage 天然共享；一次登录两边通行——**不需要跨域 SSO**。
- **不能**（不做鉴权改造就做不到）：**"一个账号"**。两边现在验票的是两套不同的东西：
  - 图麦克＝用户名＋密码，表 `admin_users(username, password_hash, password_salt)`（`main.py:180`），登录 `main.py:1286` 用盐化散列＋`hmac.compare_digest`，之后**每个口自己调 `_trusted_admin(authorization)` 验票**（如 `/admin/dashboard` 在 `main.py:1338-1343`）；
  - 图麦笔记＝**没有账号**，只有 `.env` 里一把共享口令 `ADMIN_TOKEN`，签一枚带 `scope` 与 `atk` 指纹的短命票（`app/core/admin_access.py`，四条判据缺一个就白搭）。

⇒ **结论：只做前端合并解决不了他要的那一句"一个登录账号"；必须动鉴权。** 而鉴权怎么合，就是下面第 2 节唯一需要他拍的架构题。

## 2. 账号往哪一边归（已拍：**以我们登录为主**，不是下面原稿推荐的甲）

> **10-15 站长拍的这一条覆盖甲／乙／丙三选一**：登录入口留在图麦笔记这一侧（`ADMIN_TOKEN` → `/api/admin/login` → 我们签的那枚短命票），图麦克那边不再自己收口令，而是**拿我们这枚票来我们这里验真**，验过之后由它自己签一枚对端会话。
> 与甲的差别只有一处方向：**签名钥匙不外借、身份源在我们**。甲是"两边共用一把 `JWT_SECRET_KEY`＋它签跨线票"，那样任何一边泄露就是两边同时开门；这一版对方只拿到"这枚票真不真"的回答，拿不到签名权。
> 下面那张甲／乙／丙表是拍板前的盘点，留着是为了记下代价去哪了：甲的代价①（共密钥）被这条设计消掉；代价②（`scope`＋`atk` 两边都要实现）改成了**只在我们这实现一份**，对端不复制判据、只问我们（`_decode_admin_ticket()` 是 `get_admin` 与 `verify_ticket` 唯一的一份实现）；代价③（要动图麦克那条线）没消，就是第 8 节第 4 条还欠他点头的那件事。

| 选项 | 怎么做 | 代价 |
|---|---|---|
| **甲｜账号归图麦克（推荐）** | 图麦克的 `admin_users` 当唯一身份源；登录成功后除自己的票外，**再签一枚带 `scope=wtsj.*` 的票**给运营图这一侧；我们这侧 `admin_access.py` 改成"认这枚票（scope ＋ `atk` 指纹照判）"，`ADMIN_TOKEN` **降级为应急钥匙**（口令为空一律 503 那条纪律保留） | ① 两台服务共用一枚签名密钥，泄露面合并；② `scope` 与 `atk` 两条判据**必须在两边都实现**，只做一边就是"换了口令、对面旧票还能用到自然过期"；③ 图麦克那侧要加"签发跨线票"的写口，属另一条工作区的代码，**要他点头** |
| 乙｜账号新建一套（独立 console 服务） | 新起一个 `console` 后端，自己存账号、按 scope 代理两边接口 | 多一台服务、多一份运维与备份；**但这是长期最干净的**（能顺手解决"加第二个管理员"和权限分档）；工作量最大 |
| 丙｜我们这侧升成账号体系 | 图麦笔记也建 `admin_users`，两边各登各的，只在壳页做"一次点两下" | 他明确否过（要"一个登录账号"），且等于没融合 |

**为什么建议甲而不是乙**：他现在的诉求是"一个账号管两个小程序"，甲一次改造就到位；乙要多一台机器。**乙留作二期**：等"第二个管理员／按 scope 分权／举报处置队列"这三件真要落地时，把甲自然长成乙。

### 2.1 换票这条链的线协议（图麦克那一侧照这一段实现）

```
POST https://api.agentsbin.cn/wtsj/api/admin/verify-token
Header  X-Exchange: <ADMIN_EXCHANGE_SECRET>      # 两边 .env 填同一个值
Header  Content-Type: application/json
Body    { "token": "<我们 /api/admin/login 发的那枚 session 票原样>" }
200     { "sub": "admin", "scope": "admin", "exp": 1765800000 }
401     暗号不对 / 不带暗号 / 票不是管理票（scope 不符、过期、换过口令的旧票）
503     我们这侧 `ADMIN_EXCHANGE_SECRET` 留空 —— 语义是"这条链不可用"（**10-15 20:58 起已配，这一支不再触发**）
```

**地址三条实测（10-15 21:0x，从图麦克那个容器 `watermark-image-api` 里面打出来的，不是从宿主机 shell）**：

| 打哪个 | 结果 | 说明 |
| --- | --- | --- |
| `http://172.17.0.1:8000/api/admin/verify-token` | **401**（通） | docker 网桥上的宿主机地址；`uvicorn` 现读绑 `0.0.0.0:8000`，所以容器能到。**推荐走这条**，不出机器、不过 nginx |
| `https://api.agentsbin.cn/wtsj/api/admin/verify-token` | **401**（通） | 走公网绕一圈，也行；**必须带 `/wtsj/` 前缀**（不带前缀实测 404），域名只能 `api.agentsbin.cn` |
| `http://127.0.0.1:8000/api/admin/verify-token` | **Connection refused** | 容器里的 `127.0.0.1` 是容器自己。**别照"本机直连"四个字写成这条**——宿主机 shell 上它是对的，容器里是错的 |

对面那台的落点也记一下（10-15 只读实测）：`.env` 在 `/home/ubuntu/cloud/image-service/.env`，服务是 **docker 跑的**
（容器 `watermark-image-api`，`127.0.0.1:8080->8080`，compose 走 `env_file: .env`）
⇒ **加完这一行要重建容器才读得到**，光改文件不生效。
**10-15 22:44 已把同一个值填进去**（他一句「现在把值填到图麦克那边」）：填前先核过它那套配置是 `os.getenv` 读环境
（38 处，**没有 pydantic `BaseSettings`、没有 `extra="forbid"`**）⇒ 多一个它还不认识的键是惰性的，不会让它起不来；
键数 20 → 21、"少了哪些键"为空、两边值 sha256 前 12 位 `d7e5c24bbcec` 相同、改前备份 `.env.bak-exchange-20261015-2244`。
**没重启它的容器**：今天没有任何一行对面代码读这一键，重启属于它那条线的部署动作。

对端拿到 200 之后要做的事，以及**不许**做的事：

- **签自己的短命票**，`exp` 对齐回体里那个 `exp`（不要各签各的时长：不一致时"这边还登着、那边要重登"会变成常态，而他拍的是"登录一次"）。
- 只信这三个字段。回体里不会有 `sub` 之外的任何用户数据，也不会有签名相关信息——这一口是判真假的，不是信息源。
- **不许把 `X-Exchange` 存进浏览器或任何前端**。它只在本机→本机的服务间调用里出现；出现在浏览器那一头，就等于把"能不能验票"这件事交给了访客。
- 不许在对端**复制一份票的判据**（scope、`atk` 指纹）。复制了就会有"自己人打得开的票，换票口说它无效"那一天。
- 换票口的限流是 30/minute（同机一个进程点不了这么多次；被刷的时候它比"口令被试"更容易发生）。
- 登出：我们这侧的票一失效（自然过期或轮换 `ADMIN_TOKEN`），对端那一枚也必须在下一次校验时倒掉——`atk` 指纹就是为这条准备的。

## 3. 页面怎么合（信息架构）

一个壳，**左边切产品、右边分「数据」和「配置」两类**，切换产品不需要重新登录（只是换数据域）：

- 顶栏：品牌位 ＋ 产品切换（**图麦克** ／ **图麦笔记**）＋ 当前账号与登出。
- 左导航按同一套分组命名，两个产品用同样的两格结构：
  - **图麦克**｜数据：总览（总用户数／今日访问／本周新增／图片处理总数／今日处理／VIP 兑换数／未使用 VIP 码／今日事件）、用户、邀请码、支付记录；配置：产品、生成 VIP 邀请码、改密码。**另加四块"后端已有、界面上没入口"的数据**：额度漏斗 `stats/credit-funnel`、API 指标 `stats/api-metrics`、支付对账 `payments/reconcile` 与 `payments/reconciliations`。
  - **图麦笔记**｜数据：§8.248 的 A 档五枚（新增笔记剔除 `preset`、来源分布、转存量、模板热度榜、邀请对账）＋运营图当前状态；配置：**运营图这一整屏原样搬进来**（上传 →「发布这一张」→ 历史里点一张就是「回滚到那一张」→「停用」，含 `MP_ASSETS_FREEZE` 那句冻结提示）。
- **不许同表互查两个产品的用户数据**（第 6 节红线 2）。壳只统一"入口与登录"，不统一"数据池"。

## 4. 风格统一（两版皮的实测令牌，等他挑一版）

现在两套完全不同：

- **A 版｜浅色纸感**（我们 `/wtsj/ops` 现役，也是官网那一族）：`--paper:#F2EFE9`、`--ink:#14161A`、`--muted:#6b6f78`、`--line:#e3e0d8`、`--clay:#D2683F`；卡片 `#fff`＋`border-radius:12px`，强调态 `#fff4e6`／字 `#7a4b12`，主按钮＝墨底白字，成功字色 `#1d6b3f`。
- **B 版｜深色 slate**（`admin.html` 现役）：底 `#0d1117`、卡 `#1e293b`、控件 `#334155`；字 `#e0e0e0`／`#94a3b8`／`#f1f5f9`；蓝系强调 `#60a5fa`／`#3b82f6`／`#2563eb`；状态四色 `#6ee7b7`／`#fcd34d`／`#fdba74`／`#f87171`；字体 `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto`。

**我建议 A 版**：理由不是"我们的更漂亮"，而是① A 版与官网 `agentsbin.cn`、小程序里的色卡同源（`--paper/--ink/--clay` 三枚完全一致），融合后对外只有一种视觉；② B 版是**另一个产品的皮**，把它当基准等于让图麦笔记去贴合图麦克；③ 后台是长时间盯数字的界面，浅底低眩光对表格更友好。**但这属于品牌取向，归他挑**——方向图两版都画好了。

统一时要一并定的三条（两版都得有）：字体只留一排（`-apple-system…` 那套，别再一个页用一个 font-family）；卡片圆角固定 `12px`、控件 `8px`；状态色只允许四枚语义（成功／警示／危险／中性），别出现第五种蓝。

## 5. 交互要顺的六条具体做法（不写"体验流畅"这种空话）

1. **登录一次，切产品不重登**：票里带两个 scope，切产品只换数据域；登出把两把一起清（**别留一把**）。
2. **数字卡片一律"数＋口径"两行**：只写"转存 12"没用，要写"别人把这篇存进他自己的库"。
3. **配置类动作全部走同一条两段式**：改动 →「发布之前先看一眼」（沿用我们 ops 现网那句原话）→ 生效。读数据的口不许有副作用。
4. **危险动作（停用、下架、改密、作废 VIP 码）二次确认 + 留痕**：现在图麦克侧改密／生成码都只有一层按钮。
5. **两边的空态与加载态用同一枚组件**：加载中别一个页转圈、另一个页空白。
6. **每个数字标明数据从哪来、多久更新**（现网 `TASK_TTL=3600`、任务历史还没落库，所以任何"最近"类数字都要写清窗口，否则就是把 Redis 一小时当历史卖）。

## 6. 三条红线（融合不许越过的）

1. **钱那侧不许降格成共享口令**：`admin.html` 管订单、支付、额度，必须保留"账号＋可追责"的身份与审计。
2. **两个产品的用户数据不许同表互查**：图麦克的付费用户与图麦笔记的笔记/分享是**两套对外隐私承诺**（各自的小程序后台《隐私保护指引》文本不同）。
3. **后台不许出可指到具体人的跨线画像**（例如"某付费用户在小程序里存了哪几篇"）；A 档指标一律只出聚合数。
4. 另加一条纪律：对外文案与关于页那句"无埋点"不许因为后台加了统计就悄悄变味——后台看的是**业务库里的数**，不是新增的用户行为埋点（要埋点先改对外文本，见 §8.248 第 5 节）。
