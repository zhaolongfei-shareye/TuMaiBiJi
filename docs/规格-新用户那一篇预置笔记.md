# 规格 · 新用户那一篇预置笔记与首启那张卡片

一句话口径：第一次进来的用户，**笔记列表里就有一篇官方预置笔记，卡片列表里有由它出的一张卡片**；
这一篇是他名下普通的一行笔记，能改、能删、能设私密、能分享，**服务端与客户端都不为它开分支**。
依据：站长 10-13 原话（§8.232）「笔记列表和卡片列表默认提供一个，避免打开列表都是空白」＋「卡片就是根据笔记内容生成的」。
10-14 落码，随 2.1.15 出包。

## 1. 现在长什么样

| 屏 | 新用户第一次打开看到 |
| --- | --- |
| 笔记列表 | 第一条就是那一篇，标题《你收藏过的 200 条，为什么一条都找不到？》 |
| 页头那一列「笔记」 | **1**（照实算，不限量口径不变） |
| 详情窗来源那一栏 | 「官方预置」（英文界面 `Preset sample`） |
| 卡片列表 | 首启那一次自动出图完成后有**且只有一张**；没出成就是那句「还没有生成过卡片」——这句空态文案**留着**，不许写成"一定有一张" |
| 那一格的方块颜色 | 吃它的第一个标签「产品说明」，色走 `utils/palette.js` 已有那一档，不新造色 |

## 2. 六条实现口径（都不是即兴）

1. **每个用户一份副本**，不是全局共享一条——笔记可删可改可设私密，共享一条会让"某个人删掉它"影响所有人。
2. **只挂在"这一次登录真的生出了一个新账号"那一个分支**上（`backend/app/core/auth.py` 的建号那一支调 `preset_note.seed_note_for_new_user()`）。
   判据不靠"他名下没笔记"那种现算状态：那种写法挂在每次 `_doLogin` 上，用户删完下次冷启它又回来了。
   **结构成立，不是靠哪一处记得清标记。**
3. **排在邀请归因之后**。`quota.attribute_inviter` 那句"名下已经有笔记就不认"会被自己种下的这一篇撞掉，那笔 +10 MIND 就凭空没了。
   归因与"动笔首篇"两处现在都改读 `authored_count()`（＝`source_type != 'preset'` 的那几篇），先后顺序是第二道保险。
4. **四字段写死在种子里，不走模型**（`backend/seed/preset_note.json`）。现网提炼 10-13 刚出过一次静默降级、空闲首调必吃 429，预置内容没理由依赖一次不确定的推理；也顺带绕开 msgSecCheck。
5. **卡片不预生成 PNG**，走端上首启自动出一次，排在这屏那次 `setData` **之后、不 await**，失败静默（与运营图 `mpAssets.pull()` 同一条纪律）。
   走的正是用户自己出图那三个口（`_ensurePosterAssets` → `_renderPoster` → `_keepPoster`），一篇一张、生成即上传都在里面。
6. **发令是一次性的**：登录回来的那一格只把 `seeded_note_id` 存在内存（`getApp().globalData`），`consumeSeededNote()` 取走即清。
   写进本机存储就变成"重装之后又认自己是新人"，那篇就会再去出第二张卡片。

## 3. 文案只有一个出处

种子里的摘要＝`miniprogram/utils/appInfo.js` 的 `INTRO_LEADS.zh`；要点与正文＝`pages/about/about.js` 的 `FEATURES_ZH` 那几张卡。
**不许在种子常量里另写一套产品介绍**（同一件事出现第二份真相，迟早两边不一致）。
改完那两份源件必须重跑 `node docs/工具/出-预置笔记种子.js`，否则 `验-默认预置笔记.js` 红。

标题是他交给我优化的（"要吸引眼球"），备选两句换掉只改种子常量：《一条链接丢进来，15 秒后它是一条能搜到的笔记》《收藏夹不是知识库，搜不到的都等于没存》。

## 4. 不做项

① 不做英文种子（英文界面只补齐一半，加了就是给用户看半套）；② 不借这条引"引导页／新手教程／弹窗"那类东西；
③ 不改那两句空态文案（他把这一篇删完就该回到空态，那是对的）；④ 不做多篇预置（他说"一个"）。
