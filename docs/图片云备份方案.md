# 图麦笔记 · 图片云备份方案

> 2026-10-03 · 初稿

---

## 一、现状

| 项目 | 现状 |
|------|------|
| 图片存储 | **不持久化**。截图进内存暂存 → OCR → LLM → 文字笔记 → 原图丢弃 |
| Asset 表 | 已建（`models/asset.py`），有 `object_key`/`file_type`/`file_size`/`width`/`height` 字段，**从未写入** |
| 对象存储 | 无 COS/S3 集成，配置里完全没有 |
| 前端压缩 | 无。`wx.chooseMedia` 选完直接以 `tempFilePath` 上传原图 |
| 笔记来源 | `manual`（手写）、`screenshot`（截图OCR）、`url`（链接抓取）、`share_import`（转存） |

## 二、目标

用户拍照/截图创建笔记时，**压缩后的图片同步存到云端**，实现：
- 换手机/清缓存后能从云端恢复原图
- 笔记详情页可查看原始图片（不只是文字）
- 5 GB 免费额度内运行，单图 ≤ 500 KB JPG

## 三、存储选型

### 方案 A：微信云开发云存储（推荐起步）

| 项 | 值 |
|---|---|
| 免费额度 | 5 GB 存储 + 10 GB/月流量 |
| 主体要求 | 个人主体可用 |
| 接入成本 | 小程序端 `wx.cloud.uploadFile` 直接调，**无需后端中转** |
| 限制 | 单文件 20 MB，需开通云开发环境 |

**优势：** 前端直传、零后端改动、免费额度够用（500 KB × 10,000 张 = 5 GB）

### 方案 B：腾讯云 COS（与现有后端同体系）

| 项 | 值 |
|---|---|
| 费用 | 标准存储 0.118 元/GB/月 + 流量费 |
| 接入成本 | 后端加签名接口 → 前端拿预签名 URL → 直传 COS |
| 优势 | 与现有后端同账号、可控性强、无 5 GB 上限 |

**建议：** 先用 A 跑通 MVP，量大了再切 B。

## 四、改动清单

### 4.1 小程序前端（3 天）

#### 4.1.1 图片压缩（新增 `utils/imageCompress.js`）

```
选图后 → canvas 重绘 → wx.canvasToTempFilePath 输出 JPG
- 长边上限 1920px（保持清晰度）
- quality 0.7-0.8（目标 ≤ 500 KB）
- 超 500 KB 自动降 quality 重试（最多 3 次）
- 输出格式强制 JPEG（丢弃 alpha 通道）
```

**不选 `wx.compressImage` 的原因：** 它只能压缩不能改尺寸，大图压缩后仍可能超标。

#### 4.1.2 上传流程改造（改 `utils/api.js` + `pages/create/create.js`）

```
现有流程：选图 → 原图上传 → OCR/LLM → 文字笔记
新流程：  选图 → 压缩 → 上传压缩图 → OCR/LLM → 文字笔记 + 存图片URL
```

- `submitScreenshots` 里选图后先过压缩函数，再上传
- 上传成功后服务端返回 `asset_id` / `image_url`，前端暂存
- 笔记创建成功后，图片 URL 写入笔记的 `assets` 关联

#### 4.1.3 笔记详情页展示图片（改 `pages/detail/detail.*`）

- 有图片时，在文字内容上方/下方展示图片（可点击放大）
- 图片加载失败时显示占位（灰色方块 + "图片加载失败"）
- 长按图片可保存到手机相册

#### 4.1.4 备份状态标记

- 笔记列表/详情页显示备份状态图标（☁️ 已备份 / ⏳ 待上传 /  失败）
- 失败的图片加入离线队列，网络恢复后自动重试
- 离线队列用 `wx.setStorage` 持久化，App 启动时检查

### 4.2 后端（1-2 天）

#### 4.2.1 开通云开发环境

- 微信后台 → 云开发 → 开通（免费）
- 获取 `envId`，写入小程序 `app.js` 的 `wx.cloud.init()`

#### 4.2.2 Asset 表启用（改 `models/asset.py` + `alembic` 迁移）

```python
# 已有字段够用，只需确保 ingest 流程写入
# 新增字段（可选）：
cloud_url       String(1000)   # 云存储 URL
backup_status   String(20)     # 'pending' | 'uploaded' | 'failed'
uploaded_at     DateTime
```

#### 4.2.3 截图处理流程改造（改 `app/tasks/ingest_tasks.py`）

```
现有：stage(内存) → process(OCR+LLM) → 丢弃
新增：stage(内存) → process(OCR+LLM) → 写 Asset 表(记录云URL) → 关联 Note.cover_asset_id
```

- OCR/LLM 仍用原图（压缩图可能影响识别率）
- 压缩图单独上传到云存储，URL 写 Asset 表
- `Note.cover_asset_id` 指向第一张图的 Asset

#### 4.2.4 新增接口

| 接口 | 用途 |
|------|------|
| `GET /api/notes/{id}/assets` | 获取笔记关联的图片列表 |
| `POST /api/notes/{id}/assets/retry` | 重试失败的图片上传 |
| `GET /api/user/storage-quota` | 查询已用/剩余存储空间 |

### 4.3 数据库迁移

- 启用 Asset 表写入
- Note 表加 `cover_asset_id` 外键关联（已有字段，确认索引）
- 加 `storage_used` 字段到 user 表（可选，用于配额展示）

## 五、数据流

```
用户选图/拍照
    ↓
前端压缩（canvas → JPEG ≤ 500KB）
    ↓
    ├──→ 原图 → 上传服务端 → OCR → LLM → 文字笔记（现有流程不变）
    │
    └──→ 压缩图 → wx.cloud.uploadFile → 云存储 → 返回 fileID
                                              ↓
                                         写 Asset 表
                                              ↓
                                         关联 Note.cover_asset_id
                                              ↓
                                         详情页展示图片
```

## 六、风险与对策

| 风险 | 对策 |
|------|------|
| 压缩后 OCR 识别率下降 | OCR 仍用原图，压缩图只用于存储展示 |
| 云开发 5 GB 很快用完 | 加配额查询接口，接近上限时提示用户；后续切 COS |
| 上传失败（弱网） | 离线队列 + 自动重试 + 手动重试按钮 |
| 云开发免费期到期 | 6 个月到期前评估用量，提前切 COS 或升级套餐 |
| 图片版权/隐私 | 云存储默认私有读，只有笔记主人能访问 |

## 七、排期

| 阶段 | 内容 | 工时 |
|------|------|------|
| P0 · 基础设施 | 开通云开发 + Asset 表启用 + 压缩工具函数 | 1 天 |
| P1 · 核心链路 | 截图流程接入压缩+上传 + 详情页展示图片 | 2 天 |
| P2 · 体验补全 | 离线队列 + 备份状态标记 + 失败重试 | 1 天 |

**合计：4-5 天**（比最初估的少，因为云开发直传省掉了后端上传接口）

## 八、不在本次范围内

- 图片编辑/标注
