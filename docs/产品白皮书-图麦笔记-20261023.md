# 1 产品介绍

## 1.1 产品简介

图麦笔记是一个**把你已经看到的好内容，变成能用下去的笔记**的工具。

你大概有过这种时刻：读到一篇文章、看到一张图、听人讲了一个方法，当时觉得有用，随手存了。然后就想不起存在哪儿了。存下来这一步不难，难的是**存下来之后还能用上**。

图麦笔记做的就是中间这一段：

> **随手记下来 → 自动整理成清楚的笔记 → 需要时找得回来 → 排成一张能分享的图 → 别人扫一下，能把它存回他自己的笔记里**

四条它坚持的原则：

1. **不要求你先写。** 三条录入路——拍照截图、贴链接、贴文字——都是把你手上已经有的东西接进来。
2. **原文永远留着。** 自动整理出来的是标题、摘要、要点、标签，你的原文一个字不动，随时能回去核对。
3. **公开是你主动选的。** 笔记默认只属于你。要给别人看，必须你明确操作一次。
4. **整理只是辅助，不是替你判断。** 自动摘要可能不准，所以原文和出处一直在。

## 1.2 基本概念

| 术语 | 指什么 |
|---|---|
| **录入三档** | 图片（拍照截图）／链接／文字（直接写或粘贴） |
| **提炼** | 把输入整理成 标题＋摘要＋要点＋标签 四栏的那一趟模型调用 |
| **原文翻译** | 控制提炼输出语言的一枚开关，**只在文字档**（§3.2） |
| **详情窗** | 列表里点开一篇的那扇窗，左右滑换前后篇 |
| **卡片／出卡** | 把一篇排成一张可分享图片；`note_cards` 表存留档 |
| **模板／配方** | 卡片的画法。配方是**数据**（`recipe` JSON 列），不是新写一套代码 |
| **快照** | 分享时存下的那一刻内容；`shares` 表 |
| **转存** | 读者把别人的公开快照存成自己库里的独立副本（`source_type=share_import`） |
| **私密** | 由名为"私密"的分类＋六位密码组织的访问控制，闸在服务端 |
| **心情／壁纸／亮度** | 三层外观：五档色彩语气／四套色阶／三档压暗。**都不改内容** |
| **名片四格** | 卡片上作者信息区的四个可编辑位（形象图＋名称＋一句话） |
| **MIND** | 邀请与转存的台账与配额体系（`invitations` 表、`services/quota.py`） |
| **哑管道** | 云函数的设计纪律：只做转换、不认身份、不碰数据库、规则留在调用方 |
| **代次（generation）** | 防"注销后 id 被复用导致串号"的高水位线 |

# 2 产品架构

## 2.1 产品全景图

```
客户端   微信原生小程序
           无 npm 依赖 · 无构建步 · 无 plugins · app.json 无 cloudfunctionRoot
           │
           │ wx.request → 唯一域名出处 https://api.agentsbin.cn/wtsj
           │ wx.cloud   → 只用云开发的「存储」，不调云函数
           ↓
服务端   FastAPI 0.115 + SQLAlchemy 2.0.36 + Alembic 1.14 + Pydantic 2.9
           异步：Redis 8.1 + RQ 2.12（队列名 default）
           限流：slowapi   身份：PyJWT（+ cryptography，为 SIWA 的 RS256）
           ↓
云函数   两只 Node 哑管道，由【后端】经 CloudBase HTTP 网关 + Bearer 长期 API Key 触发
           extract      文本进 → 四栏 JSON 出（内部 cloud.ai() → 混元）
           image_store  {cloud_path, base64} → {fileID, bytes}，上限 4MB
           ↓
模型     混元 hy3-preview（HUNYUAN_MODEL_ID 可覆盖）
```

**一条必须先知道的事实**：**小程序端没有任何 `wx.cloud.callFunction`**。两只云函数都由自建后端调用；小程序只碰云开发存储（`miniprogram/utils/cloudUpload.js:17` 环境 id、`:64` uploadFile）。看代码时别去找"前端调云函数"的地方，没有。

**架构层的三条设计纪律**（后面每一节都在遵守它们，先在这里定下来）：

1. **长任务一律异步**。录入／整理／外链贴图落账都走队列，绝不在请求线程里同步调上游——这是图麦那条线踩过的真教训（检图同步跑在事件循环里把整站按住十秒）。
2. **云函数当哑管道**。规则、鉴权、重试、记账全在自建后端；云函数只做一次格式转换。好处是换模型、换供应商时不动客户端。
3. **唯一来源**。色板、文案、域名、版本号各只有一处定义（§2.2）。第二处出现就是漂移的开始。

### 云函数与模型

- **模型**：`const MODEL_ID = process.env.HUNYUAN_MODEL_ID || 'hy3-preview'`（`cloudfunctions/extract/index.js:15`）；调用方式 `cloud.ai().createModel('cloudbase').generateText({ temperature: 0.3 })`（`:58-67`）。改回 `hy3` 会撞 429 `AI_MODEL_NOT_ENABLED`（`:11-14` 记着）。
- **为什么自建 OCR 而不用微信 OCR**：个人主体拿不到微信 OCR（错误码 100003），混元 token 也做不了 OCR ⇒ 落成 `rapidocr` ＋ `onnxruntime` ＋ `opencv-python`，**纯 CPU 推理、模型随包分发、不需要任何密钥**（依赖清单见本节末）。
- **image_store**：`{cloud_path, base64}` 进、`{fileID, bytes}` 出，上限 4MB（`cloudfunctions/image_store/index.js:9-12` 记着"手里没有删除权限"）。
- 触发通道：CloudBase HTTP 网关 ＋ 服务端长期 API Key（生产通道＝「环境管理→API Key 配置」，**CLI 秘钥是错型**）。

# 3 产品核心功能介绍

> 九个功能域，每节四块：**要解决的问题**（为什么有这一层）→ **屏上所见**（入口、操作、看到什么）→ **规则与边界**（哪些会被挡、哪些承诺不成立）→ **技术链路与现状**（实现在哪、依赖谁、处于哪一级读数）。

## 3.1 录入

**要解决的问题**：好内容散在相册、聊天记录和网页里，先要能把它们不费力地接进来。

**屏上所见**：打开小程序，底部三个标签：**新建 / 笔记 / 我的**。记录从"新建"开始，一块面板里切换三种起点，切换入口不会把你跳走。

| 档 | 怎么进 | 一次能进多少 |
|---|---|---|
| **拍照或截图** | 从相册选图或直接拍 | **一批最多 9 张**；系统先读图上的文字，再走同一套整理流程 |
| **贴链接** | 公众号文章或公开网页的地址 | 一条地址；省掉复制长文那一步 |
| **直接写或贴文字** | 自己打字，或把已有原文粘进来 | **单次整理最多 12,000 字** |

三档共用同一个提交动作：**面板底部是向右滑动才开始整理，不是点按钮**。这么设计的理由很实在——整理会花点时间，点按太容易误触。所以**内容是空的拖不动；条件没满足就松手，滑块自己弹回去。**

**规则与边界**：
- 读字效果受图片清晰度和排版影响，糊的、字太小的一张可能读不全；**这不是商品识别，也不会替你估价**——它认的是**文字**。
- 需要登录、有付费墙、或站点本身限制抓取的链接会失败。失败了笔记不会凭空生成，会告诉你没成。
- HEIC 不支持（第 7 章）。
- 拍照那一档**一批只出一次快门**：取景排只在零张时渲染。

**技术链路与现状**：
- 端点：`POST /api/ingest/url` `ingest.py:29`／`/text` `:70`（入队前送检 `:102`）／`/screenshots/stage` `:192`／`/check` `:251`／`/process` `:298`。
- 三个长任务 `process_url_task`／`process_screenshots_task`／`process_manual_text_task`（`backend/app/tasks/ingest_tasks.py:392,469,561`），入队点 `ingest.py:44-54,319-328,109-122`，均 `job_timeout=600`、`job_id=task_id`（uuid4 hex）。
- 截图原图先暂存在**进程内字典** `_batch_staging`：TTL 1800 秒、每批≤10 张、单张≤10MB、单批≤40MB、每用户≤2 批、全局≤120MB（`ingest.py:26,126-189`）。
- 数量与体积常量：`MAX_ASSETS_PER_NOTE=9`、`MAX_FILE_BYTES=20MB`（`models/asset.py:7,14`）。
- 图片闸（OCR 之前那道）`ingest_tasks.py:156`；OCR 见 §2.2。

## 3.2 整理

**要解决的问题**：存下来只是把东西搬了个家，"整理成能看懂"才是能用的前提。

**屏上所见**：不管从哪条路进来，出来的都是同样四栏。

```
标题     一句话结论
摘要     这段内容在讲什么
要点     编号的几条，可长可短
标签     帮你之后归类和搜索
```

你的**原文单独留着**，和整理结果并存。想核对机器有没有理解偏，回原文看就行。

「**原文翻译**」这一枚开关：只有"直接写"这一路有它，而且要把面板展开才看得见，**默认关着**。开着时，不管贴的是英文、日文还是阿拉伯文，整理出来的四栏**写成中文**；关着时，整理结果**跟着原文的语言走**。

**规则与边界**：
- **整理没成功，笔记照样存下来**，只是少那四栏——不会因为你贴的东西机器读不了，就把你的记录吞掉。
- **它不翻译原文**。原文一个字都不动、不译，它只管"整理结果用什么语言写"。
- **它不在链接和截图那两路上**。那两路的输出语言由模型自己判断，不受这枚开关影响。
- **它是一次性的**。存好一篇之后开关自动归零，不会默认带到下一篇。
- **界面语言只有中文和英文两种**，跟着微信语言走。"多种语言整理成中文"说的是上面这个能力，**不是界面有几十种语言**。
- 摘要可能不准；这产品不做"替你判断"。

**技术链路与现状**：
- 开关落点：`create.js:124 writeTranslate:false`；`create.wxml:295` 那条 `wx:if="{{active === 'write' && panelOpen}}"` 就是"只在文字档＋展开态可见"的实现。
- 链路分叉：`ingest_tasks.py:77,121`（链接与截图**不发** `translate`）vs `:173`（文字档发）；`services/llm.py:92-96` 三路分支。
- 提炼调用：`cloudfunctions/extract/index.js:58-67`（`cloud.ai()`，`temperature 0.3`）；重试策略 `services/llm.py:12-13,159-216`（§4.3）。
- 长度对齐：`routes/notes.py:45-49` 的 `MAX_SUMMARY/MAX_BODY` 与送检切片长度钉死（§4.1）。
- **"多语言整理成中文"的最新读数＝本轮没有**。现有支撑是一次历史实测（10-14 报 16/16），本文不把它当现行读数引用。

## 3.3 组织与检索

**要解决的问题**：记了三十篇之后，找不回来等于没记。

**屏上所见**：**笔记列表**（底部"笔记"）是你待得最久的一屏。

- **搜索**：按关键词搜标题、摘要和正文相关内容。你不必记得它当初是从哪个入口进来的。
- **分类**：把旅行、学习、工作的资料各归一堆。分类名和颜色可以自己改，可以排序。
- **列表／卡片两种看法**：同一批笔记，既能按文字快速扫，也能回看已经做好的卡片。
- **详情窗**：从列表点开一篇。左右滑换前后篇，遇到私密笔记会自动跳过。大图完整显示，不裁。
- **置顶**：常看的钉在上面。
- **编辑**：标题、正文、标签都能改。**配图长按拖动可以排序，第一张就是这篇的头图。**

新账号第一次打开不会是一片空白：有预置的示例笔记，也会引导你先做出一张卡片——**先看到成品，再开始记。**

**规则与边界**：
- **分类格里还有笔记时，那一格删不掉**——防止一删把里面的东西带走。
- 你**不必记得内容从哪个入口进来的**，列表不按入口分组。
- 列表**按关键词搜**，不提供"按录入日期以外的智能排序"。

**技术链路与现状**：
- 端点：列表 `notes.py:264`（`skip/limit` 上界卡死 `:267-271`）／详情 `:351`（**私密未解锁时服务端裁字段**）／新建 `:373`／编辑 `:404`／置顶 `:486`／删除 `:523`／配图排序 `assets.py:320`。
- 分类：`categories.py:85,109,137,218,236`；分类名也送检 `:29`。
- 删除是连带的：清 `shares`·`jobs`·`assets`·`note_cards`，并把 `file_ids` 回给客户端去删云上对象（`notes.py:544-576`）。
- 列表页规模 2022 行 js（§2.2）——这一屏是全产品最重的一屏。

## 3.4 卡片生成（十一套模板）

**要解决的问题**：有观点、有资料，但要发出去还得花时间把文字排成一张好看的图。

**屏上所见**：选一篇笔记，进"分享"那一屏，挑一套模板，预览、出图、存相册。**换模板不用跳页**：圆点横拖就能换，点模板名换整套，名字两侧有 `< >` 两枚箭头逐套走。

## 3.5 分享、公开与转存

**要解决的问题**：一张图发出去就断了；产品想要的是"看到的人也能把它变成自己的笔记"。

**屏上所见**：

**你点分享、创建公开之后**——系统为这一篇存一份**内容快照**，公开的是那一刻的标题、摘要、要点、标签和配图，**不是你的整个笔记库**；生成一个公开入口，别人不用登录也能读；同一篇笔记**只保留一张有效的码**，不会越分享越多份。

**别人扫你的码**——打开是一个**公开落地页**，先读到内容，不用先注册、不用先装什么；页面上有一枚**「存入笔记」**，按下去这一篇作为**独立副本**存进他自己的笔记库，之后他怎么改、删、再分享都跟你无关；你的**其他笔记他看不见**；页面上有**举报入口**。

**这条链是双向的**：你转存别人的，和你被别人转存，是同一个机制。你的笔记被别人转存了几次，会在你列表那一格留一个标记。

**规则与边界**（这一段是整个产品里唯一"对外"的一层，边界必须说清楚）：
- **你之后改了笔记：已经发出去的图片和已经被别人转走的副本不会跟着变。** 快照就是快照。
- **你撤回公开：公开入口关掉，别人再打不开。但这收不回已经转存走的副本**——那已经是别人的笔记了。
- **隐藏图上的小程序码 ≠ 撤回公开**。前者只是让这张图不带入口，后者才真正关掉访问。
- **个人记录 ≠ 默认公开**。公开永远需要你做一个明确动作。
- **分享出去的链接不设过期**，一直有效，直到你主动关掉。
- **私密笔记不能分享**（§3.6）。

**技术链路与现状**：
- 建码 `shares.py:93`——里面依次是私密闸 `:103`、帮助文档闸 `:108`、公开字段送检 `:129`；状态 `:188`；撤回 `:208`；匿名读 `:235`（含公开配图 `:239`）；小程序码 `:275`（限流 60/分钟，实测回 JPEG `:303-305`）。
- 一篇一张有效码由**数据库**兜：`share.py:9-19`。
- 转存落库：`POST /api/notes/from-share` `notes.py:583`，`source_type=share_import`（`note.py:8`）。
- 落地页三端点在 `/api` 之外：渲染 `landing.py:260`／举报表单 `:271`／举报落库 `:336`（限流 6/小时 `:337`）；域名 `SITE_ORIGIN = https://agentsbin.cn` `:48`。
- 举报保留期 180 天（`services/report_retention.py:83`），**不自动清理**，靠手工脚本 `probes/清-过期举报.py`（默认只算不删，须显式 `--执行`，`:19-22`）。
- MIND 台账两条部分唯一索引（`invitation.py:26-41`）；结算撞索引即视为已结过、不重试（`services/quota.py:143-171`）。

## 3.6 私密笔记

**要解决的问题**：有些东西记下来是给自己看的，"藏起来"必须是真藏起来。

**屏上所见**：私密是靠一个叫"私密"的分类来组织的，配六位数字密码。那一格里还有笔记时，分类删不掉。密码忘了解决路径在设置里；改密码、验证、重置都在服务端完成。

**规则与边界**：
- 私密不是"把文字涂白"，是**在读取内容之前就拦下**——**没解锁的时候，内容根本不会传到手机上**，不是前端遮住。
- 私密笔记**不能分享**，也**不能登记成卡片**。
- 把一篇改成私密时，**它原来的公开入口会自动关掉**。
- 详情窗左右滑换前后篇时，**遇到私密笔记自动跳过**。

**技术链路与现状**：

## 3.8 账号、身份与数据删除

**要解决的问题**：个人笔记工具，账号只该是一个人，删要删得干净。

**屏上所见**：用微信号进，不需要另外注册账号密码。跨端场景支持 Apple 登录，微信身份和 Apple 身份可以用一次性六位短码合并成同一个人。

**规则与边界**：

# 4 关键特性

> 这一部分回答的是"质量属性怎么保证"，不是"有哪些功能"。学的是华为云 GeminiDB 技术白皮书的写法（第 2 章关键特性＝如何保障高可用／高可靠／在线扩容／备份容灾）。

## 4.1 内容安全怎么生效

**两道闸都接了**，文字和图片各一道，且**送检排在提炼之前**——目的是"不为注定被拒的笔记花掉混元那一趟"（`ingest_tasks.py:111-113,170,425`）。

| | 文字 `msg_sec_check` | 图片 `img_sec_check` |
|---|---|---|
| 接口 | `wxa/msg_sec_check`，**v2 载荷** `{content, version:2, scene:1, openid}`（`services/wechat.py:21,176`） | `wxa/img_sec_check`（`:27`）。**`media_check_async` 未接**——异步要消息推送回调（`:22-26`） |
| 长度 | `SEC_CHUNK=2000` × `SEC_MAX_CHUNKS=8` ⇒ 单字段最多检 **16,000 字**（`:38-44`）；`notes.py:45-49` 的 `MAX_SUMMARY/MAX_BODY` 与之对齐钉死 | >1MB 先 PIL 压回 1MB 再送，否则**越大越绕过**（`:260-290`；`IMG_SEC_MAX_BYTES=1MB :28`） |
| 判定 | `risky`/`review` 抛 `UserError`；**`unavailable` 放行并记日志**（`:228-258`） | 只有 errcode，唯一"不过"码 **87014**（`:293-339`） |
| 缓存 | 只记 pass `(openid, sha256(text))`，上限 4000（`:60-61,144-156`） | 无 |
| 总开关 | `SEC_CHECK_ENABLED`（生产必须 true；测试 conftest 显式关掉以完全不出网，`config.py:40-43`） | 同 |
| 调用点 | **9 处**：`routes/notes.py:88,471`、`categories.py:29`、`shares.py:129`、`profiles.py:60`、`ingest.py:102`、`ingest_tasks.py:136,192`、`note_images.py:352` | **3 处**：`ingest.py:291`（提示层，`asyncio.to_thread` 裹同步 httpx）、`ingest_tasks.py:156`（**OCR 之前的真闸**）、`note_images.py:319`（进桶前查画面） |
| 额度 | **未上架 100 次/天，上架后 200 万次/天**；45009/44991 打光后当天等同没检（`:56-59,206-214`、`deploy.sh:681-688`） | 同 |

**混元链路内部没有内容安全环节**——闸在我们这一侧，不在模型侧。

**部署自检真打两趟**：正常文本必须 pass、已知违规必须被判下（`deploy.sh:648-701`，探针 `probe_sec_check` `wechat.py:160-170`；图片侧 `probe_img_sec_check` `:355-359`）。

**平台驳回过一次（要读原文，别当已解决）**：2.4.12 因《微信小程序平台运营规范·常见拒绝情形 3.2》被驳回，点名**【图片】功能**内容安全存在风险，要求 ①内容安全 API 在**小程序内任意发布场景**生效 ②检测结果**仅需提示用户**。整改分三批上现网（第五十九／六十／六十一次），**但当时"审核员可见度"为零**——因为屏上那半条在客户端、那颗包还没打。**"任意发布场景生效"这一条真正的承重是 worker 里那一趟闸，不是提前提示那只口。**

**⚠ 旧结论已被实测推翻**：「个人主体拿不到 `imgSecCheck`」不成立——接口调得通，**但图上文字判不出来**，要靠自家 OCR 读字后送文字检（§2.2）。

## 4.2 存储与访问控制

**存在哪**：用户配图／卡片／名片在**微信云开发存储**（环境 `cloudbase-d6gzh0i0tff02943a`，`cloudUpload.js:17`）；账上存 `cloud://` fileID 而非 S3 key（`models/asset.py:36`、`note_card.py:59`）。运营图落服务器磁盘（§3.9）。

**谁写**：

| 内容 | 谁写 | 路径 |
|---|---|---|
| 笔记配图／卡片／名片 | **小程序端** `wx.cloud.uploadFile`（`cloudUpload.js:64`） | `{kind}/{userId}/{YYYYMMDD}/{随机}.{ext}`（`:62`，kind 取 `images`/`cards` `:61`）；**字节不经过自建后端**（`routes/assets.py:5-8`、`cards.py:5-6`） |
| 文章外链贴图 | **后端 worker** 穿 `cloudfunctions/image_store` 进同一个桶 | `services/note_images.py:268-304`、`ingest_tasks.py:336-389` |
| 运营图 | 后端写服务器磁盘 | `services/mp_assets.py:115-132` |

**谁删**：**只有客户端删得动**（后端手里没有云开发存储写凭据，`config.py:85`、`image_store/index.js:9-12`）。后端删行时把 `file_ids` 回给调用方（`notes.py:575`、`cards.py:263-297`、`services/deletion.py:84-101,152`）；客户端有预留／撤销／补删队列（`cloudUpload.js:88-176`，落 `utils/assetPurge.js`）。

**⚠ 没有签名 URL、没有私有桶策略**：全仓零处 `getTempFileURL`，也没有桶 ACL 配置。**安全模型是"fileID 本身就是别人能读的地址"**，所以防线退到三处：入口校格式与长度（`routes/assets.py:53-54` `_clean_file_id`）、读口校归属、**非本主一律回 404 不回 403**。这一条风险与残留缺口（"离线删的笔记、注销路径清不到"）**代码注释里自己写着**（`assets.py:16-18`、`notes.py:553-557`）。

**图片尺子**：客户端压 长边≤1920／预算≤500KB／质量梯度 0.7-0.5-0.3，服务端逐字同值两份并有尺子钉住（`note_images.py:45-51`）；动图（GIF/APNG/动 WebP）原样存不压（`:210-249`）；防盗链占位图按"字节≤4KB **且** 长边≤200 **且** 非动图"三条件识别（`:63-66,186-204`）；下载**一律不带 Referer**（`:17-22,69-72`）；SSRF 闸门复用抓取那一道、**每跳重判**（`:148-182`）。

**身份侧的访问控制**：JWT Bearer（`core/auth.py`），**openid 不下发给客户端**；`/v1` 与 `/api` 两组钥匙互不通（§2.2）；限流走 slowapi（登录 5/分钟、邮箱 20/小时、举报 6/小时、小程序码 60/分钟）。

## 4.3 异步任务的可靠性

**队列**：RQ ＋ Redis，生产端 `services/queue.py:18-19`、消费端 `worker.py:9-10`，**队列名两边都显式写 `default`**。三个长任务见 §3.1。

**状态回读**：Redis 键 `task:<id>`，TTL 3600 秒（`queue.py:11,31-50`）；客户端轮询 `GET /api/tasks/{task_id}`。

**幂等四层**：
1. RQ `job_id` 复用；
2. 外链贴图落账按 `object_key` 查重跳过（`note_images.py:432-434`，且屏上那句实话刻意数 `kept` 不是 `written`，`ingest_tasks.py:371-379`）；
3. **数据库层五条部分唯一索引兜**（`ux_shares_one_active_per_note`、`ux_note_cards_one_current_per_note`、`ux_poster_templates_one_live_per_template`、两条 `ux_invitations_*`、`ux_mp_assets_kind_hash`），部署时逐条断言（`deploy.sh:119-273`）；
4. 一次性短码"用过＋过期"两条一起判（`link_codes.py:8-13`）。

**重试**：只有提炼侧成建制——`MAX_RETRIES=3`、指数退避 1/2/4 秒，**且只重试可能自愈的**（429、5xx、超时、云函数显式回 `retryable:true`）；4xx（除 429）、云函数回不可重试、非 JSON 响应**都不重试**（`services/llm.py:12-13,159-216`；`TransientExtractError` `:33-38`；云函数侧负责标 `retryable`，`extract/index.js:74-94`）。access_token 失效（40001/42001/40014）清缓存后**只再打一趟**（`wechat.py:33,178-196,302-315,404-427`）。**RQ worker 级没配 `retries`，即默认不重投。**

**超时表**：混元 `HUNYUAN_CF_TIMEOUT=90`（**必须大于云函数自身 60 秒**，`config.py:19-22`）、image_store 20 秒（`:96-98`）、抓取 30 秒＋正文 5MB＋最多 5 跳（`scraper.py:26,135`）、微信各接口 httpx 10 秒（`wechat.py:93,118,183,304`）、`code2session` 10 秒（`core/auth.py:83`）、Apple JWKS 10 秒（`core/apple_identity.py:37`）、任务 600 秒、nginx `proxy_read_timeout 30s`。

**并发面**：api 与 worker 共写同一 SQLite，靠 WAL＋busy_timeout；`_load_task_user` 用 `generation` 水位线防"注销后 id 被复用、A 抓的内容写进 B 的笔记"（`ingest_tasks.py:210-235`）；`deploy.sh:491-516` 明确禁止游离于两个 unit 之外的进程抢端口／抢队列。

**定时**：**仓库内没有应用层调度器**。已落地的定时只有那条每日备份 cron（§4.5）；举报保留期不自动清理（§3.5）。

⚠ **`jobs` 表现网零写入**：全仓只在删笔记／注销时删它（`routes/notes.py:546`、`deletion.py:34,47`），`idempotency_key` **无任何赋值处**（全仓检索只命中模型定义）。**任务状态的事实只在 Redis（TTL 一小时），因此任务不可回溯审计。**

# 6 应用场景

**学生与阅读者。** 课堂截图、文章摘录存了一堆，复习还是要重读一遍、手抄一遍、再想归到哪。图麦笔记把这三步合成一步：扔进来，出来就是带编号要点和标签的笔记，之后按关键词搜得到、按分类翻得到。

**年轻创作者。** 有观点、有资料，但要发出去还得花时间把文字排成一张好看的图。这里选好内容，挑一套卡片样式，直接出图存相册。

**日常记录者。** 旅行攻略、灵感、生活清单散在相册和聊天记录里。首屏一个入口，拍一张、贴一段就进来了。

# 7 产品边界

写清楚，免得有人期待错。

- **不做手写识别。** "写"那一档是你打字或粘贴，不是识别笔迹。
- **不做商品识别、不做估价。** 拍照读的是图上的文字。
- **不做语音录入。** 这条能力已经下线。
- **不支持 HEIC 格式的图片。**
- **不做多端实时同步。** 手机是主，云端是备份与找回，不是多人协作。
- **没有团队、席位、权限管理。**
- **不做内容审核豁免。** 你发布的内容会过内容安全检查；违规的会被挡下并提示。
- **卡片上的 AI 生成标识和来源信息不提供"去掉"的付费档。**
- **不承诺任何一篇内容"永久保存"。** 图片有留存周期，公开链接以你主动撤回为准。
