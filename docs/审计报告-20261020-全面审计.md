**N1｜后端｜新用户登录可以被打成永久进不去**〔代码＋本地实测〕
- 落点：`backend/app/api/routes/auth.py:16` `inviter: int | None = None` → `backend/app/core/auth.py:193-194`
  ```python

      quota.attribute_inviter(user, db, inviter)
  ```
  （**这一句不在任何 try 里**）→ `backend/app/services/quota.py:96` `if db.get(User, inviter_pk) is None:`
- 撞法：分享卡片的路径就是 `/pages/create/create?inviter=<id>`。谁把 `<id>` 换成一个超过 int64 的数（`1e21`），
  小程序 `app.js:46` 用 `parseInt` 收下、`:49` 存进本机、`:185-186` **每次登录都带上**。
- 实测：驱动层绑定 `10**21` 抛 `OverflowError: Python int too large to convert to SQLite INTEGER`
  （`10**18` 与 `2^63-1` 正常）；10-18 那轮给 `skip` 修的就是同一枚。
- 后果：那一台设备**每次登录都 500**，而本机那份 inviter 只在成功时才删（`app.js:146`）⇒ 不清缓存就再也进不来。
  其余 33 处同类裸 `int`（`note_id`/`asset_id`/`card_id`/`category_id`/`inviter`）撞进去只是那一个请求 500。
- 修法：所有 int 入口照 `skip` 那只补 `le=9223372036854775807`；`auth.py` 那一行外面再包一层（归因失败不许挡住登录）。
  **不发版；要写现网。**
- 现网底数：今天 5xx 零条 ⇒ 还没人撞过，这是"能不能被撞"不是"已经坏了"。
