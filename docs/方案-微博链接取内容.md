## 一、先说清楚为什么以前取不到（这不是回归）

现网那一发拿的是 HTML：302 → `passport.weibo.com/visitor/visitor`，9,158～9,648 B 那一张
标题写着 `Sina Visitor System` 的访客壳页，正文 **0 字**。10-19／10-29／10-31 三回读数一致
（`docs/枚举-URL转存全部情况.md` 表一第 6／7 行、表七第 16／17 行）。

⇒ 卡点在站点那一侧，而且**只卡 HTML 那一发**。10-31 的解法不是把访客墙爬过去，是换一发：
微博自己的移动页数据接口 `m.weibo.cn/statuses/show?id=<id>` 不要 cookie、不要浏览器、不要端上签名，
带上四枚头就回 `ok:1` 和那份数据。

## 二、这一发要吃哪四枚头／回的是什么形状（全部为 10-31 现读）

| 一项 | 读数 |
|---|---|
| 主口 | `https://m.weibo.cn/statuses/show?id=<mid 或 bid>`；**mid（16 位数字）与 bid（9 位字母数字）两种都认**，`H5Ro3mlPz` 那种就是 bid |
| 必须的头 | 四枚一起带：`Referer: https://m.weibo.cn/`、`X-Requested-With: XMLHttpRequest`、iPhone 的 `User-Agent`、`MWeibo-Pwa: 1`。**10-31 在现网出口逐枚摘头发过六发，真正承重的是前两枚**：摘 `Referer` → **403／81 B／`errno 100015`**、摘 `X-Requested-With` → **302 进访客壳**；摘 UA（连 curl 默认那枚都不给）与摘 `MWeibo-Pwa` 都仍 200／`ok:1`（那两枚留着只为"像同一个客户端"，不许当可省的删）。一枚都不带 → 302 进 `visitor.passport.weibo.cn` 那张壳页 |
| 全文口 | `statuses/extend?id=`，**只在 `isLongText` 为真时**多打这一发；回空不报错（主口那一份照用） |
| 正文 | `data.text` 是**一小段 HTML**：`<br/>` 是换行、表情是 `<img alt="[衰]">`、话题是 `<a><span class="url-icon"><img 无 alt>…</span><span class="surl-text">周深</span></a>`。压法＝`<br>`→换行、`img`→它的 `alt`（没 alt 就丢）、其余取显示字 |
| 配图 | `pics[].url` 是 `orj360`（360×479 那一档），`pics[].large.url` 是 `mw2000`（2048×2730）⇒ **取 `large.url`**，下游要压进单张预算，从 360 起压只会更糊 |
| 标题 | `status_title`（现读图文那条掐着头回「…咱们主...」⇒ 结尾那三个点抹掉）；没有就用「<作者> 的微博」，再没有就「微博正文」 |
| 作者 | `user.screen_name` |
| 转发 | `retweeted_status` 那一份接在自己那句后面，写法照微博屏上那个 `//@原作者：原文`；两边的图并一起（先自己再原文），张数上限仍归下游那 9 张 |
| 取不到的两种 | **都是 HTTP 200**，只有数据里的码分得开：`errno 20101`＝不存在或已删、`errno 20170`＝博主设了权限。屏上念的两句逐字是「这条微博不存在或已被删除」／「这条微博设置了权限，看不到内容」 |

## 三、四条形状，下一个人不许改错

1. **失败软着陆：新代码只能让结果变好。** 认不出 id、不是微博的站、那一发回了非 JSON、
   结构对不上——一律回 `None`，落回今天那条 HTML 那一路。所以这一刀之后最坏的情况是"和今天一样"，
   不存在"以前能存、现在存不下"。
   ⚠ 这一条有个反面：**按主机名认，不按子串认**。闸门那一层用 `hostname in {weibo.com, www.weibo.com, m.weibo.cn}`，
   拿 `"weibo.com" in url` 判就能被 `weibo.com.evil.example` 拼进队——这条有反向钉（`test_scraper_weibo.py`）。
2. **取不到 ≠ 一次站点级失败。** 微博那一条链上凡是"这一条本身取不到"（已删／设权限／只有视频／超 5MB）
   一律走 `UserError`，**不返回 0 字正文**。理由只有一个，很硬：`docs/规格-来源黑名单.md` 那两道计数器
   只把「4xx／5xx」与「200 且正文 0 字」记进账，阈值 3 次、**全局累计、不清零、进了名单不会自己出来**。
   要是每条被删的微博都回 0 字，`weibo.com` 整族会被永久拦下——代价与收益完全不成比。
3. **配图那一族的来路只能"点名给"，不许做成全局开关。** 10-31 现网出口六发矩阵：
   同一枚 `wx*.sinaimg.cn` 地址，**一枚头都不带＝200**、**带生产那套头（桌面 UA）而不带来路＝403／238 B**、
   **带 `https://m.weibo.cn/` 或 `https://weibo.com/`＝200**（`orj360` 22,521 B／`mw2000` 1,248,453 B／`large` 2,853,517 B）、
   **带一枚外站来路（example.com）＝仍 403／304 B**。
   ⇒ 落码的是「抓取那一层把 `image_referer` 写进回体 → `_archive_images` 原样递 → `archive(referer=…)`」，
   其余各族那一格是空串。旧的"永远不带 Referer"那条纪律**没有撤**，只是把"默认"与"点名"分开了；
   两族防盗链的方向仍是相反的（`mmbiz.qpic.cn` 带错来路回的是 **200＋2,090 B 那张 140×140 占位图**、
   `sns-webpic-qc.xhscdn.com` 回**硬 403**，10-19 各打三次复现），所以判据写了两条：默认那一批不许带、点名那一批必须带。
   ⚠ 这也**推翻了旧台账里那句解释**（「微博不带 Referer 就 403」）：真正卡的是"这枚 UA 配不配带对来路"，
   不是"缺来路"本身。解释改了、结论没改，就地记在 `docs/枚举-URL转存全部情况.md` 表四第 3b 行。
4. **这一族没有官方接口。** 走的是站点自己移动页在用的那一发，形状跟着改版会漂。
   所以第 1 条那种软着陆不是客气，是这一条链的前提；并且**不承诺"所有微博链接都行"**（第五节）。

## 五、现在到底行／不行（每族样本仍是 1～8 条，不外推）

**行（现网出口含闸门，逐条读数在尺子输出里）**：`weibo.com/<uid>/<mid>`、`weibo.com/<uid>/<bid>`（带话题）、
`m.weibo.cn/detail/<mid>`、长文那种（多打全文口那一发）、转发那种（转发语＋`//@原作者：`原文）。

**不行，且老实念一句／老实落回原路**：

| 那一型 | 屏上现在念什么 |
|---|---|
| `weibo.com/u/<uid>`（主页，不是某一条） | 落回网页那一路 → 仍是 0 字那句「未能从 URL 提取到有效内容」（**与今天逐字相同，不新增失败**，但见第六节那一格） |
| 头条文章 `weibo.com/ttarticle/p/show…` | **没量过、没写这一路** ⇒ 走网页那一路。这一族能不能也拿到，谁都没读数 |
| `t.cn` 短链 | **没验过跳转后的落点长什么样**，所以现在不认。验过再说，不在这里承诺 |
| 视频微博（只有视频、没文字） | 「这条微博只有视频，没有文字内容」（这一句只在用例里证过形状，**没有活样本**） |
| 已删／设了权限 | 「这条微博不存在或已被删除」／「这条微博设置了权限，看不到内容」（两句都有活样本，逐字回显过） |
| 图集九张以上 | 仍按现成那条链：前 9 张进桶，屏上念「这篇原文有 {n} 张图，只留下了前 {k} 张。」 |
