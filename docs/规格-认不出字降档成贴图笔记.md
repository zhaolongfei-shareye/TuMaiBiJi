## 一、什么时候走这一档

一条：**这一次认出来的字数不足 5 个字符**（数法见 §二最后一则）。

| 情形 | 走哪条 | 屏上 |
|---|---|---|
| 认出 ≥5 个字符 | 老路：LLM 提炼 → 建笔记 | 标题／摘要／要点／原文都有 |
| 认出 ≥5 个字符但 LLM 不可用 | 老路：原文照存，回体带 `degraded: True` | 标题取正文首行 |
| **认出 1–4 个字符** | **这一档：建贴图笔记，摘要那一格写那几个字本身** | 标题自动组装＋配图＋摘要一行 |
| **一个字符都没认出来** | **这一档：摘要那一格写「图册」** | 标题自动组装＋配图＋摘要一行 |
| OCR 引擎自己炸（超时、像素超限、模型起不来） | **仍然报错**，库里零行 | 红字一句（反向尺子 `tests/test_ocr_flows.py:395`） |

`degraded` 与 `image_only` 是两件事，不共用一枚：前者说的是"提炼这一步不可用"，后者说的是"这篇是贴图笔记"。
不足 5 个字符这一批**不再送去提炼**——省一次模型调用是顺带的，要的是别拿三五个碎字编出一篇像样的笔记。

## 二、屏上那一句标题怎么拼

```
{名称}图片笔记 {MMDD}{序号}          例：阿麦图片笔记 101901
```

**名称**三级兜底，逐字照他 10-19 点的丙：

1. `user_profiles.name`（「我的」页那格名片名称）；
2. 空或全空白 → `users.nickname`（微信昵称）；
3. 还空 → 固定词**「我的」**。

空白串按"没填"处理（`.strip()` 之后判），所以不会画出"  图片笔记 101901"那种带两个空格的样子。
最后一级不落 openid／账号 id：那是标识符不是名字，进标题等于把他的 id 印在每篇笔记第一行。

**日期**按**北京那一天**（`UTC+8`）。库里 `created_at` 是朴素 UTC（实测：北京 11:03 存的那篇库里写 `03:03:57`），
所以"今天"先换成北京日、再把窗口两端折算回朴素 UTC 去比。凌晨 0–8 点那两个小时是这条唯一会错的地方。

**序号**＝**当天窗口内、同一账号、`source_type=screenshot` 的笔记里，标题尾号的最大值 +1**，两位起
（`01`、`02`…），第 100 篇起自然变三位（`1019100`）。
- 为什么不是"数当天有几篇 +1"：那样在"删掉一篇再存"时会把已有那篇的号重新发一遍，屏上出现两行逐字同名。
- 尾号只从标题尾巴那串数字读（`图片笔记 (\d{4})(\d{2,})$`），所以他手动改出来的号也算得进去——
  **宁可空掉几个号，也不发一个已经存在的号**。
- 标题里那四位也要等于今天才算数，双保险：窗口筛过一遍、四位再对一遍。

**来源那一格不动**（他点甲）：`source_type` 仍是 `screenshot`，列表／详情窗／详情页／卡片上那格
照旧念「截图识别」。这一档**没有**新起一个"贴图笔记"的类型，屏上看不出它和认得出字的那批是两回事。

---

**字符怎么数**（这一档的门槛，站长 10-19 补的那半句点的甲）：**剥掉所有空白之后数字符**，中英文数字一律一个字符算一字，
标点算字符，**不按词数**。不足 5 个就走这一档：`OK 3` 数出来 3 个 ⇒ 降档；`HELLO`、`a b c d e` 都是 5 个 ⇒ 走老路。
数出来的那把尺子和写进摘要的那一份**必须是同一个读法**，否则会出现"数出来 4 个、屏上写着 5 个"这种没人能解释的差。

## 二·补 那一句摘要写什么（站长 10-19 补的半句）

「字自动写入其他空白字段，如果完全识别不了，也不要空白字段，默认写"图册"」——落下来只动**摘要那一格**（他点甲）：

- 认出 1–4 个字符：摘要＝**那几个字本身**，写法是把内部连续空白压成一个空格、首尾去掉
  （`你好\n世界` 写成 `你好 世界`；`<view>` 本来就把换行折成空格，见 §8.316 那一族）。
  英文那一路不许学计数那样全删——`OK 3` 要写成 `OK 3`，不是 `OK3`。
- 一个都没认出来：摘要＝**「图册」**（常量 `IMAGE_NOTE_PLACEHOLDER`，界面上就这两个字，不带引号）。
- **原文那一栏与要点那一栏照旧不写、不画**，那枚「展开原文」也不出现。

## 三、图是怎么留下来的

照片那一趟本来就是**两条链并行**（2.0 定的 A/B 双链）：

```
A 链：POST /api/ingest/screenshots/process → worker 认字 → 建笔记 → 回 note_id
B 链：客户端逐张压缩 → 直传微信云开发 → 攒一批 file_id，等 A 链的 note_id 去绑
```

绑不上就删。以前"认不出字"让 A 链空手回来，于是 B 链把刚传上去的原件当孤儿删了
（`pages/create/create.js:1002`）；现在 A 链照给 `note_id`，图就自然留下。
**客户端一行没改**，那一屏的走法与"提炼成功"完全同一条：吐司一句「已存入笔记」→ 800ms →
回笔记列表并替他把那篇的详情窗打开（§8.337 那一条落点）。

一条老实话：**服务端不知道那批图最后成没成**（B 链在它旁边跑）。所以云没配那台、或弱网一张都没传上时，
这一刀会建出一篇**只有标题的笔记**。这不是这一刀新造的形状——今天"提炼成功但云没配"建出来的就是这样一篇，
`_settleBackup` 在 `items` 为空时静默返回（`create.js:1001`）。我没有为这一格另加话术。

## 四、屏上画哪几块

`notes` 表里 `summary`／`key_points`／`original_content`／`imported_from` 都可空，`title` 非空——
这一档写 `title`／`source_type`／`summary` 三格，其余留空，各处自带 `wx:if`：

| 落点 | 判据（现读） | 结果 |
|---|---|---|
| 首页详情窗·摘要那一栏 | `index.wxml:266` `wx:if="{{detailNote.summary}}"` | **画出一行**：那几个字，或「图册」 |
| 首页详情窗·要点那一栏 | `index.wxml:269` `wx:if="{{detailNote.key_points && detailNote.key_points.length}}"` | 不写 ⇒ 整块不出现 |
| 首页详情窗·原文那一栏＋「展开原文」那枚 | `index.wxml:283`／`291` | 不写 ⇒ 那栏与那枚按钮都不出现 |
| 独立详情页·摘要／要点／原文三块 | `detail.wxml:87`／`92`／`107` | 只有摘要那块画，另两块不出现 |
| 笔记列表那一行 | 列表不读 `summary`（`index.js` 那一趟没这一格） | 「图册」不上列表，只在窗里与详情页 |
| 配图那一排（`aspectFit` ＋同照片毛玻璃底） | `wx:if="{{detailImages.length}}"` | 有图就画，与正文无关 |
| 「这篇原文有 N 张图」那两句实话 | 读 `imported_from` 快照 | 这一档不写快照 ⇒ 一句都不报（没做过的事不许说） |
