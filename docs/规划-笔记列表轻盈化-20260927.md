# 规划：笔记列表轻盈化（2026-09-27）

- **起因**：用户反馈列表"每条笔记前面一个方块，显得太重，不够轻盈"；而且色块颜色重，**选深色壁纸时和背景混在一起很难区分**。
- **这份文档的用法**：先给三版专家效果图挑方向（§1），再给一份"防推倒"的路线（§3 锚点 → §4 分阶段 → §5 负面清单 → §6 要拍的板）。**这次只谈列表页**，录入页那批（C 方向）另算。
- **当前状态（09-27 下午更新）**：方向已定 **D2**，并追加两条（圆角收小、底栏撤掉墨黑），修订稿见 **§1.1**。§6 里第 1 条已拍，剩 2/3/4/5/6 五条等拍；拍完才动代码。
- **数据出处**：`master` 的 `346966d`。所有对比度数字是我本机按 WCAG 2.x 公式算的，像素占比是无头 Chrome 渲染后逐像素数的，不是估的。

## 2. 现状硬事实（先看这个，不然会当成审美问题）

**结构**：一条笔记 = `.card.row`，左边 `.blk` 一枚 **176rpx 见方**的实心色块（`app.wxss:50` `--blk: 176rpx`，圆角 `--r-block: 32rpx`），块里从上到下塞了三样东西——分类名（`32rpx/800`）、日期（`18rpx/800`）、一个抽象母题图形（`app.wxss:338-390`）；右边才是 `.blk-body`（`pages/index/index.wxml:60-83`）。

**颜色来源**：`utils/palette.js:14-21` 五支分类色 + 一枚墨黑，`toneFor(categoryId)` 按 **id 取模**取一支（`:59-61`），由 JS 注入 `--blk-bg/--blk-ink`，**不随壁纸主题变**（`app.wxss:5` 明写着这条）。

**这五支色当初是按"大面积实心底 + 上面压字"选的**（`palette.js:4-6`：黄/橙/绿配白字只有 1.63 / 3.03 / 2.98，所以这三块改配深墨字）。也就是说：**判据是"字压色块"，不是"色块压卡片"。**

**一旦把面积降级成细线或小字，判据反过来，立刻有一串不合格**（我算的，压白卡 `#FFFFFF` / 压夜紫卡 `#181828`）：

| 分类 | 色值 | 压白卡 | 压夜紫卡 |
|---|---|---|---|
| 芥末黄 | `#F6C445` | **1.63** | 10.75 |
| 宝蓝 | `#3F52D6` | 6.20 | **2.82** |
| 橙 | `#E9723D` | **3.03** | 5.78 |
| 草绿 | `#46A863` | **2.98** | 5.87 |
| 紫 | `#6E4BD0` | 5.87 | **2.98** |
| 未分类墨黑 | `#23252C` | 15.30 | **1.14** |

加粗那几格就是问题的全部来源：**浅色下黄/橙/绿不合格，深色下蓝/紫/墨黑不合格**。WCAG 对非文本元素要 ≥3:1、小字要 ≥4.5:1，所以墨黑那枚 1.14 在深色下等于**隐形**——现在只靠一条 `rgba(255,255,255,0.16)` 描边救（`palette.js:81-83`，注释里写明白了"只有它有描边"），救不回来。

**还有一条更根上的**：夜紫下卡片底 `#181828` 压页面底 `#0C0C1D` 只有 **1.11**（`app.wxss:129-136`，卡片底是 `rgba(255,255,255,0.05)` 叠页面底）。所以深色下"卡片的边界"本来就全靠那条 `rgba(255,255,255,0.12)` 描边撑着——**块和底糊在一起，一半原因是卡和底也糊在一起**。这不是换形状能解决的，必须同时动"色值按外观分档"这件事。

**一个已经埋着的架构裂缝**：后端 `categories` 表**有 `color` 字段**（`backend/app/models/category.py:12`，默认 `#666666`），但前端**故意不用它**（`pages/index/index.js:124` 注释："不用后端那个 category.color——两者对不上时用户会以为分类乱了"）。**同一件事现在有两套真相，一套被停用**。自建分类的数量后端没有上限（grep 不到任何限制），而前端只有五支色——**第 6 个分类会和第 1 个撞色**。

## 3. 现在必须钉死的四条锚点（这几条不钉，将来一定推倒重来）

**锚点 1 · 分类色只有一个来源，且必须是"可派生的函数"而不是"一张固定表"。**
先定死来源归前端 `palette.js`（后端那个 `color` 字段要么停用并在文档里写明，要么删列——**不许两边都留着**）。再把取色从"5 支取模"改成一个派生函数：给定分类序号，产出**色相均分 + 明度按外观定档**的一组值。这样分类涨到 12 个、20 个都不用再改代码，也不会撞色。**这条是商业化/规模化倒推出来的：付费版本迟早要放开自建分类数量。**

**锚点 2 · 每个分类色成对定义（浅色档 + 深色档），页面里不许写死 hex。**
判据钉死：非文本元素（色签、圆点、描边）压卡底 **≥3:1**，文字（含 21rpx 的分类名）**≥4.5:1**。两档都过才算完。做法是走 CSS 变量（`--cat-line` / `--cat-ink` 由主题给），JS 只负责按分类算出"第几档"，不负责决定深浅。

**锚点 3 · 分类身份不许只靠颜色承载。**
色觉障碍、深色壁纸、聊天里被压缩转发的截图，三种情况下纯色标都会失效。所以**颜色 + 文字**必须同时出现（三版效果图都满足这条，D3 也满足——它至少还有"分类名"三个字）。

**锚点 4 · 行卡的信息槽固定四个：身份 / 标题 / 摘要 / meta。**
换方案只换这四槽的画法，不改数据字段、不改 `blockStyle` 之外的任何接口。日期现在住在方块底部，换方案后并入 meta 行右端——这是**画法变化，不是字段变化**。

## 4. 分阶段（每一段独立可验收、独立可回滚，前一段不等后一段）

**阶段 0 · 这次做：换画法 + 补第二档色值。**
选定方向后：`palette.js` 给每支分类色加一档深色值（D1/D2/D3 的稿子里都已经给了具体 hex，可以直接采纳）；`app.wxss` 加 `--cat-line`/`--cat-ink` 两个主题变量；列表页 `.blk` 换成新画法，筛选胶囊和详情页跟着换（**同一个分类在全应用只有一张脸**，这条规矩不能破）。
验收：`docs/工具/验-色板零回归.js`（现 67 条）跟进 + **新增一把尺子**扫"6 分类 × 8 壁纸 × 卡底"的两档对比度（不达标就红，反向验过）+ 模拟器浅色/夜紫两屏实拍。回滚：整批一个 commit，只碰列表页和色板。

**阶段 1 · 下个版本：把"5 支取模"换成派生函数。**
这一步会**连带改海报**——`poster.js:41 paperOf` 和 `palette.js:284 plateColors` 都吃 `toneFor`，所以必须单独一批、单独验（海报那十套刚定稿，不能顺手带）。验收要加一条：造 12 个分类，逐个出图，色相不撞车。

**阶段 2 · 外观系统收口。**
八枚壁纸归成"明/暗两族 + 一张 token 表"，顺手解决"卡片压页面底只有 1.11"这条边界问题（深色族要么提卡片底亮度，要么把描边抬到 ≥1.3）。这张 token 表同时是给 iPhone 版的跨端契约——**只出文档，不动那个仓**。

**阶段 3 · 无障碍与规模化验证。**
色觉障碍模拟复看、系统大字模式、英文长分类名（现在靠渐隐裁尾）、分类数 >12 的真实取色。

## 5. 负面清单（这几条现在不要做，比路线图更防返工）

- **不要把分类色删干净**。"轻盈"不等于"无色"——完全去掉颜色会让海报色带和波普四格一起失去来源（它们和列表吃同一支 `toneFor`）。
- **不要在这一轮动海报模板的色带**。1.5.0 正在审核中（提交时间 2026-09-27 11:53:27），海报刚在 §8.47 定稿，碰它等于把两批风险叠一起。
- **不要给分类加图标库、封面图、用户手动配色面板**。都没提过；手动配色是产品决策（见 §6 第 3 条），不是这次的技术活。
- **不要为了阶段 1 的派生函数推迟阶段 0**。两档定值现在就能落地。
- **不要在 wxss 里为深色主题另抄一串 hex**。必须走 CSS 变量，否则第三次还是这个坑。
- **不要顺手改搜索条**。D2/D3 两张稿子把现网那块**饱和色卡**（`pages/index/index.wxml:12-25`，里面只有一条横线）画成了纯横线，那是稿子越界，不是要改的东西。（D2 修订稿已按现网原样画回来，只跟圆角阶梯从 40 收到 24。）
- **不要把圆角收成"只收首页"**。`--r-card` / `--r-pill` 是全站令牌，改就是所有页面一起改；另起一个"只在列表用"的圆角令牌会养出两套几何，下一轮一定走样。
- **不要在底栏上同时留"文字标签"和"图标垫块"两种选中语言**。要么照咖啡人只留图标 + 垫块，要么留文字 + 一条短线，两种混着用等于没说。
- **不要动 `验-字眼与模板条.js` 钉住的那三个入口叫法**（URL链接 / 拍照或截图 / 亲自撰写）。

## 6. 要你拍的板

1. ~~**三版选一**~~ → **已定 D2**（2026-09-27）。原推荐是 D1，理由一并留档，免得以后回看不知道当初为什么没选它：D1 保住了"扫一眼认分类"（颜色从面积变成线），深色下六档全部 ≥6.2，改动面最小；D2 最干净、最像国际主流工具，认分类从"扫色"退成"读字"——你选了 D2，那就按 D2 走，§3 锚点 3（颜色 + 文字同时出现）在 D2 下是硬约束，不能哪天把分类名文字省掉。
2. **未分类还继续用墨黑吗**。深色下 1.14 就是它糊掉的根因。建议照 D2 的做法改成**空心环 + 亮墨字**（"没颜色"这件事本身就该长得不一样）。
3. **以后要不要让用户自己挑分类色**。这条直接决定阶段 1 的形态（能挑色 = 派生函数必须支持"用户给的色也自动配出深浅两档"，工作量翻倍但更商业化）。**现在不做**，但你要提前说要不要留这个口子。
4. **日期从方块底部挪到 meta 行右端**，接受吗。这是视觉记忆点的变化，不是功能变化。
5. **底栏那三个字（新建 / 笔记 / 我的）撤不撤**。咖啡人的底栏只有图标，修订稿照它撤了字、选中态改成图标垫块。撤字更轻，但"最左那枚是新建"这件事就全靠一个加号说清楚；不撤就走 §1.1 标注屏里那条"文字 + 短线"的备选。这条只影响 `custom-tab-bar`，不影响列表。
6. **圆角这一档收到多少**。修订稿给的是 卡 24 / 控件 14 / 小牌 8（rpx）。这是**全站**令牌，点一次头就是所有页面一起变，不是只改首页。

## 7. 这份文档里没验到的

- 三版效果图是 CSS 画的**示意**，不是真机；深色屏是在浏览器里按现网变量复算的卡底色（`#181828`），真机上微信还会画一层自己的底色，最终以模拟器实拍为准。§1.1 那两个"纯黑比重"的数同样是浏览器里数的，同理。
- **咖啡人那三条看图事实的边界**：图来自 App Store 官方列表（id 6757520656，v1.3.0）里两张带底栏的宣传图，不是我们真机抓的，也不是它的浅色主题——**它浅色下底栏长什么样我没看到图**。所以"淡底"这一档只在我们自己的米白 / 夜紫两屏上画过。
- **修订稿只画了八枚壁纸里的两枚**。剩下六枚没画，尤其象牙 / 天青那两套"整套色阶"：现网底栏的墨色是 JS 按主题递进来的（`custom-tab-bar/index.js:37-41`，那两枚递的是暖褐 / 冷绿），换淡底后这个"递"的方向要反过来（浅色档递纸白、深色档递白@10%），**这条只推理过，没实测**。
- "一屏 5~6 条"是估的，没按具体机型量过行数。
- 阶段 1 换派生函数对海报的实际影响**只做了来源分析，没出图验证**。
- 色觉障碍下三版各自还剩多少区分度，没测（留给阶段 3）。
