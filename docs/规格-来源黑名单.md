## 二、现网事实（三条现读，决定这功能必须新建什么）

1. **失败今天完全不落库。** 任务态只在 Redis 且只活一小时：`app/services/queue.py` 的 `TASK_TTL = 3600`、`set_task_status()`。⇒ **没有任何历史可查**，"累计 3 次"必须新建一张能存下来的表。
2. **`jobs` 表看着合适，但它是空的。** `app/models/job.py` 有 `status`／`error_message`，可**全仓找不到一处 `Job(...)` 构造**（本地库现读 `jobs`＝0 行）——和 `assets` 当年"建好之后全仓零写入"是同一个形状。**所以不复用它**：拿一张从没被写过的表做计数，等于先要做另一件"把写入补上"的事，那不在这条里。

另外两条口径沿用现网、不重写：域名从 URL 里取走的是 `_validate_url`／`urlparse` 那一套；`_detect_source_type()` 里已经有按 `mp.weixin.qq.com` 字面分档的先例。

## 三、三处我直接定死（每条给唯一答案与理由，不摆甲乙）

**① "失败"只数『站点级确定性失败』，其它一律不计数。**

计入这一类的只有两种：
- 抓页返回 **HTTP 4xx／5xx**（实测到的一型：知乎＝**403** + `zse-ck` 反爬页）；
- **200 但正文读出 0 字**（实测到的一型：微博＝**200** + `Sina Visitor System` 访客页，`_parse_general_url` 读出 0 字）。

**明确不计**（这四类一条都不许加进去，理由都不是"实现难"而是"计了会误杀好站"）：
- **混元提炼失败／额度打光／`degraded`**——那是我们自己的账。这台机器上有现成教训：10-13 那次现网 `.env` 少三行，提炼**静默降级**了一整天；那种一天能把所有站刷进黑名单。
- **网络超时、连不上、DNS 失败**——偶发，且换一次就好。
- **RQ 队列／worker 挂了**——我们的故障。
- **单张贴图下载失败**（`方案-公众号贴图随笔记存档.md` 那一路）——一张图被原作者删掉不代表整站读不到。**贴图那一路的失败与这条黑名单互不喂数**，两边都要钉这条。

**② 计数维度＝主机名原样，不去子域、不合并注册域。**

`www.zhihu.com`／`zhuanlan.zhihu.com`／`m.zhihu.com` 各算一条。理由：这三者的可读性**可能不同**（我实测到的是 `www.zhihu.com/question/…/answer/…` 403，**没测过 zhuanlan**），合并就是拿一个子域的证据去判整族，属于"证据不够就下结论"。**代价说在前面**：同站不同子域要各攒满 3 次才拉黑，拦得比"整族拉黑"慢——这是故意的，宁可慢也不能误杀。管理员要快就手工加（他要的那一格本来就是手工）。

**③ 阈值 3 次是『全局累计』，不分用户、不清零。**

主机名是唯一索引，`fail_count` 全站共用。理由：黑名单描述的是**这个站点能不能读**，不是某个用户的运气。进了名单之后**不自动过期、不自动移出**（这条明确不做，见第八节），要出去只有管理员手工移。

## 四、命中之后用户看到什么

- 提取入口**前置一次查询**（走主机名唯一索引，一次读，不打外网）；命中就**直接失败返回**，不发 HTTP——省资源这条要能被证明（第六节判据第 3 条）。
- 那句 toast（≤30 汉字，我起草、他要改一句就行）：
  > **「这个网站读不到内容，已停用」**
  为什么这么写：① 说清了"读不到"是真发生过的（它确实被记了 3 次）；② 不说"这个网站有问题"（我们不替别人定性）；③ 不说"暂不支持"（那是他打过回的含糊话）。
- ⚠ **这句话不许承诺"点这里申诉/会自动恢复"**。用户要说得上的地方是现网那格邮箱（「我的」页），不在 toast 里；那句引导放帮助文档，与「支持来源」清单写在一起。
- **只拦『链接提取』这一路**：用户手动上传截图、拍照、亲自撰写**一律照常**；黑名单不参与、也不显示在那几条路上。

## 五、后台那一栏（`/ops` 新增，管理员看得懂才叫能管理）

一栏里每行给这六个数，一个都不省：

| 列 | 为什么必须有 |
|---|---|
| 主机名 | 他要的那格 |
| 失败次数 | 判"3 次"这条阈值真不真 |
| 最后一次的 HTTP 状态码 | 一眼分得开 403 与 200-壳页（两种形状都在第三节） |
| 最后一次失败时间 | 判它是不是半年前的旧账 |
| 进名单方式：自动／手工 | **这条是"手工增删"能不能收拾自动那一份的前提**；没有它，管理员分不清哪些是自己加的 |
| 一句移出按钮 | 他要的"删" |

⚠ 一条边界，与 A4 那张卡的区别要说清：**这里允许列主机名**。A4 那张"一个分类名都不列"的理由是分类名＝用户写的字、与正文同源；主机名是**站点标识**、由我们的代码从 URL 里取出，不是用户创作的内容。两条不冲突，别照搬成"后台什么都不许显示"。

接口形状（照现成那几口的样子）：`GET /api/admin/source-blocklist`、`POST`（手工加一个主机名）、`DELETE`（按主机名移除），全部要管理票（`get_admin`／`_decode_admin_ticket()` 那一份实现，不改），写口各带限流（照 `admin_ops.py` 里读写分开配数的那种写法）。

## 六、判据（另一路不必做，我自己立；反向钉为主）

1. **阈值边界**：同一主机 2 次确定性失败 → **不进**名单；第 3 次 → 进。钉数不钉话。
2. **不计数那四类各钉一条**：提炼失败／超时／worker 挂／单张贴图下载失败，喂进去之后 `fail_count` **必须不涨**（这条不立，将来就是把自家故障算到网站头上）。
3. **命中不出网**：给抓取那一步放一个计数替身，命中黑名单的请求**替身调用次数必须是 0**——"省服务器资源"这一句只有这条抓得住，光看返回话抓不到。
4. **移出即生效**：手工移除后同一主机再提必须放行（负向钉：不许出现"移出还被拦"）。
5. **自动与手工分得开**：手工加的那行 `source='manual'`，且手工加**不要求**先攒够 3 次（否则他没法立刻拉黑一个新站）。
6. **两张表互不喂数**：贴图那一路的失败不许进这里的计数（第三节①那半句的代码化）。
7. **没票的三个口**：无票／错票 → 401/403，不许读到主机名列表。
8. **迁移**：新表要走 `add_column`/`create_table` 那套既有形状。**这一条比看起来重**，见下面第七节（这一条不是纯技术活）——它不是纯技术活，要他先点一件事。
9. **不改现网那句失败话**：`未能从 URL 提取到有效内容`／`该网页需要登录，无法读取` 这两句保持原样，黑名单那句是**新增的一型**，不许把老的合并掉。
