# 调研：卡片的图片支持动图吗（10-23）

他一句「调研下，卡片的图片支持动图吗」，接着「你自己先验证」⇒ 下面每一条要么有代码行号、要么有我自己打出来的读数；没有的明确写"没验"。**代码一行没动、没部署、没出包、没碰现网写入。**

## 一句话结论

**卡片不支持动图，而且不是卡片的错——它拿到的源图早就是第一帧。** 屏上直接放图的那三格（列表缩略、详情窗配图、看大图）会播；卡片那条是"画布画一遍 → 导出 PNG"，画布只取第一帧、PNG 本身装不下动图；再往前一站，手机选的图在出手机之前就被压成 JPEG 了。现网此刻 `assets` 表 **129 行逐行 `file_type` 全为 `image/jpeg`＝一张动图也没有**。

## 为什么卡片注定不动（一条链走完）

1. 图进来：手机选的 → 第一帧 JPEG（`compressForBackup`）；URL 转存的 → 动图原样入库。
2. 卡片出图：`<canvas type="2d">` 上 `createImage` + `drawImage` 画一次，`canvasToTempFilePath({fileType:'png'})` 落一张位图。画布那一趟我实测过——三个时刻采的都是第一帧。
3. 屏上看卡片：显示的是第 2 步那张 PNG 的临时路径，`<image>` 组件本身会播 GIF，但源里已经没有第二帧可播。
4. 分享出去：微信好友／朋友圈吃的是这张位图文件，位图不可能是动图。

⇒ 要让"卡片"动起来，只能换架构：卡片那一层不烘焙位图、改成 `<image>` 直接摆动图。而**一旦要分享出去（存相册／发好友）就必须落回位图，动图必然掉帧**——这一条不是我们代码能改的。

## 存量与代价（他没问，先摆着不动）

- 现网 `assets` 129/129 全 JPEG ⇒ 改不改都不影响存量，这一条是"要不要支持"而不是"存量坏了"。
- 想让 URL 转存来的 GIF 在屏上播：现在就已经能播（列表／详情／看大图三格实测）。
- 想让卡片播：见上面第 4 步那条硬限制；且要给动图单独开一条"不导出位图、只在屏上显示"的分支。

## 两条我打错又改回来的读数（别再踩）

- ⚠ **第一次判"列表那一格不播"是假红**：我按纯 (255,0,0)／(0,255,0) 数样本，屏上实际是色域转换后的 (234,51,35)／(90,197,58)，红绿两档各读成 0 px，于是六张图只看得出蓝。按屏上真读数重打才看见换帧。
- ⚠ **第二次裁错位置**：`el.offset()` 报的 y（349.07 rpx → 折算 683 px）与截图里那格的实际落点（830 px）差 147 px，照它裁出来恒是 (175,164,158) 灰＝裁到了卡片底。这一格的落点要用"帧色像素自己框出来"（bbox (600,830)–(687,917)），别信 `offset()`×缩放。

## 没验到的三格

- 详情窗那一排 `<image>` 没单独采帧（与列表同组件同源，推定能播）。
- 真机上有没有模拟器那层色域差、iOS/Android 是否有差别——没上真机，也没让他或任何人替我测。
- 服务端预览引擎那一份对 GIF 的实际采帧，只读了实现，没在浏览器里采过点。
