## 〇、决策摘要

| 项 | 决定 |
|---|---|
| 模板本质 | **Prompt + 区块布局**，存服务端 JSON，客户端按 type 动态渲染 |
| 数据存储 | Note 表新增 `structured_content JSON` 列，老笔记该列 null 走老渲染 |
| 模板管理 | 系统级模板，站长通过后端 JSON 配置，无用户自建模板（MVP） |
| 适用范围 | URL 导入 + 截图导入（有 LLM 环节）；手动撰写暂不走模板 |
| 发版频率 | 改 prompt / 改区块组合 / 加新模板 = **零发版**；加新渲染类型 = 发版 |
| 向后兼容 | `structured_content` 为 null 时走现有 summary → key_points 老渲染 |
| 默认模板 | slug=`general`，prompt 和现有 SYSTEM_PROMPT 完全一致，行为不变 |

## 一、现状（改动起点）

### 1.1 LLM 提取链路

```
用户提交 URL / 截图
  → 后端入 RQ 队列（ingest_tasks.py）
  → 抓取/OCR → 取文本
  → extract_knowledge(text) → 固定 SYSTEM_PROMPT
  → LLM 返回 {title, summary, key_points, tags}
  → 写入 Note 表对应列
```

**关键文件：**
- LLM 调用 + 固定 prompt：`backend/app/services/llm.py` → `SYSTEM_PROMPT` (L64-77) + `extract_knowledge()` (L80)
- URL 任务：`backend/app/tasks/ingest_tasks.py` → `process_url_task()` (L60)
- 截图任务：`backend/app/tasks/ingest_tasks.py` → `process_screenshots_task()` (L111)

### 1.2 详情页渲染

```
detail.wxml:
  hero 区 → note.title + note.tags
  摘要面板 → note.summary（if 存在）
  要点面板 → note.key_points 遍历（if 存在）
  来源链接 → note.source_url（if 存在）
  原文面板 → note.original_content 可折叠（if 存在）
  转存来源 → note.imported_from（if 存在）
```

**关键文件：**
- 渲染：`miniprogram/pages/detail/detail.wxml` (L1-71)
- 数据加载：`miniprogram/pages/detail/detail.js` → `loadNote()` (L54)

### 1.3 数据模型

**Note 表（`backend/app/models/note.py`）相关字段：**

| 字段 | 类型 | 当前用途 |
|---|---|---|
| `title` | String(500) | LLM 提取 / 手填 |
| `summary` | Text | LLM 提取的摘要 / 手填正文 |
| `key_points` | JSON | LLM 提取的要点列表 |
| `tags` | JSON | LLM 提取的标签 |
| `key_links` | JSON | **从未被 LLM 填充，详情页不渲染** |
| `content` | Text | **从未被 LLM 填充，详情页不渲染** |
| `original_content` | Text | 抓取的原文 / OCR 原文 |

**问题**：summary / key_points / tags 三个字段名硬编码在 LLM prompt、数据库列、详情页渲染三处。加一个新板块（比如"人物关系"）要同时改这三处 + 发版。

## 二、核心设计

### 2.1 一句话定义

**模板 = 给 LLM 的 prompt + 给客户端的区块布局说明**

```json
{
  "slug": "reading",
  "name": "读书笔记",
  "description": "适合书籍、长文的深度阅读笔记",
  "icon": "book",
  "prompt": "你是一个读书笔记整理助手...",
  "sections": [
    {"key": "summary", "label": "摘要", "type": "text"},
    {"key": "characters", "label": "人物关系", "type": "list"},
    {"key": "insights", "label": "核心观点", "type": "list"},
    {"key": "quotes", "label": "金句摘录", "type": "quote"},
    {"key": "tags", "label": "标签", "type": "tags"}
  ]
}
```

- **prompt** 告诉 LLM 要提取什么、按什么结构输出
- **sections** 告诉客户端有哪些区块、每个区块用什么组件渲染
- **type** 是客户端已实现的渲染组件（text / list / tags / quote / link），数量有限可穷举

### 2.2 为什么这样能减少发版

| 操作 | 传统方式 | 模板系统 |
|---|---|---|
| 改 prompt 措辞 | 改代码 → 部署后端 → 发版小程序 | 改数据库 JSON → 完 |
| 加一个"金句"板块 | 改 prompt + 加列 + 改渲染 → 发版 | 改 sections 数组 → 完 |
| 加一种全新渲染类型（如时间线） | 发版 | 客户端加一个 type 渲染器 → 发版一次 |
| 新增一个模板（如"会议记录"） | 发版 | 加一条数据库记录 → 完 |

**关键区分**：改"有哪些区块"不需要发版（数据驱动），改"区块长什么样"才需要发版（代码驱动）。而后者是可以穷举的。

### 2.3 客户端渲染器设计

客户端只认 **type**，不认模板名：

```javascript
// 六种渲染组件覆盖 95% 场景，后续扩展不超过 10 种
const SECTION_RENDERERS = {
  text: 'renderText',     // 段落文本
  list: 'renderList',     // 编号列表
  tags: 'renderTags',     // 标签行
  quote: 'renderQuote',   // 块引用（带左竖线）
  link: 'renderLink',     // 可点击链接
  table: 'renderTable',   // 简单表格（两列）
}
// 遇到不认识的 type → fallback 到 text，不会白屏
```

WXML 用 `wx:for` + 动态组件实现：

```xml
<!-- 动态区块渲染：structured_content 有内容时走这条路 -->
<block wx:for="{{note.structured_sections}}" wx:key="key">
  <!-- text：段落 -->
  <view wx:if="{{item.type === 'text'}}" class="panel">
    <text class="section-label">{{item.label}}</text>
    <text class="section-text">{{item.data}}</text>
  </view>
  <!-- list：编号列表 -->
  <view wx:elif="{{item.type === 'list'}}" class="panel" style="{{note.toneStyle}}">
    <text class="section-label">{{item.label}}</text>
    <view class="points-list">
      <view class="point-item" wx:for="{{item.data}}" wx:for-item="li" wx:key="index">
        <text class="point-num">{{index + 1}}</text>
        <text class="point-text">{{li}}</text>
      </view>
    </view>
  </view>
  <!-- tags：标签行 -->
  <view wx:elif="{{item.type === 'tags'}}" class="tags">
    <text class="tag" wx:for="{{item.data}}" wx:for-item="tg" wx:key="*this">{{tg}}</text>
  </view>
  <!-- quote：块引用 -->
  <view wx:elif="{{item.type === 'quote'}}" class="panel">
    <text class="section-label">{{item.label}}</text>
    <view class="quote-block">
      <text class="quote-text" wx:for="{{item.data}}" wx:key="index">「{{item}}」</text>
    </view>
  </view>
  <!-- link：可点击链接 -->
  <view wx:elif="{{item.type === 'link'}}" class="panel">
    <text class="section-label">{{item.label}}</text>
    <text class="link-text" bindtap="openLink" data-url="{{item.data}}">{{item.data}}</text>
  </view>
  <!-- 兜底：不认识的 type 当 text 处理 -->
  <view wx:else class="panel">
    <text class="section-label">{{item.label}}</text>
    <text class="section-text">{{item.data}}</text>
  </view>
</block>
```

## 三、数据模型

### 3.1 新增 templates 表

```python
# backend/app/models/template.py（新建）

class NoteTemplate(Base):
    __tablename__ = "note_templates"

    id = Column(Integer, primary_key=True, index=True)
    slug = Column(String(50), unique=True, nullable=False)     # 'general' | 'reading' | 'research' ...
    name = Column(String(100), nullable=False)                  # '通用笔记' | '读书笔记' ...
    description = Column(String(500), nullable=True)            # 创建页那枚卡片上的说明文字
    icon = Column(String(30), default="doc")                    # 前端按 icon 选 Lucide 图形
    prompt = Column(Text, nullable=False)                       # 给 LLM 的 system prompt
    sections = Column(JSON, nullable=False)                     # [{key, label, type}]
    sort_order = Column(Integer, default=0)                     # 创建页排列顺序
    is_active = Column(Boolean, default=True)                   # 关掉 = 创建页不显示，但老笔记不受影响
    created_at = Column(DateTime(timezone=True), server_default=func.now())
    updated_at = Column(DateTime(timezone=True), server_default=func.now(), onupdate=func.now())
```

**设计要点：**
- `slug` 是稳定标识，前端用它选模板，不改不删
- `prompt` 和 `sections` 都是 JSON 可热更新的字段——改它们只动数据库
- `is_active=False` 是软删除：老笔记的 `template_slug` 仍指向它，渲染不受影响

### 3.2 Note 表新增字段

```python
# backend/app/models/note.py 新增两列

template_slug = Column(String(50), nullable=True)        # 创建时用的哪个模板，null = 老笔记
structured_content = Column(JSON, nullable=True)          # [{key, label, type, data}]
```

**向后兼容规则：**
- `structured_content` 为 null → 详情页走老渲染（summary / key_points / tags 面板）
- `structured_content` 非 null → 详情页走新渲染（遍历 sections）
- `template_slug` 为 null → 老笔记，不影响任何逻辑

```python
def process_url_task(task_id, user_id, url, generation, template_slug=None):
    """新增 template_slug 参数，默认 None 走 general。"""
    # ...
    scraped = asyncio.run(scrape_url(url))
    text = scraped["content"]

    # 查模板
    template = get_template(db, template_slug or "general")
    template_prompt = template.prompt if template else SYSTEM_PROMPT  # 兜底用老的

    # 用模板 prompt 调 LLM
    knowledge = asyncio.run(extract_with_template(text, template_prompt, scraped["title"]))

    # 按模板 sections 组装 structured_content
    structured = []
    for sec in template.sections:
        value = knowledge.get(sec["key"])
        if value:  # 跳过空区块
            structured.append({
                "key": sec["key"],
                "label": sec["label"],
                "type": sec["type"],
                "data": value,
            })

    # 写入 Note
    note = Note(
        user_id=user_id,
        title=knowledge["title"],
        # 老字段也填：general 模板走老渲染，其他模板老字段为空
        summary=knowledge.get("summary", ""),
        key_points=knowledge.get("key_points", []),
        tags=knowledge.get("tags", []),
        original_content=text[:50000],
        source_type=scraped["source_type"],
        source_url=url,
        template_slug=template_slug or "general",
        structured_content=structured,
    )
```

#### 4.2.4 模板缓存策略

```js
// 创建页 loadTemplates 加本地缓存
async loadTemplates() {
  if (this.data.templates.length) return

  // 先读缓存（秒开）
  const cached = wx.getStorageSync('noteTemplates')
  const cacheTime = wx.getStorageSync('noteTemplatesTime') || 0
  if (cached && Date.now() - cacheTime < 3600000) {  // 1 小时缓存
    this.setData({ templates: cached })
    return
  }

  // 后台拉最新
  try {
    const templates = await api.getTemplates()
    this.setData({ templates })
    wx.setStorageSync('noteTemplates', templates)
    wx.setStorageSync('noteTemplatesTime', Date.now())
  } catch (err) {
    if (cached) this.setData({ templates: cached })  // 网络失败用旧缓存
    console.error('加载模板失败', err)
  }
}
```

## 五、数据流（终态）

### 5.1 创建流程

```
用户在创建页选模板（默认"通用笔记"）
    ↓
提交 URL / 截图 + template_slug
    ↓
后端入队 RQ（带 template_slug）
    ↓
Worker 取模板 prompt → 调 LLM → 得到 JSON
    ↓
按模板 sections 组装 structured_content
    ↓
写入 Note（title + structured_content + template_slug + 老字段兼容填充）
    ↓
详情页拿到 structured_content → 遍历渲染
```

### 5.2 模板更新流程（零发版）

```
站长改数据库 note_templates 表的 prompt / sections
    ↓
下次用户打开创建页 → 拉模板列表（缓存 1 小时）→ 拿到最新
    ↓
用户选该模板提交 → 后端用新 prompt 调 LLM → 新 sections 组装
    ↓
详情页按新 sections 渲染
    ↓
老笔记不受影响（它们的 structured_content 是创建时的快照）
```

### 5.3 向后兼容流程

```
老笔记（structured_content = null）
    ↓
详情页 → structured_sections 为空 → 走老渲染
    ↓
summary / key_points / tags 面板照常显示
    ↓
用户无感知
```

## 六、风险与对策

| 风险 | 对策 |
|---|---|
| LLM 漏掉某个 section 的 key | `build_structured_content` 跳过缺失 key，不报错；客户端跳过缺失区块 |
| LLM 返回的 JSON 格式和 sections 对不上 | `_parse_response` 已有容错；新增：对每个 section key 做类型校验（text 要 string，list 要 array），不合规则跳过该区块 |
| 模板 prompt 改坏了 | 改之前先备份旧 prompt（`updated_at` 有时间戳）；改完用测试文本跑一次看输出 |
| 客户端遇到不认识的 type | WXML 的 `wx:else` 兜底分支当 text 渲染，不会白屏 |
| 缓存导致用户看不到新模板 | 1 小时 TTL + 杀掉小程序重进时刷新；紧急更新可改 TTL 为 0 |
| 老笔记和新模板不兼容 | 老笔记 `structured_content` 为 null，走老渲染，完全隔离 |
| 模板 prompt 泄露 | `GET /api/templates/` 不返回 prompt 字段，只返回 name/description/icon/sections |
| 数据库迁移失败 | `ALTER TABLE ADD COLUMN` 加 nullable 列在 SQLite 上是原子操作，不会丢数据 |

## 十一、与配色与界面统一规范的对接（2026-10-04 补）

规范文档：`docs/配色与界面统一方案-四套莫兰迪.md`。这一节只写**两份文档打架的地方**和**开工顺序**，不复述规范内容。

### 11.1 本方案里必须改的 5 处（照原文位置）

| # | 位置 | 问题 | 改法 |
|---|---|---|---|
| 1 | §4.2.2 那段 `create.wxss` 样式里的 `background: var(--bg-accent-soft)` | **这个令牌不存在**，现网只有 `--accent-soft`；写上去等于没写，选中的模板 chip 不会有底色 | 用 `--btn-bg` + `--btn-ink`（选中态＝主按钮那一档） |
| 2 | 同一段的 `font-size: 26rpx` / `border-radius: 32rpx` / `border: 2rpx solid var(--border)` | 三处都是档位外的裸值，且现网描边写法是 `--w-edge` + `inset box-shadow` | `--fs-meta`(24) / `--r-chip`(28) / `box-shadow: inset 0 0 0 var(--w-edge) var(--card-edge)` |
| 3 | §4.2.3 详情动态区块的 `quote` 渲染 | 左竖线颜色没指定来源 | 竖线 `--card-edge`、引文 `--text-secondary`，不新起色号 |
| 4 | §4.2.3 的 `link` 渲染 | 现网详情页那支链接色 `#3F52D6` 是**旧雾蓝主题的 accent**，正被规范撤掉 | 链接 = `--text-primary` + 下划线，**不许把这支蓝抄进新组件** |
| 5 | §2.3 / §4.2.3 的区块 `label`（"摘要""核心观点"） | 字号/字色没指定，会和老笔记的摘要面板长得不一样 | `--fs-label`(20) + `--text-tertiary`，正文 `--fs-body` + `--text-primary`，与详情页 `.ds-*` 同一套 |

### 11.2 开工顺序（只有一处是硬的）

```
配色 P0（令牌层） → 配色 P1/P2（清写死 + 字号遮罩）
   → 模板 P0/P1（建表 + 后端路由 + LLM 链路）   ← 这两步与配色无冲突，可并行先做
   → 模板 P2/P3（chip 选择条 + 详情动态渲染）   ← 必须排在配色 P1/P2 之后
   → 配色 P3（壁纸 6→4 并档） → 模板 P4（预置数据）
```

硬的只有中间那一条：**模板 P2/P3 是这次唯一新增界面组件的两步**。规范先落地，它们照着令牌写；反过来就是先造 5 处新违例、再跟 P1 一起返工。

### 11.3 一条约定：模板不带颜色

`sections[].type` 只决定**形状**（text / list / tags / quote / link / table），颜色一律来自当前主题的四个令牌（`--bg-card` / `--text-primary` / `--text-secondary` / `--card-edge`）。**模板 JSON 里不许出现任何色值字段**——出现一次，就意味着以后每加一枚壁纸都要重画一遍这个模板。

海报那 6 套风格色（`utils/palette.js` 的 `POSTER_SCHEMES`）是另一条线，不受壁纸影响，也不许反过来影响界面。§十"不做海报适配"这条保持不变。
