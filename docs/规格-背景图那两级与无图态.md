# 规格 · 背景图那两级与无图态

一句话口径：头部那一张**只有两级**，两级都空就是**没有图**（白底那一档），包里不再有任何硬编码默认图。
依据：站长 10-13 拍甲的加强版（§8.231）——「后台图片肯定要优先」＋「如果是之前的背景图写到代码，硬编码就要删除。只提供白色背景」。
10-14 落码，随 2.1.15 出包（§8.234 末尾那条改记）。

## 1. 取图口只有一处，只有两级

`miniprogram/utils/poster.js` 的 `homeBg()`：

| 级 | 来源 | 落在哪 |
| --- | --- | --- |
| 第一级 | 他自己在「我的 → 卡片模板」四个位置里勾了「背景」的那一格 | `poster_profile` 那一份的本机文件 |
| 第二级 | 运营后台下发、已经落到本机的那一张 | `MP_ASSET_KEY_home_bg` 那一格指的文件；**这一级必须验文件真在**：账对不上文件就连账一起撤（`serverBgPath()`）。只回 null 不够——`pull()` 判 `content_hash` 相等就 `continue`，留着半截账这台机永远不会再补下那一张；而发一个不存在的非空路径更糟：`has-bg` 会点亮，图上那一整套纸白字压在浅壁纸上＝看不见 |
| — | 两级都没有 ⇒ **返回空串** | 屏上没有 `<image>`、没有压暗罩 |

三条不许：

1. **不许有第三级兜底。** 原来末尾那一档是包内 `/assets/home-bg-portrait.jpg`（314,793 B）——新用户冷启首帧必先解它，运营图落地后又没有一处重绘当前屏，这就是他报的"连续 load 两张背景图"。文件已删（留档在 `docs/design/留档-背景图-20261013/`，历史效果图还引它，那 9 份不追改）。
2. **第一级不许被服务端盖掉。** 「后台优先」这句打的是第二级与（已删的）第三级之间；他自己勾的那一张永远是第一级。
3. **白底不是一种壁纸。** 它是"没有图"那一档，不许进四套莫兰迪的体系、不许给它加圆角和色块（§8.231 负面清单⑤）。

## 2. 无图态屏上长什么样（这是新常态，不是边角）

| 项 | 无图态的产物 | 为什么 |
| --- | --- | --- |
| 头部那张 `<image>` | **一个都不渲染** | `wx:if="{{bgSrc}}"` |
| 新建页压暗罩 `.page-scrim`／「我的」`.head-scrim` | 都不渲染 | 同一条 `wx:if` |
| 新建页那一行「换背景」 | **照旧画着**（只剩右半截，左半截「调亮度」不画） | 站长 10-14 原话「白底也要换背景，这是核心功能」（§8.235）。行本身不再看 `bgSrc` 的脸色；「调亮度」仍看着——它拧的就是上面那层不渲染的罩子，留着是一枚死钮。**这一半是我自己定的，他没提过** |
| 那一行的字与箭头 | 吃 `var(--text-secondary)`（墨，跟着壁纸走），**不再是那两支写死的纸白** | 白底那一档背后是壁纸自己的浅底色，纸白压上去实测只有 1.14～1.20＝看不见。与同屏那行 Tips 同一枚令牌 |
| 容器类名 | 有 `theme-*`，**没有 `has-bg`** | 没有 has-bg ⇒ 所有翻色规则吃不到，屏上就是基样式那一套**墨字** |
| `bgLight` / `bgLightLow` | 显式归置成 `false`（`utils/imgBrightness.js` 的 `if (!src)` 那一支） | 不许靠探针那条 `p === null ? false` 的巧合 |
| 导航条 | `app.applyNavForBand` 第一句 `if (!hasBg) return`，整条不碰 ⇒ 落回 `app.json` 的 `#f4f2ec` ＋ 黑字 | 与四套浅壁纸同档 |
| 页头那一列「笔记」 | 照实算 | 与背景图无关，只是同一屏 |

`.home-swap` 那个盒子（88rpx 高、`margin: -14rpx 0 -22rpx`）两态**一个字都没改**，所以少半截不改流内高度，
下面录入条那一组不漂——实测白底档 `行 64..109｜组顶 470`，铺图档同一枚行也是 `64..109`。
