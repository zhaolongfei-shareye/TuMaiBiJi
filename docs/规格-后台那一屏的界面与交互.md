## 三、五条要说清的口径

**① 「两下」只有一条判据：改线上用户看到的东西。** 发布（图片／Tips／帮助文档／刷存量）、停用、上架／下架、拉黑、
历史那一格（点一张就把那张发出去）——这些先染橙、写明「再点一次=…」，六秒不点第二下自己撤回去。
**保存（模板那四格元数据）与上传仍是一下**：改错了再存一次就回来，两下只会添麻烦。这一条我钉进了判据（`arm(btnSave` / `arm(btnUp` 不许存在）。

**② 33px 那条溢出是旧写法本来就有的，不是我引入的。** 现网前一遍量到 0px，是因为那一栏当时只有 ≤3 条历史；
本机灌到 4 条它就伸出来了（4×90px＋3×10px 间距正正超过 390 的内容宽）。
**③ 每一枚历史缩略图定宽 90px 这条是我加的**，理由不是省地方：那句「再点一次」和长备注都比 72px 的图宽，
不设宽的话点一下染橙就把相邻那几枚顶得往右跳，六秒后自动撤时再跳回来——**屏抖**。同理那句确认话术改成常驻一行、只用 `visibility` 换，
跟 `hidden` 类说再见（判据钉死了 `ask.classList` 不许再出现）。

**④ 桌面那一档 1440 上还有 20 枚 30–32px 的可点，我没抬。** 前读数那一格写的是「3 枚」，**不是变好了、是统计的人群变了**：
旧写法里左栏那 14 条是 `<s>`，不被这把尺子当按钮数；改真 `button` 之后它们进了同一排读数。
过没过线：WCAG 2.5.8（AA）要求的最小目标是 **24×24 CSS px**，30–32px 已过；44px 那条下限我只在 ≤720px 那一档抬（移动档量到的实测数是 14 枚写口按钮全 **44px**）。

**⑤ 落点那一条读的是"顶在不在视口上沿"，两种情况要分开念**：`顶 394px` 是文档已经滚到底、那张卡抬不上去了（卡就在屏上，不是没到）；
`顶 892px` 才是真没落到。尺子里那个 `到底` 字段就是为这一句加的（`前-量数.txt` 里 11 条「没落到那一栏」，`后-量数.txt` 里 **0 条**）。

### 落成两刀

**第一刀（一栏一屏）**：`focusKey(key)` 扫 `#main .card[data-key]`，只把**带左栏 key 的那几张**（`NAVKEYS` 那份名单）
藏到只剩点中的那一张；左栏点击走 `showKey()`＝藏卡＋挪高亮，再 `window.scrollTo(0, 0)`。
跟着撤掉的是一整套滚动定位／滚动跟随（`spyNav`／`navLock`／`VIEWS`／`scroll` 监听／`scrollIntoView`）——
一栏只剩一张卡之后没有"滚到那一张"这回事，而跟随留着只会跟刚点那一条抢高亮（第一轮撞过）。
三处补藏卡：`render()`、`renderStats()`、`renderTemplates()` 末尾各一次 `repaintFocus()`，
因为卡片是每次重画新建的，`hidden` 不会自己长回来。
两处兜底（都是我自己定的，他没拍过，但少一处就是屏上事故）：那一张卡这一栏没有时**不藏其余的**（整栏摊着），
以及 `showView()` 发现手上那把 key 不属于这一栏时退回该栏第一条——不兜的话顶部那枚「图麦笔记」
回来是一片空白（`swSelf` 只调 `showView('stats')`，走的正是这条路）。

**第二刀（模板栏折叠）**：`tplCard` 的预览＋状态＋那四个输入框＋回执＋按钮＋配方一起搬进 `div.tplbody`，
标题行挂一枚「展开这一套／收起这一套」（带 `aria-expanded`），`TPL_OPEN` 保证**一次只开一套**（两套并排会把彼此顶出屏）。
只翻 `hidden`、不重建卡片——重建会把刚打没保存的那四格换掉。保存／上架之后那句回执落在折叠体里，
所以 `renderTemplates(flash)` 会把回执那一行**自动展开**，不然症状是"点下去什么回执都没有"。
预览**点开才画**（`box._painted` 那层守卫）：折叠态把二十套配方各跑一遍是白干。
模板行带的是 `data-id` 不带 `data-key`，所以第一刀扫不到它们，二十行不会被一起藏掉。
