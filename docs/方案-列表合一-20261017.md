## 2. 现网这一屏到底是什么（核过代码，不是印象）

`pages/index` 一屏里挂着**两批屏**，靠 `.vtabs` 那两枚 tab 切：

| | 笔记列表（默认） | 笔记卡片 |
| --- | --- | --- |
| 屏上结构 | 日期列 ＋ 标题 ＋ 三行摘要 ＋「显示更多」 | 两列等宽格子，只画本机台账里有图的那几篇 |
| 数据 | `rows`（`index.js:346` 的 `arrange()`） | `cells`（同一次 `arrange()` 里筛出来的，`index.js:363`） |

**两批屏共用同一份序、同一份筛选结果**（`arrange()` 一次算完，切 tab 只是换画法）。
所以"合一"在数据这一层几乎不做加法，要动的只有：撤掉第二枚 tab、行里撤摘要与「显示更多」、行右端补两样东西。

上半那一段（书法位图 ＋ 右上角一列数字 ＋ 一枚裸搜索 icon ＋ 圆角卡往上盖 20px）**不在这一刀的范围内，一个字不动**。

## 4. 三处数据代价（这一节是"研究"的主要结论，每条都回代码里核过）

### ① 右侧那枚配图：**列表接口今天不带图**，这是这一刀唯一真正的后端活

- 现状：`GET /api/notes/` 的响应模型是 `NoteListItem`（`backend/app/api/routes/notes.py:110`），
  只比详情多两栏：`has_active_share`、`share_author_name`。**没有任何一栏指向配图。**
- 配图存在另一张表：`assets`（`backend/app/models/asset.py`），`note_id` 可空（B 链先传后 bind），
  `object_key` 就是云开发 fileID，一篇最多 9 张（`MAX_ASSETS_PER_NOTE`）。
- 客户端今天只有一种取图口：`api.getNoteAssets(id)`（`utils/api.js:229`）——**逐篇一次请求**。
  列表一页 20 篇 ⇒ 20 个来回。这条路能走但不该走。
- **推荐走法（甲）**：照 `_attach_share_marks` 那个先例，加一栏 `cover_file_id`，
  一次 `IN` 查完这一页（`routes/notes.py:156` 的注释就是为这件事写的："一次 IN 查完，不逐篇查：
  一页 20 篇各自查一次，首页拉一次就是 20 个来回"）。取"最早那一张"当首图，
  并且**必须过 `not_failed()`**——`backup_status='failed'` 的行云上根本没有对象，
  拿它当缩略图就是一张碎图；历史遗留的 NULL 要一起算进来（那个函数头把这条坑写得很清楚）。
  代价：后端一条路由 ＋ 一个 schema 字段 ＋ 一次部署；客户端零新增请求。
- **另一条（乙）**：`notes.cover_asset_id` 那一栏外键今天**没有任何一处读它或写它**
  （全仓 grep 只命中列声明 `models/note.py:31`、那条外键的迁移、和 `asset.py` 里一句"从没赋过值"的注释）。
  要走这一栏就得先决定"谁在什么时候赋它"，那是第二条链路的活，比甲贵，收益只有"用户可以自己指定封面"——他没提过要这个。
- ⚠ 这一条要他点头才动：它**要改后端、要上一趟现网**。

### ② 「生成过卡片」那枚小标：**零新增请求**

- `utils/cardCloud.js` 今天已经拉一次全量：`refresh()` → `GET /api/user/cards` → `{cards, need_confirm, snapshots}`，
  谓词收在 `cellFor(noteId)`／`hasCard(noteId)` 一个出处（`cardCloud.js:178/197`）。
  卡片那一屏的 `cells` 就是问它筛的。
- 所以合一之后那一枚小标读的是**内存里已经有的一份名单**，一行代码的事，不加请求、不加表、不加部署。
- 顺带一条好消息：`cellFor` 返回的那一份里带 `cloud` URL ⇒ 将来若想把小标画成"那张卡片自己的缩略图"，
  数据已经在手，不用另开口。

### ③ 私密那一行不许画配图 —— 这是闸，不是装饰

- 现网列表那一趟在锁着的时候**不是"裁掉几栏"，是按白名单重建那几行**：
  `row = {f: getattr(n, f) for f in NOTE_BRIEF_FIELDS}`（`routes/notes.py:249`），
  而 `NOTE_BRIEF_FIELDS`（`app/core/private_access.py:43`）只有九栏：
  `id, title, summary, tags, source_type, source_url, category_id, is_pinned, created_at` —— 没有任何一栏指向图。
- ⇒ 好消息：`cover_file_id` **只要不写进 `NOTE_BRIEF_FIELDS`，私密那几行天然拿不到它**，
  这一闸是"默认关"的那种，比"记得去裁"安全。
- ⚠ 但有一处会埋雷：`_attach_share_marks` 挂在 `if not locked: return notes` **之前**，
  它自己的注释写着"挂在这一步而不是最后一步：两支出门都得带着这两样"。
  照同一个位置挂封面查询，就会连私密那几行一起算进封面（多查一批 assets），
  白名单会替我们挡在门外，**但这条必须钉一条用例证明挡得住**——
  否则哪天有人图省事把 `cover_file_id` 加进 `NOTE_BRIEF_FIELDS`，图上就漏了。
  `private_access.py:39` 那句"两份清单都按'少列一个字段就等于那个字段照给'来对待"讲的就是这件事。
- 界面上同一件事：私密那一行右侧一律不画（效果图第四屏那一格画了一枚锁、没有图）。
  一张照片里可能正写着密码、脸、票据；没解锁先把内容露一角，与正文那把闸不同罪同等。

### 9.2 ⚠ 炸出来的硬伤：上一版那两档字号**一个字都没上屏**

量第一遍就发现现网对照那一格分类行算出来是 **16px**，不是 24rpx 的 12px。根因不在我改的那两档，在更下面一层：

- 生成器把令牌**原样**塞进 `:root`（`--fs-body:28rpx`）。rpx 在 Chrome 不是合法长度 ⇒
  `font-size:var(--fs-body)` 摊开成 `font-size:28rpx` 属于 **invalid-at-computed-value**，整条声明静默作废、
  退回继承值。字号三档（来源／标题／分类／日期／摘要）实际全是 16px，两条 `box-shadow`
  （`--sh-lift`／`--sh-drop` 里带 `-12rpx 28rpx`）同理静默变 `none`。
- 所以**他这句"来源的字体太大"是完全准确的实测**：上一版稿子里来源与标题本来就一样大，
  我以为"已经小一档"只是我读源码读出来的，不是屏上的。
- 这类红不出来：出图守卫只量"溢出容器 >8px"和"外部资源没画上"，量不到"字号退回继承值"。

补的两道（都在 `docs/工具/出-列表合一效果图.js`）：
1. 令牌进 `:root` 前一律过 `pxize()`（值里每个 `Nrpx` 换成 `N/2 px`），注释里的 rpx 不算；
2. 出 HTML 前扫 `<style>` 的**声明**，只要还有一个 `rpx` 就抛 —— 反向钉过：把一处 `pxize()` 抽掉，
   守卫当场红（`CSS 里还有 1 种 rpx 值没换成 px（28rpx）`），抽完用 Edit 还原，没走 git。
3. 新增探针 `docs/工具/验-字号档位与对比.js`：逐屏比"令牌值／2 是否等于屏上算出来的 px"，
   不等就点名哪一格 —— 这一版九屏全过（实测：分类 10.5px／来源 9px／标题 14px／现网对照分类 12px）。
4. **同类错查过，没有第二处**：`docs/工具/出-*` 全扫了一遍，只有这一份把令牌原样写进 `:root`；
   另外两份里的 rpx 只出现在注释与说明文字里（`出-首屏顶部改版.js` 本来就按 `S = 0.4` 换算过），不是同一个病。
