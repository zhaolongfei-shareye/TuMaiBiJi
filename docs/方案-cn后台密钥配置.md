# 方案与规格：.cn 后台密钥配置（凭据不发版、不重启换一把）

落码日期 2026-10-25。这一份写的是**现在长什么样**，不是计划；计划部分只在最后一节留着没做的格子。

## 一、需求原文对照

站长 10-24 两句，第二句是对第一句的更正：

| 原话 | 落在哪 |
| --- | --- |
| 「密钥配置功能请加到cn的官网后台，我自己去加」 | `/ops` 那一页新增一节「密钥配置」；值由他自己在页面上填，我们不接触原值 |
| 「配置功能放错地方了，你放在图麦克，应该放在图麦笔记下面进行配置」 | 实现位置 = 图麦笔记后端 `backend/`（`api.agentsbin.cn/wtsj/ops`）；图麦克那一处（`AgentsWatermark/cloud/image-service`）要撤，撤现网等他点头 |

第一句里那句"我自己去加"决定了这一节的核心判据：**页面上不允许出现任何需要我们把密钥值交给他
或他把值交给我们对话的环节**。值只在他浏览器 → HTTPS → 服务端 → SQLite 这一条线上走一次。

## 二、现在长什么样（口径）

- 一张表 `service_secrets`：`name`（主键，规范化成大写）/ `value`（明文）/ `note` / `created_at` / `updated_at`。
  没有历史行——改一次覆盖一次，历史上只留最后一次的时间。迁移 `e7b3a9c1d482` 建表，**一行都不预建**。
- 三个口，全在 `admin_access` 那把独立的钥匙后面（`/api/admin/secrets` GET、`/api/admin/secrets/{name}` PUT、DELETE）：
  口令没配一律 503，不是 401，也不是放行（与运营图那四个口同一条纪律）。
- 读侧唯一的覆盖点：`app/services/service_secrets.py:resolve(name, fallback)`。库里那一行优先，
  查不到 / 那一行是空的 / 读库抛异常 → 三种都回 `fallback`，也就是调用方从 `settings`（`.env`）拿的那一份。
- 今天真被 `resolve()` 读的三个消费者（两处微信凭据必须一起改，否则"登录用新钥匙、取 token 用旧的那把"）：
  - `app/services/wechat.py:_token_body` —— `WECHAT_APP_SECRET`
  - `app/core/auth.py:_wechat_code2session` —— `WECHAT_APP_SECRET`
  - `app/services/llm.py:_call_hunyuan_cloud_function` —— `HUNYUAN_CF_KEY`
  名单在 `service_secrets.CONSUMED_NAMES`，且有一条用例把"名单"与"源码里真出现过的 `resolve('…')` 字面量"
  做双向相等判定——名单与消费者谁先跑偏，用例就红。
- 界面上每一条给三样能确认"刚那一趟真存进去了、存的是不是同一把"的东西：长度、sha256 前 8 位、更新时间（本地那天，
  不是切 UTC 串），加一句"生效值从哪一层来"和"删掉会回到哪一层"。
  还没代码在读的名字，界面直接补一句「还没有代码读这个名字」，不假装生效。

## 三、三条锚点（缺一条这一节就不能上现网）

1. **值只进不出。** `describe()` 交出去的是长度与指纹，接口回体里没有 `value` 这个键，
   所以"忘了删敏感字段"这类坏法从源头上不成立。日志同样只打 `name / 长度 / 指纹`。
2. **库里只是覆盖层，不是第二套配置系统。** 只有 `CONSUMED_NAMES` 里点名的那几个名字真有读法；
   删一行 = 当场回到 `.env`。这一条是"撤回一次改动不需要知道旧值"的落地，也是它敢上现网的前提。
3. **读侧不许抛。** `resolve()` 里那一句 `except Exception` 不是装饰：表还没建（迁移没跑）、库被锁、
   连接打满，三种情况都只该有一个结果——照旧用 `.env`。它挂在登录那条链上，坏了不能变成登录 500。

## 四、负面清单（这一版明确不做，每条附依据）

- **不做多管理员、不做审计流水。** 现网这把钥匙只有站长一个人（`admin_access.py` 文件头：多管理员在
  运营图方案的负面清单第 4 条，今天不建）。所以没有 `updated_by` 这一栏。
- **不做值加密存放。** `.env` 里也是明文，这台机器上没有任何一层加密能假装保护它；真做了只会让
  "读侧不许抛"那条多一个失败面（密钥环挂了 = 全线退回空值）。
- **不做值的回显、复制、导出。** 一旦能回显，就多出页面、浏览器历史、截图三条外流路径。
  换错了只能重新粘贴覆盖，这是刻意的。
- **不做"启动时打印当前覆盖了哪几个名字"。** 现网 `deploy.sh` 今天不打印配置，加这一句要单独议；
  界面上那一句"生效值从哪一层来"是目前唯一的可见处。
- **不做 `.env` 里没有的键的自动注册**（例如 `DEEPSEEK_API_KEY`）：存进去只是躺在库里，等代码接上同名读法。
  界面已经会把这一格说出来。

## 五、这一趟的证据（10-25 实跑，不是推断）

- 用例：`backend/tests/test_service_secrets.py` 39 条；整套后端 878 条，0 失败。
- 三把反向探针（改坏源码看用例抓不抓得住），逐条跑过：
  - 往 `describe()` 里加回 `value` → 红 1 条（「值不在回体里」）。
  - 让 `resolve()` 无条件回 `fallback` → 红 5 条（三个消费者、空白剥离、删行回到 .env）。
  - 去掉名字那一句 `.upper()` → 红 1 条（「库里只有一行」）。
  三条探针全部还原后再跑一遍全绿。
- 浏览器真点：本机起服务（临时库 + 迁移建表）→ 登录 → 用小写名保存一把 → 界面回显
  `DEEPSEEK_API_KEY　长度 25 字　指纹 …`，值输入框已清空；点删除走 `confirm`，
  桩成"取消"那一趟行仍在、桩成"确认"那一趟行消失且服务端 `service_secrets` 表剩 0 行；
  访问日志与服务日志里搜哨兵值 0 次命中。
- 迁移真跑：`alembic upgrade head` 到临时库 → `service_secrets` 五栏齐、0 行、`PRIMARY KEY(name)`。

## 六、部署与回退

- 部署跟着 `backend/deploy.sh` 走（先备份演练 → `alembic upgrade head` → 重启 → 健康检查），
  这一节的迁移在 head 上，`deploy.sh` 不用改。
- **空表 = 现网行为一行不变**：三条消费者在没有覆盖行时读到的就是 `.env` 那一份，
  这是第五节那条迁移用例后半句钉的东西。
- 回退有两条，都不动用户数据：
  1. 只撤某一把 → 后台点删除（回到 `.env`），或 `delete from service_secrets where name='…'`。
  2. 撤整节 → 回退代码 + `alembic downgrade -1`（删表）。⚠ 如果有人已经改成"只用后台管凭据、
     `.env` 里留的是旧值"，删表那一刻线上会退回旧值——先核 `.env` 再 downgrade。
