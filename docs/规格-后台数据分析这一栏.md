# 规格：`/wtsj/ops` 里这一栏"数据分析"

> 口径来源：站长 10-15 三句话拼出来的——「这个上传背景图后台与之前 .cn 数据后台打通，登录一次就行了」→「`https://api.agentsbin.cn/wtsj/ops` 我指这个后台」→「**数据分析也是这个后台**」，末尾一句「你来」＝**指标集由我定**。
> 本文只定"看什么、每个数从哪来、今天算不算得出来、要付出什么代价"。**一行代码没写、没迁移、没部署。**
> 台账：PRD §8.247（指代与作废的那三条路）＋§8.248（本规格）。

---

## 1. 一句话结论

**这一栏不是"打通"，是"从零加一屏"**——同一扇本来就一次登录（一把 `ADMIN_TOKEN`），但库里今天没有任何统计接口，也没有任何行为数据。
好消息：**A 档十一枚指标一行新列都不用加，纯读现表就能出**；坏消息：**站长最想看的那三枚（提炼降级率、任务失败率、留存）今天算不出历史**，因为任务状态只在 Redis 活一小时、`jobs` 表是死的、用户没有活跃时间列。

## 3. A 档｜今天就能算，零迁移、零新列、零对外文本改动

口径都写在下面这栏里，因为**同一个数有两种算法**（比如"笔记数"含不含预置那篇），不写清就是给自己埋雷。

| # | 看什么 | 怎么算 | 必须写死的口径 |
|---|---|---|---|
| A1 | 用户总数 · 每日新增 | `users` 按 `created_at` | 注销重登会拿到新行（`generation`/`account_id` 在动），所以**按行计、别按人计**，界面话术用"账号数"不用"人数" |
| A2 | 笔记总数 · 每日新增（**剔除预置**） | `notes` 按 `created_at`，`source_type != 'preset'` | §8.232 那批"新用户默认给一篇"会让每个新用户自动 +1 ⇒ **不剔除，新增曲线就是用户数的影子，是个假数** |
| A3 | 来源分布 | `GROUP BY source_type`（六个取值） | 微信文章与网页要分开（`wechat_article`/`web_article`），这才看得出"公众号是不是主入口" |
| A4 | 分类分布 · 未分类占比 | `category_id IS NULL` 单列 | 私密那一格按 10-12 口径是**分类名判据**；**只许出计数，正文/标题/摘要一律不许进这一屏** |
| A5 | 卡片生成量 · **十套模板热度榜** | `note_card` 按 `tpl` | `no_qr` 单独一档（不带码那张是发外部平台的），`is_current` 用来区分"当前这张"与历史 |
| A6 | 建了多少分享 · 还活着多少 | `shares` 总数／`is_active`／`expires_at` 过期比 | 一篇一张码，所以"张数"≈"篇数"，别当 PV 用 |
| A7 | **转存量（裂变闭环唯一的硬证据）** | `notes.imported_from` 非空计数 | 这一枚直接对上"存内容 + 传得出去"那条对外叙事，**A 档里最该上的** |
| A8 | 邀请台账 · 奖励发放 | `invitations.reward` 求和，对 `users.quota_bonus` 求和 | **两个数必须相等**，不等就是账裂了——界面要把两个一起念，别只念一个 |
| A9 | 图片云备份健康度 | `assets.backup_status` 分布 | 待删队列那些是本机 storage，不在库里 ⇒ 这一栏只能证"上传侧"，不许写成"云端零孤儿" |
| A10 | 举报量 · 原因分布 · 已处置比 | `share_report` 按 `reason`、`hidden` | 这枚是"平台该不该管"的证据，参赛/审核场合能用 |
| A11 | 运营图当前状态 | 现成 `/api/admin/mp/state` | 已有口，白拿 |

## 4. B 档｜要加一列或接一处写点才算得出，且**历史从今天起、补不回来**

| # | 看什么 | 现在为什么算不出 | 要动什么 | 代价与不可逆点 |
|---|---|---|---|---|
| B1 | **提炼降级率**（真调到大模型 vs 只存了原文） | `degraded` 不落库（models/routes 零命中） | `notes` 加一列（`extract_status`：`ok`／`degraded`），在落库那一趟写 | 一次迁移＋三个入口各写一处；**上线之前的所有笔记无法回补**，只能从今天起算 |
| B2 | **任务失败率 · 各阶段耗时** | `jobs` 表是死表；Redis 一小时过期 | **把 `jobs` 接上电**（列已齐），在 `ingest_tasks` 三个入口的每次状态变更各写一行 | 零新表零迁移；但它会让 worker 每任务多几次写库；同样**历史从今天起** |
| B3 | DAU · 次日/7 日回访 | 没有 `last_active` | `/api/auth/wechat` 那一趟多写一次 `users.last_active_at` | 一次 UPDATE，成本可忽略；但**这是行为数据**，要先看第 5 节那条对外承诺 |
| B4 | 落地页被打开多少次（PV） | 库里零计数 | 甲：只读服务器 nginx access log（不入库）／乙：加一张计数表 | 甲零隐私代价但要 ssh；乙等于开始记"谁在什么时候开了哪个 token" ⇒ 进第 5 节 |
| B5 | 搜索行为（搜了什么、搜不到什么） | 完全没记 | 要么记查询词，要么不记 | **建议不做**：搜词是最容易出事的一类数据，收益却最低 |

## 5. C 档｜技术上做得到，但**先撞我们自己对外说过的话**

关于页 `PRIVACY` 十条（1.1.7 起逐条对过代码）与后台那份已生效的《用户隐私保护指引》里，都写着**"无埋点""不收集使用行为"**这一类话。B3／B4-乙／B5 任何一条落地，**这两处对外文本就得改，那是法律文本重交**（10-11 那次整份重交、逐格核对的代价在案）。所以顺序不能反：

**先决定要不要碰行为数据 → 要碰就先把两份文本改对 → 才允许写那行代码。**
不允许"先埋了再改话术"。

另外两条硬边界，跟文本无关、现在就生效：
- **私密笔记的正文、标题、摘要任何情况下不许出现在这一屏**（服务端那五道读旁路 B1/B2/B4/B5/B6 还**没部署**，所以现在更要把它写死在聚合层：只出计数）。
- 后台这一侧只有"全站视角"，**不许做跨用户画像**（"谁转存了谁的哪篇"这种能指到具体人的表，A7 只出总数）。

## 6. 我建议这一栏先上哪五枚（P0，全 A 档）

1. **A2 新增笔记（剔除预置）** ＋ **A3 来源分布**——产品到底有没有人被真正用起来。
2. **A7 转存量**——"存内容 + 卡片传出去"这条对外主张唯一的硬证据，也是"不限量＋邀请 +10"那条机制的回执。
3. **A5 模板热度榜**——十套模板哪几套没人用，直接决定要不要下架（这条不需要任何新数据就能改产品）。
4. **A8 邀请对账**——两个数不等就是账裂了，属于**发现问题**而不是看风景的那一类。
5. **A11 运营图状态**——白拿，且这一屏本来就是传背景图那一屏。

**这一批不加列、不迁移、不埋点、不改任何对外文本**，风险面只有"多几个只读聚合口"。B1／B2 我建议紧接着做（它们是"运维看得境"的那三枚，但历史从今天起，越早开工越值）；B3～B5 先不动，等第 5 节那条决定拍了再说。

## 7. 负面清单（这一栏里不许出现的东西）

- 不许写"实时"／"当前在线"——任务态只活一小时、没有活跃列，这两个词兑现不起。
- 不许把 **降级**（只是没提炼、原文还在）叫成 **失败**（采集没成），这是两件事，1.9.x 就把这条口径钉过。
- 不许把预置笔记算进新增内容（A2），也不许把 `is_current=false` 的历史卡片算进"模板使用量"（A5）。
- 不许给"分享张数"起名叫"浏览量"（一篇一张码，跟被打开几次无关）。
- 不许在这一屏展示任何用户输入过的搜索词、私密笔记正文、或能指到具体人的转存关系。
- 不许出现"找回""恢复"这类名字（技术上做不到的事不起这个名字）。
