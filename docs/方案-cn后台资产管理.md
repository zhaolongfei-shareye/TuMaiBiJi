## 二、现状硬事实（都带 文件:行号，2026-10-11 实读）

**默认背景图这一侧**

- 默认图是**包里的一个文件**：`miniprogram/assets/home-bg-portrait.jpg`（314KB，实存）。
- 路径写死在常量：`miniprogram/utils/poster.js:217` `HOME_BG_DEFAULT = '/assets/home-bg-portrait.jpg'`。
- 取图口只有一个：`poster.js:219-221` `homeBg()` = 用户自己那格（本机文件）`||` 包内这张。
- `poster.js:212-215` 的注释写明：WXSS 的 background-image 不认包内文件、只认 base64 与网络地址，所以第一屏是用 `<image>` 组件铺的（`pages/index/index.wxml:10`，值来自 `pages/index/index.js:151`）。
- `homeBg()` 的全部调用点：`pages/index/index.js:151、989`，`pages/create/create.js:199`，`pages/me/me.js:119`。**四处共用一个口**，所以改一处四处跟着变。

**已有的三条服务端下发通道，没有一条够得到"全站默认背景"**

- 名片四格上云 `miniprogram/utils/profileCloud.js`：权威在 `user_profiles` 那一行，客户端只认 slots／name／slogan／tpl／bg_dim，全是**每个人自己的**；本机四格空着时它不会塞图，直接落回包里那张。
- 卡片模板配方下发 `backend/app/api/routes/poster_templates.py:38-43`：只有一个 GET，需登录，回 `template_id/label/label_en/group_key/sort_order/min_app_version/content_hash/recipe`。**没有任何 HTTP 写接口**，而且 `poster_templates.py:3-4` 明写这是故意的：「这张表能改画面，所以它不该出现在任何 externally reachable 的写接口上」。配方里的 `emit k:'image'` 只认 `key`（avatar／qr）从本机预载位图取（`poster.js:695-696`），参数表里没有"给一个网络地址"这一项。
- 壁纸预设 `GET /api/user/wallpaper/options`（`backend/app/api/routes/user.py:62-64`）：回的只是**预设名清单**（四套莫兰迪），颜色值在包内 `utils/palette.js`；写口还拿包内名单校，不在名单里就回「壁纸不存在，请更新小程序后重试」（`user.py:55-56`）。这条连"换一张图"都表达不了。

**后台页面这一侧（要从零建）**

- 全仓库搜 `admin/backoffice/管理后台/is_admin`：**没有任何我方管理页面或路由**。
- 后端唯一的 HTML 出口是分享落地页与举报页：`backend/app/api/routes/landing.py:260-268`、`:271-385`（HTMLResponse，面向公众、无鉴权）。这是"后端直接吐一个网页"的现成先例。
- `backend/app/` 内搜 `StaticFiles|mount|FileResponse`：**没有**，后端今天不发任何静态文件。
- 他之前说"后台截图不要带地址栏（`?token=…`）"指的是 **微信官方控制台**（`docs/提审-2.1.8-提交材料.md:10`、`docs/产品需求.md:5386`，真实 href 是 `/wxamp/wacodepage/getcodepage?token=…`），不是我们的东西。
- 官网源码不在本仓库：agentsbin.cn 的 root 是服务器上的 `/var/www/agentsbin-cn`，nginx `try_files $uri $uri/ /index.html`（`deploy/公开落地页/上线步骤与回滚.md:6-8`、`nginx-agentsbin.cn.片段.conf:8-12`）；`/n/` 反代到 127.0.0.1:8000（同文件 `:27-43`）。API 走 `api.agentsbin.cn/wtsj`（`miniprogram/utils/api.js:3`）。
- 部署链路：`backend/upload.sh:38-44`（scp 到 `agentsbin:/home/ubuntu/wtsj-backend`）、`backend/deploy.sh:5`。

**上传与发图这一侧**

- 后端唯一的 multipart 入口：`backend/app/api/routes/ingest.py:183-239` `POST /api/ingest/screenshots/stage`。**字节不落盘**，存进程内存字典 `_batch_staging`（`ingest.py:25`），随后塞进 Redis 队列。限额已成体系：单图 10MB（`:120`）、单批 40MB（`:121`）、每用户 2 批（`:124`）、全局暂存 120MB（`:125`）、TTL 1800s（`:117`）、格式白名单 `_image_format`（`:132-146`）、过期清扫 `_sweep_stale_batches`（`:153-157`）。⇒ **限额与格式校验的写法可以直接抄这一份**，但"落盘持久保存"这件事今天不存在。
- 后端以 HTTP 回吐图片字节的现成端点：`GET /api/shares/{token}/qrcode`（`backend/app/api/routes/shares.py:263-293`），**免登录 + `@limiter.limit("60/minute")` + 按真实客户端 IP 分桶**（`:264-274` 那段注释写明 uvicorn 带 `--proxy-headers`、nginx 传 `X-Forwarded-For` 都已实测），媒体类型按文件头判（`:290-293`）。⇒ 这是"后端发公网图片 URL"的既有先例，连限流与判型都能照抄。
- 用户图片资产走微信云开发，不经后端磁盘：`miniprogram/utils/cloudUpload.js:64`（`wx.cloud.uploadFile`），后端只存 file_id（`assets.py:196`）。

**鉴权这一侧**

- 小程序侧：微信 code2session（`backend/app/core/auth.py:75-102`）换 JWT HS256，密钥 `settings.JWT_SECRET_KEY` 来自服务器 `.env`（`core/config.py:51-53`，占位符会拒启 `:63-65`），7 天有效，校验在 `auth.py:105-128`。
- **没有** is_admin 列（`backend/app/models/user.py:21-48` 全列可见）、没有管理员 API key、没有 HTTP Basic。唯一"另一种凭证"是私密笔记那把 15 分钟 scoped 解锁 token（`core/private_access.py`），而且登录口明确拒收带 scope 的 token（`auth.py:58-64`）。⇒ **管理页鉴权要从零建，且不能复用小程序那套。**

**网络图这一侧（这条决定方案成立与否）**

- 合法域名三栏**已配齐**：`request` / `uploadFile` / `downloadFile` 均为 `https://api.agentsbin.cn`（`docs/产品需求.md:553` R8 条，2026-09-20 后台实查闭合；同文件 `:849` 重申这三栏是分开配的）。
- 已被本仓库实测走通的网络图路线是「**先 downloadFile 再进画布**」：`wx.downloadFile(api.getShareQRCodeUrl(token))`（`pages/share/share.js:116-127`、`pages/index/index.js:731-740`；URL 构造 `utils/api.js:257`）→ `poster.loadImage` 用 `canvas.createImage()` 解码（`poster.js:438-455`，createImage 在 `:441`）。
- **没找到**把 https URL 直接塞给 `<image src>` 或 `createImage` 的代码 ⇒ 那一条在本仓库**无先例、未实测**，本方案不拿它赌。
- 云开发图片域名需另加 downloadFile 白名单（`docs/2.0-挂起进度.md:51、60`）⇒ **用云开发桶存这些图，就等于要改小程序后台配置，而改配置的生效路径与发版绑在一起**，这条直接把"云开发桶"这个选项判死（见锚点 A3）。

## 三、现在必须钉死的锚点（防止走到一半推倒重来）

**A1 「没登记过」与「登记成停用」必须是两个值。**
一张 `mp_assets` 按内容哈希记账（谁传的、多大、多宽、什么格式、哪个文件），另一张 `mp_settings` 记 `kind → 当前生效的 asset_id`，**可以为空，空就是"用包里那张"**，且"空"要显式写出来，不能靠"没这一行"表达。
依据：同一个坑在名片那条链上踩过并且造成过不可逆删图——`utils/profileCloud.js:13-15、111-117` 那段注释写着「"云上没这一行"≠"云上四格都是空的"」，10-11 审计严重①就是只认 `updated_at` 导致半行被当成"用户清空了"。这一格从第一天就分两个值，将来加灰度、加排期都不用迁表。

**A2 图片只走一个发图端点、一个不可枚举路径。**
形如 `GET /api/mp/a/{token}`，token 是随机串不是自增 id；免登录，所以必须挂限流。
依据：对外用 token 不用自增 ID 是这个项目已有的口径（分享那条链）；免登录发图的限流与 IP 分桶写法直接抄 `shares.py:263-293`。

**A3 图片 URL 的域名只能是 `https://api.agentsbin.cn`，这一条不许商量。**
理由：`downloadFile` 白名单里今天只有这一个域名（`docs/产品需求.md:553`）。**换成任何别的域名（包括微信云开发桶的公网 CDN 域名），客户端 downloadFile 就会被拦，而加白名单这件事本身要跟一次发版**——那就把"不发版换图"这个目标自己废掉了。所以存储选型必须服从这一条，不是反过来。

**A4 客户端取图走 downloadFile → 本机缓存，缓存文件按 content_hash 命名。**
不选 `<image src="https://…">` 直吃，因为那一条本仓库无先例未实测（见第二节末段），而 downloadFile 这一条已被小程序码链路跑通。
按哈希命名而不是固定名：`<image>` 与 `canvas.createImage()` 都按**路径字符串**缓存位图，同名换内容会照画第一张——这条坑已经踩过并记在案（`poster.js:54-56` 的注释就是为它写的）。

**A5 `homeBg()` 的三级回退顺序钉死，且全程不抛、不出声。**
用户自己那格 > 下发的默认（本机缓存有且哈希对得上）> 包里那张。任何一级读不到就静默落下一级，不许弹提示、不许把主流程带回错误。
依据：`profileCloud.js:9` 那条纪律（「名片是附属品，读不到就维持本机那一份」）；背景图同理，它坏了顶多是"没换过来"，不该让用户看见报错。

**A6 提审期冻结闸从第一天就带上。**
一个环境闸（形如 `MP_ASSETS_FREEZE=1`）让下发端点回"无下发"，客户端自然落回包里那张。
依据：模板那条链已有同型闸门先例（`POSTER_TEMPLATES=1`，`backend/deploy.sh:246-284`）；而"审核时看到的首页与上线后不一致"是合规风险，不是技术风险，只能用纪律堵。

**A7 管理页鉴权与用户体系完全隔离。**
独立 `ADMIN_TOKEN`（`.env` 里的长随机串，可轮换），不进 users 表、不加 is_admin 列、不复用小程序 JWT。
依据：`models/user.py:21-48` 没有角色列，加一列就把"运营凭证"和"用户身份"永久绑在一起；而 token 可以随时换，泄露了也只影响这一个页面。凭据交付按老规矩走剪贴板（pbcopy／pbpaste），不进对话、不进 argv，换完拿旧值打一次接口证明已吊销。

**A8 模板那一栏的边界：只能改数据，不能"上传一张图就变成一套新模板"。**
后台能改的是 status（draft／live／archived）、sort_order、label／label_en、min_app_version；配方 JSON 本体仍走"种子文件 + 静态校验 + 模拟器出图"那套工具（`docs/工具/跑新模板流程.sh`，规范正本在 `docs/产品需求.md §11`）。
依据：配方是矢量画法数据（`miniprogram/utils/posterRecipes.js`），官方微信禁止下发 JS 解释器式的代码热更新，所以"新画法"永远要发版，能数据化的只有配方本身——这一条已经在 10-07 那轮验证过并写进规范。

## 四、分阶段（每段独立可验收、可回滚，前一段不等后一段）

### P0-a 后端 + 后台页（不碰客户端，可以先上现网）

要做的：

1. 两张新表 `mp_assets`、`mp_settings` + alembic 迁移（不动任何现有表）。
2. 上传端点（multipart）：落服务器磁盘 `var/mp-assets/`，限额与格式校验照抄 `ingest.py:117-146` 那一套写法（单张字节上限、格式白名单、超限即 400 并给可读文案）。
3. 发图端点 `GET /api/mp/a/{token}`：免登录 + 限流 + 按文件头判媒体类型（照抄 `shares.py:263-293`）。
4. 下发端点 `GET /api/mp/config`：需登录，回 `{ home_bg: { url, content_hash, updated_at } }`；冻结闸打开时回空（锚点 A6）。
5. 管理页：后端直接吐一个单页 HTML（先例 `landing.py:260-268`），原生 HTML+JS 零构建，路径挂在 API 同一个前缀下（预计 `https://api.agentsbin.cn/wtsj/ops`，**这个路径要实测一次 nginx 是否照转**）。功能：登录、上传、预览、发布、停用（回到包内那张）、历史与一键回滚。
6. `ADMIN_TOKEN` 鉴权 + 登录失败限流。
7. 判据：pytest 用例（上传／发图／下发／冻结闸／鉴权拒绝）+ 现网探针（只读，不写现网数据）。

验收（一条一条能跑）：后台上传一张图 → 页面显示出图 → `curl` 那个 URL 拿到同样字节 → 打开冻结闸后 `GET /api/mp/config` 回空 → 用错 token 打管理接口一律 401/403。

回滚：删掉新路由即可；两张表是新增的，现有表一行没动。

**副作用声明（按"副作用为准，不以名字为准"那条规矩）**：这一段上现网之后，**现网小程序的行为一行都不变**——客户端还没有读 `/api/mp/config` 的代码，新端点默认没人调，新表默认没人写。它是 inert 的。

### P0-b 客户端那一刀（跟 2.2 发版）

要做的：

1. 新增 `miniprogram/utils/remoteAssets.js`：读下发 → 比对本机缓存的哈希 → 不一样才 `wx.downloadFile` → adopt 成本机文件（沿用 `poster.adoptLocal`）→ 全程不抛。
2. `poster.js` 的 `homeBg()` 接上第三级回退（锚点 A5）。四个调用点自动跟着变，不用逐个改。
3. 启动那一趟挂上拉取，位置与 `profileCloud.pull()` 同一层，并且**不许阻塞首屏**（拉不到就先用包里那张，回来了下次冷启生效——这一条要不要做成"回来立刻刷"，见第八节 H 项）。
4. 判据三把：哈希没变不重下／拉不到静默落回包内那张／用户自己那格永远优先于下发默认。外加一次视觉自证（真机截图看头部那张确实换了）。

验收：真机装 2.2 → 后台换图 → 冷启一次 → 首页头部是新图；后台点停用 → 冷启 → 落回包里那张；用户自己在「我的 → 卡片模板」放过图的账号，两种情况下都还是他自己那张。

回滚：这一刀只加不改（`homeBg()` 多一级回退），把 `remoteAssets` 那个调用摘掉就回到今天的状态。

### P1 模板管理那一栏（做完之后，上下架模板不发版）

要做的：后台页第二栏，列出 `poster_templates`（live／draft／archived 三态）、改 sort_order、改中英文名、改 min_app_version、上下架、上传**后台自己看的**预览缩略图。

判据：后台改完 → `GET /api/poster/templates/` 的回体跟着变；旧版包按 `min_app_version` 自己筛（`poster_templates.py:7-8` 那条口径不动，服务器不按 query 筛，避免多出第二份会不同步的真相）。
