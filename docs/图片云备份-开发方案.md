#### 3.1.2 新增图片压缩工具（新建 `miniprogram/utils/imageCompress.js`）

```js
/**
 * 压缩图片：canvas 重绘 → JPEG 输出
 * @param {string} srcPath 原图 tempFilePath
 * @returns {Promise<{tempFilePath: string, width: number, height: number}>}
 *
 * 规则：
 * - 长边上限 1920px，短边等比缩放
 * - 初始 quality 0.7，输出 > 500KB 则降到 0.5 重试，再降 0.3
 * - 强制 JPEG（丢弃 alpha）
 * - 超过 3 次仍 > 500KB，用最后一次结果（宁可大一点也不丢图）
 */
```

**实现要点：**
1. 用 `wx.getImageInfo` 取原图宽高
2. 算缩放比：`scale = Math.min(1, 1920 / Math.max(w, h))`
3. 创建离屏 canvas（`wx.createOffscreenCanvas({ type: '2d', width: newW, height: newH })`）
4. `ctx.drawImage(img, 0, 0, newW, newH)`
5. `wx.canvasToTempFilePath({ fileType: 'jpg', quality: q })` 输出
6. 检查输出大小，超标降 quality 重试

**不选 `wx.compressImage` 的原因：** 它不能改尺寸，4000×3000 的截图压缩后仍可能 > 500KB。

#### 3.1.3 新增云上传工具（新建 `miniprogram/utils/cloudUpload.js`）

```js
/**
 * 上传压缩图到云存储
 * @param {string} compressedPath 压缩后的 tempFilePath
 * @param {string} userId 用户ID（用于路径隔离）
 * @returns {Promise<{fileID: string}>}
 *
 * 云存储路径规则：
 *   images/{userId}/{YYYYMMDD}/{随机UUID}.jpg

 * 失败策略：
 *   返回 null，不抛异常（上传失败不应阻断笔记创建主流程）
 */
```

#### 3.1.4 改造截图提交流程（改 `miniprogram/pages/create/create.js`）

**当前 `submitScreenshots()`（L430-458）改为：**

```
submitScreenshots():
  1. batch = this.data.previewImages.slice()   // 现有逻辑不变
  2. 并行启动两条链：
     A链（主流程，不变）：api.ingestScreenshots(batch) → pollTask → 跳转详情
     B链（新增，后台）：
       for img in batch:
         compressed = await compressImage(img)
         fileID = await cloudUpload(compressed, userId)
         if fileID: collectedFileIDs.push(fileID)
       // 笔记创建成功后，调后端接口把 fileIDs 关联到笔记
       await api.bindNoteAssets(noteId, collectedFileIDs)
  3. A链完成后拿到 note_id，B链如果也完成了就 bindNoteAssets
  4. B链如果还没完成：把 fileIDs 存到 wx.setStorage 的待绑定队列，
     下次进详情页时检查并补绑
```

**关键原则：** B链失败或慢不阻断主流程。笔记创建成功 = 文字已保存，图片备份是附加价值。

## 四、数据流（终态）

```
用户选图（wx.chooseMedia）
    ↓
    ├──→ 原图 → uploadFile → 后端内存 → OCR → LLM → Note 表（文字）

    └──→ 前端压缩（canvas → JPEG ≤ 500KB）

              ↓
         分享 → 小程序卡片 → 落地页读 assets → 展示图片
```

## 五、风险与对策

| 风险 | 对策 |
|------|------|
| 压缩后 OCR 识别率下降 | **OCR 仍用原图**，压缩图只用于存储展示，两条链独立 |
| 云开发 5GB 用完 | 后端 `GET /api/user/storage-quota` 查用量，前端 >90% 时提示 |
| 上传失败（弱网） | 离线队列 `imageQueue.js` + App.onShow 重试 + 手动重试按钮 |
| 云开发免费期到期（6个月） | 到期前评估，可升付费套餐（19.9元/月 50GB）或切 COS |
| 云存储图片被非授权访问 | 安全规则设「仅创建者可写」+ 分享场景用临时链接 |
| 分享落地页（H5）无法直接用 fileID | 当前分享走小程序卡片，fileID 在小程序内可用；H5 场景后续再加 |
| 图片压缩耗时导致提交流程变慢 | 压缩和上传走 B链 后台执行，不阻塞 A链（笔记创建主流程） |
| canvas 压缩在低端机崩溃 | try-catch 包住，失败时回退用原图上传（不压缩） |

## 十、实现与原方案的出入（2026-10-06 写完之时更正，代码为准）

这一份是最初拍方案时写的，落地时有七处和它不一样。不在这写清楚，下一个人会照这份文档去改代码，改到一处已经不存在的地方。

1. **§3.1.9 那个 `utils/imageQueue.js` 没建，改成 `utils/assetQueue.js`，而且管的不是同一件事。** 原方案要的是**补传**（上传失败的图存本机、网络恢复再传）；现在做的是**补绑**（图已经传到云上、"归到哪篇笔记"这一步没做成）。补传要把原图先落到本机（`tempFilePath` 活不过一次会话），本机就多存一份用户截图、多一处要清理的目录——**这一条是待拍，不是漏做**，见文末。
2. **§3.1.5 的 `bindNoteAssets(noteId, fileIDs)` 改成了 `{items:[{file_id,size,width,height}]}`。** 只传字符串数组的话后端拿不到 `size`，而那 5GB 的比值是按 `SUM(file_size)` 算的——没有大小就没有配额提示。
3. **§3.2.3 的配额 SQL 是 `WHERE user_id = ?`，改成全站合计。** 云开发免费额度是一个环境一个池子，不是每人 5GB；按人算会出现"我 0.4%、全站其实 92%，谁都收不到提示"。回体里两个数都给（`user_bytes` / `total_bytes`），比值只认全站那个。
4. **§3.2.1 的 `note_id` 不带 `ForeignKey("notes.id")`。** SQLite 上 `ALTER TABLE ADD COLUMN` 加不了外键，声明了就和"alembic 升级后的库要和模型一字不差"那条用例永远对不上；删笔记那一路本来就显式清这批行，外键在这里买不到东西。
