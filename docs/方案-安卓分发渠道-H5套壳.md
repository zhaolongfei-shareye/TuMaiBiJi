# 安卓分发渠道（H5 套壳＋邮箱登录＋AI 自付）

他 2026-10-19 三句：**目的＝多一个分发渠道；登录走邮箱；AI 额度我自己付。**
壳走哪条（甲 Capacitor／乙 TWA／丙 uni-app）**他没选**——我取了甲，理由在第二节末，**这条是我定的，可推翻**。

---

## 一、现读的家底（决定工作量的就这几个数）

- 小程序端：**24,489 行**（13 个 wxml ＋ 15 个 wxss ＋ 39 个 js），用到 **45 种 `wx.*` 接口**。
- 后端：**58 处 `openid` 引用**，散在 12 个以上文件里（`core/auth.py`、`models/user.py`、`api/routes/*`、`services/accounts.py`…）。
- **账号那一层已经预留好了抽象**（这是最大的省）：`models/account.py` 的 `AccountIdentity` 上是
  `(provider, provider_uid)` 唯一索引，注释逐字「`provider_uid` 存的是平台侧原样那串（微信 openid / Apple 的 user identifier）」；
  `api/routes/v1_auth.py` 里 `/apple` 与 `/wechat` 两条登录**并存**。⇒ 邮箱登录是**加第三种 provider，不是重写账号系统**。
- **后端一行邮件/SMTP 代码都没有**。全仓库只有 `user.contact_email` 这一列，而它是"联系方式"（隐私指引第五项那个口径），
  **不是登录凭证，不许混用**。
- 提炼通道：`cloudfunctions/extract/index.js` 走 `cloud.ai()` ＋ `hy3-preview`，顶上注释写死「**不切计费也能用上成长计划的免费额度，走的是 hy3-preview 这一行。别改回 hy3**」。
  `usage` 只在云函数回体里（同文件 `out.usage = result.usage || null`），**后端没落账** ⇒ 单篇真实 token 数今天读不到。

## 二、路线为什么取甲（H5 ＋ Capacitor WebView 壳）

- **乙 TWA 排掉**：它依赖 Chrome Custom Tabs，国内大量安卓机没有 Google 服务／新版 Chrome ⇒「装得上打不开」这个风险要用户承担，而且它不解决商店要审的那件事。
- **丙 uni-app／Taro 排掉**：要先把 24,489 行原生小程序代码迁进框架，**等于重写前端**；而目的只是"多一个渠道"，不划算。
- 甲的代价说清楚：壳里那个 WebView 的渲染性能、输入法、返回键行为都要单独回归一遍；`<input type=file>` 与原生插件（相机／相册／存图）要一层一层试。**比丙便宜，比乙稳。**

## 三、四块工作（每块单独可验收）

### 1. 邮箱验证码登录（后端 ＋ H5）
要新写：发信、验证码或魔法链接、限频、防枚举、`AccountIdentity(provider='email', provider_uid=邮箱小写)`、注册即建账号。

⚠ **这一块的第一个卡点不在代码，在发信通道**：`.env.example` 里今天**没有任何 MAIL/SMTP 键**；
`docs/方案-2.1大版本.md` 那句「SPF/DKIM ＋ 已备案域名现成」是**当时的设想**，不是现状。
**发不出去信，这一档一行代码都开不了工** ⇒ 要么他给一枚能发信的域＋SMTP 凭据，要么开腾讯云 SES（要他账号里操作）。

连带一条合规：新增"邮箱作为登录凭证"要改《用户隐私保护指引》与 App 内隐私政策。小米官方逐字要求：
「应用首次运行应当有隐私政策弹窗，隐私政策内容完整且可直接阅读」「应提供明确的同意和拒绝选项」。

### 2. H5 前端
- **能直接复用**：全部业务 API（`/wtsj/api/*` 那套形状不动）、后端 `app/poster_engine/mpAssets.js` 那条
  ——它证明**画卡这件事已经不完全依赖小程序运行时**，H5 端不必重写画卡。
- **必须换实现的（现读计数，别漏）**：`wx.cloud` 11 处（云上对象要换成后端签发的 https URL）、
  `getFileSystemManager` 10 处、`chooseMedia` 4 处、`canvasToTempFilePath` 4 处、`saveImageToPhotosAlbum` 3 处、
  `previewImage` 7 处、`switchTab`/`navigateTo` 12 处（换前端路由）、`get/set/removeStorageSync` 63 处（换 localStorage，语义一致）。
- 顺带一条：`web-view` 官方「个人类型的小程序暂不支持使用」是**小程序侧**的限制，H5 侧不受影响。

### 3. AI 自付——两条不同的路，别混
- **①（我建议）继续 `cloud.ai()`**，成长计划那 10 亿免费额度到期（2027-03-18）后由云开发按量扣费。
  改动最小，但**要先在他的腾讯云账号里把付费方式绑上**——那是他账号里的动作，我做不了。
- **②改走混元 HTTP API ＋ 腾讯云 SecretKey**：彻底脱离「仅限小程序和云函数中使用」那句限制，
  但要重写 `extract` 那一层并自己管 key 与配额。
- 官方那句限制逐字（两处）：「AI 资源包含混元 Token 资源包和混元生图资源包……**仅限微信小程序和云开发服务端中使用**」
  ＋「**AI 资源包仅限小程序和云函数中使用，其他来源均不可使用**」。
  ⇒ 换成 H5／App 客户端时**链的形状没变**（客户端→我们服务器→云函数），变的是"给谁用"。**这一格我不判它合规还是违规**，
  他选①就是接受这个不确定性，选②就是花钱买干净。
- **价格我不给数**：官方价目页是 JS 渲染，我这次抓不到正文；搜到的两个数（2026-03 某报道称 HY2.0 Instruct 输入 0.004505 元/千 tokens、输出 0.01113 元/千 tokens；
  腾讯云社区帖写"Hy Token Plan 28 元起、3500 万～6.5 亿月度 Token"）**都不许当报价用**。
  要定成本有两条正路：控制台用量页读一次，或**给后端加一行把 `usage` 落库**（这是新需求，等他点，我自己不加）。
- ⚠ 一条迁移风险：官方那页标题写着「腾讯混元大模型服务将迁移至 TokenHub」——**我只读到标题，正文没读到**，标"待核"。

### 4. 打包与上架（这一档最可能卡死）
- Capacitor 出 APK／AAB，**侧载自己用不需要任何资质**。
- 进国内商店是另一件事，小米官方逐字：要《计算机软件著作权证书》或《APP电子版权认证证书》＋ ICP 证明，
  且「**ICP备案主体需与所提交的开发者企业信息保持一致**」「《计算机软件著作权证书》需与发布的应用信息、**企业信息**一致」
  ＋「应用发布上架，需按相关规定履行 APP 备案手续…未履行备案手续的，不得从事 APP 互联网信息服务」。
- ⇒ 三个前置今天都不齐：① **软著还在办**（10-08 已提交，鉴别材料是错件等补正）；② **APP 备案是新手续**，跟小程序备案不是一回事；
  ③ **「个人开发者账号能不能过这一关」我没读到官方明确表述**（华为那页是 JS 壳，抓不到正文）⇒ **未核实，要问接入商**。
- 域名：H5 要公开可访问 ⇒ 现读 `api.agentsbin.cn/wtsj` 在跑（后端 API 与 `/wtsj/ops` 都挂这个域），
  但**这个域名的 ICP 备案主体是谁、状态如何，我今天没有证据** ⇒ 待核。

## 四、分阶段（每段拿一次证据再走下一段，不叠第二轮）

| 这一段 | 交付 | 前置 |
|---|---|---|
| **第 0 段（一天内可验）** | **H5 只读版**：把"看笔记"那一屏做成公开网页，不登录、不收钱、不动小程序 | 一个能公开访问的域 |
| 第 1 段 | 邮箱验证码登录＋建账号 | **发信通道**（卡这） |
| 第 2 段 | H5 完整可用（录入／提炼／列表／详情／出卡），AI 走现有云函数不改计费 | 第 0＋1 段 |
| 第 3 段 | Capacitor 打包＋真机自测（**侧载，不进商店**） | 第 2 段 |
| 第 4 段 | 商店提审 | 软著下来 ＋ APP 备案 ＋ 问清个人开发者资格 |

**我建议只先做第 0 段**：一天能验，验完再决定要不要投第 1～4 段。理由是"多一个分发渠道"这件事到底有没有人来，
第 0 段就能看出来，不必先花掉发信、备案、软著这三笔等待。

## 五、负面清单（这次不做、不碰）

- 不做 iOS 版：纯 H5 套壳会被按 repackaged content 拒；iPhone 那条线本来就是原生 Swift，**两条口径不许互推**。
- 不做 uni-app／Taro 迁移。
- **不动小程序那 24,489 行**：H5 是新写一份，不是改小程序。
- 不在软著与 APP 备案齐之前先上商店（侧载可以）。
- 不引入手机号验证码（要买短信服务＋资质，比邮箱贵一档，他选的是邮箱）。
- 不为安卓版接微信支付 APP 支付（个人主体拿不到商户号；与虚拟支付那条线分开谈）。
- 不擅自把 `hy3-preview` 改回 `hy3`（那行注释里写死了原因）。
- 不在没问清"个人开发者能否上架"之前先花备案与软著的等待成本去换一个大厂账号。
