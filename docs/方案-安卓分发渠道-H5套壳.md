## 一、现读的家底（决定工作量的就这几个数）

- 小程序端：**24,489 行**（13 个 wxml ＋ 15 个 wxss ＋ 39 个 js），用到 **45 种 `wx.*` 接口**。
- 后端：**58 处 `openid` 引用**，散在 12 个以上文件里（`core/auth.py`、`models/user.py`、`api/routes/*`、`services/accounts.py`…）。
- **账号那一层已经预留好了抽象**（这是最大的省）：`models/account.py` 的 `AccountIdentity` 上是
  `(provider, provider_uid)` 唯一索引，注释逐字「`provider_uid` 存的是平台侧原样那串（微信 openid / Apple 的 user identifier）」；
  `api/routes/v1_auth.py` 里 `/apple` 与 `/wechat` 两条登录**并存**。⇒ 邮箱登录是**加第三种 provider，不是重写账号系统**。
- **后端一行邮件/SMTP 代码都没有**。全仓库只有 `user.contact_email` 这一列，而它是"联系方式"（隐私指引第五项那个口径），
  **不是登录凭证，不许混用**。
- 提炼通道：`cloudfunctions/extract/index.js` 走 `cloud.ai()` ＋ `hy3-preview`，顶上注释写死「**不切计费也能用上成长计划的免费额度，走的是 hy3-preview 这一行。别改回 hy3**」。
  `usage` 只在云函数回体里（同文件 `out.usage = result.usage || null`），**后端没落账** ⇒ 单篇真实 token 数今天读不到。

## 二、路线为什么取甲（H5 ＋ Capacitor WebView 壳）

- **乙 TWA 排掉**：它依赖 Chrome Custom Tabs，国内大量安卓机没有 Google 服务／新版 Chrome ⇒「装得上打不开」这个风险要用户承担，而且它不解决商店要审的那件事。
- **丙 uni-app／Taro 排掉**：要先把 24,489 行原生小程序代码迁进框架，**等于重写前端**；而目的只是"多一个渠道"，不划算。
- 甲的代价说清楚：壳里那个 WebView 的渲染性能、输入法、返回键行为都要单独回归一遍；`<input type=file>` 与原生插件（相机／相册／存图）要一层一层试。**比丙便宜，比乙稳。**

## 三、四块工作（每块单独可验收）

### 1. 邮箱验证码登录（后端 ＋ H5）
要新写：发信、验证码或魔法链接、限频、防枚举、`AccountIdentity(provider='email', provider_uid=邮箱小写)`、注册即建账号。

⚠ **这一块的第一个卡点不在代码，在发信通道**：`.env.example` 里今天**没有任何 MAIL/SMTP 键**；
`docs/方案-2.1大版本.md` 那句「SPF/DKIM ＋ 已备案域名现成」是**当时的设想**，不是现状。
**发不出去信，这一档一行代码都开不了工** ⇒ 要么他给一枚能发信的域＋SMTP 凭据，要么开腾讯云 SES（要他账号里操作）。

连带一条合规：新增"邮箱作为登录凭证"要改《用户隐私保护指引》与 App 内隐私政策。小米官方逐字要求：
「应用首次运行应当有隐私政策弹窗，隐私政策内容完整且可直接阅读」「应提供明确的同意和拒绝选项」。

### 2. H5 前端
- **能直接复用**：全部业务 API（`/wtsj/api/*` 那套形状不动）、后端 `app/poster_engine/mpAssets.js` 那条
  ——它证明**画卡这件事已经不完全依赖小程序运行时**，H5 端不必重写画卡。
- **必须换实现的（现读计数，别漏）**：`wx.cloud` 11 处（云上对象要换成后端签发的 https URL）、
  `getFileSystemManager` 10 处、`chooseMedia` 4 处、`canvasToTempFilePath` 4 处、`saveImageToPhotosAlbum` 3 处、
  `previewImage` 7 处、`switchTab`/`navigateTo` 12 处（换前端路由）、`get/set/removeStorageSync` 63 处（换 localStorage，语义一致）。
- 顺带一条：`web-view` 官方「个人类型的小程序暂不支持使用」是**小程序侧**的限制，H5 侧不受影响。

### 3. AI 自付——两条不同的路，别混
- **①（我建议）继续 `cloud.ai()`**，成长计划那 10 亿免费额度到期（2027-03-18）后由云开发按量扣费。
  改动最小，但**要先在他的腾讯云账号里把付费方式绑上**——那是他账号里的动作，我做不了。
- **②改走混元 HTTP API ＋ 腾讯云 SecretKey**：彻底脱离「仅限小程序和云函数中使用」那句限制，
  但要重写 `extract` 那一层并自己管 key 与配额。
- 官方那句限制逐字（两处）：「AI 资源包含混元 Token 资源包和混元生图资源包……**仅限微信小程序和云开发服务端中使用**」
  ＋「**AI 资源包仅限小程序和云函数中使用，其他来源均不可使用**」。
  ⇒ 换成 H5／App 客户端时**链的形状没变**（客户端→我们服务器→云函数），变的是"给谁用"。**这一格我不判它合规还是违规**，
  他选①就是接受这个不确定性，选②就是花钱买干净。
- **价格我不给数**：官方价目页是 JS 渲染，我这次抓不到正文；搜到的两个数（2026-03 某报道称 HY2.0 Instruct 输入 0.004505 元/千 tokens、输出 0.01113 元/千 tokens；
  腾讯云社区帖写"Hy Token Plan 28 元起、3500 万～6.5 亿月度 Token"）**都不许当报价用**。
  要定成本有两条正路：控制台用量页读一次，或**给后端加一行把 `usage` 落库**（这是新需求，等他点，我自己不加）。
- ⚠ 一条迁移风险：官方那页标题写着「腾讯混元大模型服务将迁移至 TokenHub」——**我只读到标题，正文没读到**，标"待核"。

### 4. 打包与上架（这一档最可能卡死）
- Capacitor 出 APK／AAB，**侧载自己用不需要任何资质**。
- 进国内商店是另一件事，小米官方逐字：要《计算机软件著作权证书》或《APP电子版权认证证书》＋ ICP 证明，

  ＋「应用发布上架，需按相关规定履行 APP 备案手续…未履行备案手续的，不得从事 APP 互联网信息服务」。

## 六、决策定稿（他 10-19 深夜一句「三个决策点全批默认，直接定稿输出」）

三个决策点按我给的默认钉死，**下面每一格都写清"定了什么、为什么、谁动手"**：

### 决策① 发信通道＝腾讯云 SES ＋ `agentsbin.cn` 作发信域名
- **为什么取 SES 不取自建 SMTP**：他账号本来就在腾讯云（云开发＋混元都在那），域名已备案、DNS 在他手里，
  SES 只要加几条验证记录就能发；自建要管 IP 信誉、反向解析与退信，运维成本比这件事本身贵。
  ⚠ **SES 的单价与免费额度我没读官方页 ⇒ 未核实**，开工前照一次控制台再定限频。
- **他的动作（我做不了）**：开 SES → 加 SPF/DKIM 那几条 DNS 记录 → 建一个发信地址 → 把 SMTP 凭据放进服务器 `.env`。
  **凭据一律走剪贴板或 stdin，不进对话、不进 argv**（同 `feedback-credential-via-clipboard`），且**必须换完打一发真邮件自证**。
- **要新增的 `.env` 键（本路定的形状，开发那一路照抄）**：`MAIL_HOST` / `MAIL_PORT` / `MAIL_USER` / `MAIL_PASSWORD` / `MAIL_FROM`，
  外加两枚开关 `EMAIL_LOGIN_ENABLED`（默认 false，形状对齐 `XPAY_ENABLED` 那种"没配好就别开"）与 `EMAIL_CODE_TTL_SECONDS`。
  ⚠ 一条已知隐患要防：服务器 `/home/ubuntu/.env` 是**另一个项目的**，而我们 `config.py` 是 `extra="forbid"`——
  脚本 cwd 落错目录会把那一份的键值原样打印出来（见 `wtsj-server-deploy-info`）。**新增键必须落在项目自己的 `.env`，且 `deploy.sh` 的少键自检要跟着加。**

### 决策② AI 付费＝继续走 `cloud.ai()`（选项①），不改混元 HTTP API
- **理由**：改动最小——`cloudfunctions/extract/index.js` 那一行 `MODEL_ID = 'hy3-preview'` 不动，
  提炼链形状、回体四栏、`usage` 字段全不变；换 HTTP API 要重写这一层并自己管 key 与配额。
- **他的动作**：在云开发／腾讯云账号里**把付费方式绑上**，否则 2027-03-18 免费额度到期那天起，提炼会静默失败（10-13 那次丢 `.env` 三行就是同一类静默）。
- **判据（我出尺子）**：① 到期日前 30 天要有一条能读到的提醒或自检；② 提炼失败必须回"降级态"而不是把空正文存进笔记；
  ③ `usage` 现在只在云函数回体里、后端没落账 ⇒ **建议加一行把每篇 token 数落库**，这样"每篇几分钱"以后能现读，不必再猜。

### 决策③ 交接件＝要，已出
`docs/交接-安卓H5分发渠道-20261019.md`（形状照 10-11 那份比赛材料交接，末节就是给开发那一路的提示词）。

### 本路定的实现口径（他没逐条拍过，可推翻，但开发那一路照这个开工）
- 壳取**甲（H5 ＋ Capacitor）**，不起新子域，落点 `agentsbin.cn/app/`。

## 八、域名那一格已答（10-19 深夜他一句「H5 挂在 .cn 下面就行了，这个网站已经是备案的」）

**现读四条基础设施事实**（全部当场从服务器与现网取的，不是推断）：

1. **备案是真的**：`https://agentsbin.cn/` 页脚现读 `粤ICP备2026125298号-2`，标题 `Tumark 图麦笔记｜链接截图转笔记 · 笔记卡片小程序｜图麦克去水印`。
   ⇒ 这一格结案：**挂在已备案的 `agentsbin.cn` 下面，不需要新域名、不需要新备案。**
2. **落点＝子目录，零基础设施改动**：nginx 那个 server 块 `server_name agentsbin.cn www.agentsbin.cn`，
   `root /var/www/agentsbin-cn`（里面现有 `index.html`／`en/`／`assets/`／`releases/`＋一枚 `deploy-static-site.sh`）。
   ⇒ H5 放 **`/var/www/agentsbin-cn/app/`** 就是 `https://agentsbin.cn/app/`，**不改 nginx、不加 DNS**。
3. **证书不覆盖新子域**：那张 Let's Encrypt 证书 SAN 逐字只有 `agentsbin.cn, api.agentsbin.cn, www.agentsbin.cn`（`notAfter=Dec 4 2026`）
   ⇒ 所以**别起 `h5.agentsbin.cn` 这种新子域**（要改 DNS＋重签证书＝两趟现网写）；子目录这条路把这些全绕开了。
4. **跨源今天就已经通**：现网预检实测——`OPTIONS https://api.agentsbin.cn/wtsj/api/notes/` 带 `Origin: https://agentsbin.cn`
   回 **200**，响应头 `access-control-allow-origin: *`、`access-control-allow-headers: authorization,content-type`；
   代码侧 `app/main.py` 那枚中间件是 `allow_credentials=False` ⇒ **Bearer 票这种鉴权配 `*` 正好，`.env` 一行都不用改。**

⚠ 但有一条**别读成"商店那关也过了"**：网站 ICP 备案 ≠ **APP 备案**。小米逐字仍要「应用发布上架，需按相关规定履行 APP 备案手续」
＋「ICP备案主体需与所提交的**开发者企业信息**保持一致」——这个域名的备案主体是个人还是企业我今天没读到证据，
而"个人开发者能否在国内商店过这一关"仍是**未核实**（第四节第 4 块那三格没变）。

**⇒ 于是第 0 段（公开只读网页版）今天零阻塞**：域名有、备案有、证书覆盖、跨源已通、后端 API 现成。
欠的那一格（发信通道）只挡第 1 段（邮箱登录），不挡第 0 段。
