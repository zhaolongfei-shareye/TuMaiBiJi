# 图麦笔记｜让有价值的信息，不止于收藏

**比赛提交说明** · 创作背景 / 创作思路 / 用到的 AI 技术 / 满足的场景 / 实践过程

> 一款把**链接和截图变成知识笔记**的微信小程序。一条链接、一张截图丢进来，十几秒后回来的是一条带标题、摘要、核心要点和标签的笔记——之后能搜、能归类、能存成一张卡片图随时调用。

---

## 一、创作背景：收藏夹不是知识，是一笔越欠越多的债

我们每天都在生产同一种东西：**没来得及整理的有价值信息**。

微信里读到一篇有启发的公众号文章，第一反应是收藏；看到一段有用的课程内容，第一反应是截图；群里丢来一份参考资料，先存进相册。三天之后，当你真的需要它——收藏夹两百条，相册里四百张截图，你既想不起来它在哪，也没有耐心从头读一遍再抄几句。**"先存着"这个动作完成了，"以后整理"这个承诺从来没有被兑现。**

市面上的工具各解决了半件事。收藏类工具解决"存下来"，它保存的是**入口**——一个等待被再次打开的地址，而你当初为什么收藏它，已经忘了。笔记类工具从一块空白编辑器开始，它假设你**已经知道要写什么**，于是记录变成了一次小型写作任务，启动成本之高，足以让绝大多数记录冲动在打开应用之前就被放弃。

这两类工具之间，一直横着一道没有人补上的裂缝：**从"我发现了价值"到"我留下了可用的记录"，中间那次整理，至今完全由人肉完成。**

为什么现在值得重新做一遍？因为两件事同时成立了：

1. **大模型第一次便宜到可以被一个个人开发者随手嵌进产品里。** 微信云开发的成长计划提供了 10 亿 Token 的免费额度，而实测下来把一篇长文提炼成结构化笔记大约消耗 1,900 Token——**"读懂一篇文章并帮你整理好"这件事的边际成本，第一次降到了 0 元**。这不是纸面推算，是现网跑出来的读数（见第三节）。
2. **开源 OCR 第一次能在最便宜的单机上跑起来。** 一套检测 + 方向分类 + 识别的三模型 OCR，纯 CPU 推理、模型随包分发、不需要任何密钥，常驻内存 160MB 左右——一台 3.7GB 内存的服务器就够用。

于是"图麦笔记"有了它唯一要做的那件事：**把整理这一步交给机器，把发现的动作留给人。**

## 二、创作思路：把记录的起点，从空白页前移到"已经看到的好内容"

产品的核心不是功能列表，而是一个流程重构：

**取回内容（抓取 / 识别）→ 炼成结构（大模型）→ 存成找得回来的东西（分类 · 搜索 · 卡片图）**

链接和截图不再是"记录之前的临时材料"，它们本身就是合法输入。用户不必先组织好语言，也不必先规划知识体系——从最小的一次记录开始，先用起来，再慢慢积累。

四条原则支撑着这个思路，它们同时也是这个项目最不像"demo"的地方：

**① 顺应用户已有的习惯，而不是教育用户建立新流程。** 复制链接、按截图键，这些动作每天发生几十次。产品要做的只是给这些已经存在的高频动作接上下一步，而不是要求用户先学会一套知识管理方法论。

**② AI 的不确定性必须被关进契约里。** 大模型会超时、会被限流、会吐出不是 JSON 的东西。我们的做法是把它的输出钉成四个字段，解析时保留宽容度，并且把"值得重试"和"重试也不会好"显式区分开。**模型不可用时，系统降级保存原文并标记为降级态——绝不用假内容填空，绝不让用户以为已经整理好了。**

**③ 界面不许诺服务端还没做的事。** 计划中的额度闸门和邀请奖励还没实现，所以界面上至今没有出现"100 篇""分享得额度"这类数字。隐私条款里的每一句承诺（截图只在内存、不落盘、无埋点）都是逐条对着代码核对后才写上去的。

**④ 隐私是架构决定，不是免责声明。** 截图经 HTTPS 上传后只在服务进程内存里暂存，识别完立刻丢弃，不落盘、不入数据库、没有对象存储；OpenID 不下发给客户端；接口按登录身份隔离，用别人的身份访问你的笔记拿到 404；小程序内没有广告、没有统计埋点、不接入任何第三方分享或推送 SDK。在一个"AI 应用"里，这条尤其重要：**用户交给你的应该是内容，不是数据。**

## 三、用到的 AI 技术

### 1. 大模型结构化提炼：把"一篇文章"变成"四个字段"

- **模型**：腾讯混元 `hy3-preview`，通过微信云开发在云函数内以 `cloud.ai()` 调用。
- **任务契约**：文本进 → 严格 JSON 出——`title`（简洁标题）、`summary`（2–3 句摘要）、`key_points`（3–8 条要点，每条一句话）、`tags`（3–6 个短词标签）。`temperature 0.3`，输入截断 12,000 字。
- **实测延迟**：单次 1.27–2.87 秒；从提交到笔记出现在列表，链接导入约 4 秒。
- **成本实测为 0 元**：现网四十余次真实调用的消耗全部落在成长计划的免费 Token 包（76,248 / 10 亿），云开发套餐那侧的调用与计算读数同时为 0。按单篇 1.9k token 折算，额度够五十万次量级提炼。

这条链路上有三个只有真跑过才会知道的细节，它们比"接了个大模型"更能说明工程含量：

- **提示词全仓库只有一份**，由调用方持有并通过参数传给云函数。留第二份在云函数里，改一处忘一处，线上就会出现"后端以为换了 prompt、模型其实没换"。
- **空闲后的第一次调用必吃一个 429**，紧接着的几次全好。后端最初把"函数返回错误"一律当不可重试直接降级，结果就是每条空闲后的第一条笔记静默丢掉摘要。现在云函数把可重试性用字段显式带出来，后端只对 429/5xx 做指数退避重试。
- **模型 id 不是照文档抄的**：控制台里带"免费额度"标记的 `hy3` 一律在 0.68 秒内抛 `AI_MODEL_NOT_ENABLED`（要求先切换为资源点套餐，而那个切换不可回退），`hy3-preview` 才是不切计费就能用上免费额度的那一行。这是实测出来的结论。

### 2. 自建 OCR：让相册里的图片重新变成文字

截图是这个产品最重要的输入之一，而"图片里有什么字"这件事我们没有交给任何云服务。

- **方案**：RapidOCR（PP-OCR 系：文本检测 + 方向分类 + 序列识别三模型），ONNXRuntime **纯 CPU 推理**，模型随 wheel 分发。**不需要任何密钥，不向任何第三方上传一张图片。**
- **三道闸门全部来自实测**：
  - 识别前缩放到长边 ≤1600px。同一张 3420×2214 的长图对照：不缩放进程峰值内存 **1,076.6MB**，缩放后 **666.6MB**，而识别出的字符数从 294 **升到** 301——缩放没有丢信息。
  - **缩放之前先按像素数拒图**。因为缩放要先解码，"单张不超过 10MB"这种字节上限挡不住一张 0.43MB 的 1.44 亿像素纯色 PNG（实测吃掉 1,271MB）。现在 4,000 万像素是硬上限，拒图只花 0.015 秒。
  - 按检测框坐标重排成视觉阅读顺序，并剔除工具栏图标被认成的噪声单字（"AB X""κ7"这类不含中文的极短行）。
- **生产机端到端读数**：一张 1170×3200 的真实中文长截图，从提交到笔记出现在列表 **4.0 秒**；worker 进程组按 0.15 秒轮询采到的 cgroup 内存峰值 **465.6MB**（当时机器可用 1,959MB）。
- 一次最多 9 张图，多图批次在内存里暂存、30 分钟未提交自动作废。

（选型本身也是一个决定：个人主体拿不到微信官方 OCR 接口，混元的 token 也做不了 OCR，所以"自建"不是偏好而是唯一可行路径——它顺带让整条链路少了一个外部依赖和一笔凭据。）

### 3. 网页正文抽取

`trafilatura` + BeautifulSoup/lxml 在自有服务器上直接抓取并抽取正文，**不经过任何第三方解析服务或短链服务**。需要登录、有付费墙或屏蔽抓取的页面会直接告诉用户失败，**不会塞半条空笔记进列表**——"看起来成功了但内容是空的"是最糟糕的失败形态。

### 4. 多来源，统一成一种知识表示

链接和截图的入口形态完全不同，但它们最后进的是**同一个四字段结构**。所以搜索、分类、标签、置顶、卡片图这些能力对所有来源一视同仁，用户不需要为不同来源维护不同习惯。搜索同时命中标题、摘要、正文和抓下来的原文四列——在 200 条笔记里找一个词，不需要你记得当初给它打过什么标签。

### 5. AI 也用在研发过程本身

这个项目 6 天完成，靠的不只是写代码，而是**让界面自己证明自己对**：

- 用自动化框架驱动微信开发者工具的模拟器，真点按钮、真输文字、真截图、真量控件尺寸，**55 条界面断言**在每一次交付前跑一遍；后端 **87 条 pytest 用例**。
- 断言要落在独立事实上。海报"按内容定高"这类改动，量的是导出的成品 PNG（逐行扫描最长连续空白），而不是回读画布尺寸——画布尺寸和页面里那个数出自同一份计算，拿它验自己永远是对的。
- 有一次真机报"选完照片没反应"，而 18 张状态截图 + 13 条真点断言全绿。根因是模拟器的选图替身不会补发 `onShow`，而真机从相册返回时一定会补发一次，页面里"每次显示都重置草稿"把刚选好的图清空了。从此自证流程里多了一条：**凡是调起相机、相册、支付这类系统能力，必须手动补一刀 `onShow`。**

## 四、满足了哪些场景

**学习资料积累**——课程文章链接、板书和 PPT 截图，变成带要点的笔记，复习时搜一个词就能定位，而不是在相册里翻四十张图。

**工作信息整理**——行业动态、竞品页、群里丢来的报告截图，十几秒后已经是摘要加标签的形态，会后翻一眼就够，不必重读原文。

**创作灵感收集**——值得借鉴的选题和表达，随手一条链接进来，标签自动带上，攒成自己的素材库。

**日常兴趣记录**——旅行攻略、菜谱、书单。这也是我们最喜欢的一条用法：**把一条笔记生成一张按内容排高的卡片图，打印出来贴在纸质手账或攻略本上，或者插进任意一篇文章里当配图，日后从那张图就能调回来看。** 数字笔记最有价值的时刻，往往是它离线之后的那次被翻到。

**微信内的零切换**——内容本来就发生在微信里。复制链接、截一张图，三秒后笔记已在库里，不需要切换应用、不需要"稍后再整理"。

也如实写清楚**不满足的**：iPhone 默认的 HEIC 需要先改成"兼容性最好"；经微信转发的图片会丢拍摄参数，这类图只认画面里的字；部分海外站点抓取不稳定。边界写清楚，比把功能说满更经得起追问。

## 六、我们真正想证明的一件事

"AI 应用"这个词现在很贵，但它其实可以很朴素：**一个人，六天，一台 3.7GB 的服务器，零 API 账单，把"读懂内容并整理好"这件事做进了一个 194KB 的小程序里，让它每天在微信里顺手可用。**

图麦笔记的创新不在模型，而在**重新设计了知识记录的起点**：不再等待用户写下第一句话，而是从他已经发现的价值开始。收藏工具让你存下更多，笔记工具让你写得更认真，我们想做的是中间那一层——**让每一次随手保存，都有机会成为未来真正用得上的积累。**

> 图麦笔记，让收藏不止于收藏，让信息逐渐成为自己的知识。
