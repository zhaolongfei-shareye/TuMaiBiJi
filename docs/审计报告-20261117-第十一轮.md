## 二、逐条证据

### W1 干净 HEAD 的引擎副本对不上（两笔账叠着）

判据本体：`backend/tests/test_admin_poster_preview.py::test_副本与客户端那一份逐字相同`——manifest 里那份 md5 表钉着每一只副本，副本／客户端／名单三者必须一字不差。

HEAD worktree（`git worktree add /tmp/audit11-head 26a699f`）现跑：**1 failed, 16 passed**。红的第一只是 **api.js**：

```
E  AssertionError: api.js 的副本与 miniprogram/utils 那份不一样了——跑 python3 docs/工具/同步-后台预览引擎.py 刷新，别手改副本
E  assert '0a5984ce0f92…' == '9cac3504da0c…'
```

逐只现量（同一棵 worktree，只读脚本）：`api.js`、`appInfo.js` 两只是 **manifest==client: False / engine==manifest: True**——名单和副本还停在旧客户端，客户端已经往前走。两笔账分别是：

1. **api.js＝Z47 那笔同步债**：`b456d75`（11-16 02:46）改了客户端 api.js 没带副本走。今天出包前跑同步脚本在工作树刷平了（76 passed），但没 commit。
2. **appInfo.js＝昨晚抬号那笔**：`7d3834d` 只把客户端 `appInfo.js` 抬到 2.5.3，副本那份在 HEAD 上仍是 2.5.2。对照 2.5.2 那颗的先例——抬号时把刷平的副本一起入了库，HEAD 自己才是咬合的。

为什么当时不单独 commit 这四只：`manifest.json` 里那张 md5 表把九份副本钉成一整份名单，而 manifest 与 poster.js 的在途改动是**海报那一批**的（不混别人文件的纪律）。单独提 `api.js`＋`appInfo.js` 两份副本，名单不跟着走照样红；名单跟着走就是把别批未提交的画法卷进来。所以这一格的正解只有一个：**等海报批入库，四只一起进**。位次正本第 15 行昨晚已记明这笔欠账。

### W2 “从不抛”在签名那一段不成立

`asc_reports.py:141`（pull_sales）与 `:271`（pull_analytics）的 `token = _token()` 都在 try 外面；`_token()`→`_read_key()` 是真开文件。`configured()` 检查过钥文件在，到这里之间文件被挪走／权限变了／ES256 签名炸（cryptography 缺档）——任何一条都会把异常打穿 `sync()`：路由层只接 `AscNotConfigured`（`admin_ops.py:505`），其余就是一张 500；cron 脚本没有 try，traceback 进 log。
网络那一族的错都兜得住（每发都包了），**没兜住的只有签票那一发**。两条改法任选：把 `_token()` 挪进各自 try；或把文档与 docstring 的"从不抛"改成"网络不抛、签票会抛"。等他拍，不许只改注释不改行为当修完。

### W3 四只列表口都只读第一页

`_find_ongoing_request`（:326）、`_list_reports`（:338）、`_latest_daily_instance`（:344）都只拿 `data` 第一页，没有跟 `links.next`。今天的形状下够用（ONGOING 单基本唯一、报告 52 份一页装得下、实例按 procDate 挑最大），但 `:353` 那句注释"**本来就是新→旧排的**"是一条**从未被真实数据验证过的假设**——现网 asc_daily 0 行（见 W10），analytics 一份实例都还没下载过，"新→旧"只有 11-16 建单时列表接口的观察、没有实例接口的读数。若实例超过一页且排序不是新→旧，`max(procDate)` 只在一页里挑，会拿旧的那份当最新。
**动作**：首批实例到手那天（预计 11-17～11-18）拿真数验一次排序；验不过就补翻页。

### W4 `state(days)` 没夹边界

路由（`admin_ops.py:484`）把 `days` 原样传进 `state()`（:500），窗口循环按 `range(days)` 铺——`days=-1` 画空表、`days=100000` 画十万行。只有管理票拿得到，影响止于那一屏，但 60/minute 的限流防不住一个手滑的 URL。夹 `1..60` 一行事。

### W5 payload 会长胖

`upsert`（:467-470）对 payload 是**整键替换**（`merged.update`），重复拉不涨；但 `analytics_rows` 把那一天那份报告的**每一行 JSONL 原样留底**。四份报告各一天一份，Apple 窗口 35 天封顶，SQLite 单行数 MB 前没事。只记，不动。

### W6 `.env.example` 少六栏

`backend/.env.example`（现读 125 行）里有 `ADMIN_SESSION_MINUTES`（:45），**没有** `ADMIN_REMEMBER_DAYS`，**也没有** `ASC_KEY_ID／ISSUER_ID／KEY_PATH／VENDOR_NUMBER／APP_ID` 那五栏。这份文件是"重建一台服务器该配哪些栏"的清单——缺栏的后果不对称：`ADMIN_REMEMBER_DAYS` 丢了退回默认 30 天（无害）；ASC 五栏丢了那一栏当场 503（响的，不是静默），但**没有一句提示告诉你少抄了哪栏**。补六行（ASC 那五栏注明"值不是密钥、密钥是 KEY_PATH 指的那只 .p8"）。

### W7 退出话术说强了

`ops_page.py:614` 那句「标签页里和本机记住的那份票都清了」——清的是**这一页**的 sessionStorage 与共享的 opsRemember；同一浏览器里**另一个还开着的**标签页，它自己那份 sessionStorage 票还在，继续能用。"退出这一台"四个字的字面承诺比实现宽。改话术（"这一页退了"）或实现广播清理（storage 事件）二选一，前者便宜。

### W8 30 天 localStorage 票的边界（记录，不返工）

## 三、没有问题的部分（点名过、没挑出毛病）

- **30 天那一刀的测试形状**：三条新用例覆盖"不勾=短票／勾了=长票且照常开门／两端接线逐格查"，其中接闸方向用了 monkeypatch 缺文件→503 的反向；`test_ops页面匿名可取` 的存储纪律从"整页不许 localStorage"改成**逐行扫**"每一处 localStorage 必须带 opsRemember"——比旧判据强，不许溢出的口子还在。
- **迁移与模型**：单头链、nullable 全计数列（缺数≠零）、唯一索引 `ux_asc_daily_report_date` 走 `Index(...)` 而非 `Column(unique)`（反射坑照纪律避开了）、`models/__init__` 注册齐（no such table 那族坑第二次预防）。
- **Tsv 按列名取数**（不按位置）、404=那天没数不补行、`Begin Date` 跟报表走不跟请求走、两种币不加总——四条口径都对且有用例。
- **同步口是同步 `def`**（不占事件循环）＋按 IP 限流；与 Z3 那一族（事件循环里的同步调用）没有重犯。
- **色板零回归那把尺子的新锚**（`5675192`）：从"函数叫什么名字"改钉"clipRounded 在 paintLayers 之前／最后一次对号到落笔无 await／h 与 img 同帧 setData／画布离屏且窗内只放 image"——正是 `24f9048`"锚别钉取法、要钉被禁的东西自己"那条纪律的样子；作者当日已报五发变异各咬一条。
