## 1. 这一屏的骨架（收起 → 展开）

| 状态 | 画什么 | 在哪 |
| --- | --- | --- |
| 收起 | 一条纸白胶囊：左「动动手指」＋右三枚小圆（拍照／相册／链接） | `create.wxml` `.bar`，`wx:if="{{!active}}"` |
| 展开 | 胶囊**整条退场**，换成：框外一行小字 → （可选）框外一行报错 → 一张暗面板 | `.out` / `.out-err` / `.panel` |
| 展开·面板 | 三枚模式标签（照片／链接／文字）＋ 一张卡；卡里只有**一个输入框（或一横排小图）＋ 一枚右滑长条** | `.modes` / `.card` / `.sld` |

- 展开时整组 `position: fixed`，左右内缩 `--sp-3`(24rpx)、底边 `bottom: 152rpx`（= 底栏 128 + 一条 24 的缝）。底栏几何一改，这里要跟着改（由 `验-录入面板沉底.js` 两头现读钉住）。
- 「换背景」「调亮度」那一行只在收起态存在；展开时整行不渲染。
- 点面板外任何空白 = 收回；`busy` 期间不收（别把进度藏起来）。

## 2. 两档高度（都是算出来再量过的，不是拍的）

| 档 | 高 | 什么时候在这一档 |
| --- | --- | --- |
| 收起 | **500rpx** | 默认 |
| 展开 | **580rpx** | 「文字」档原文框拿到焦点；或「照片」档小图 + ➕ 超过一行（>5 格） |

- 算式（静态尺子现读现算，10-08 实测读数）：`面板 500 − 描边 2×3 − 上内边距 30 − 标签行 77.5(字号×1.6+下内缩 15) − 卡上边距 25 − 卡边框 2×3 − 卡内边距 2×30 − 下内边距 32` ⇒ **卡内可用 251.4rpx**（展开那一档 331.4）。
- 最占地方的一态是照片那三枚圈：快门 210 + 那列间距 8 + 那行字（字号×1.35）= **250.4 ≤ 251.4**——**只剩 1rpx**。第二占的是文字展开那一叠：框 160 + 开关 48+8 + 条 110 = **326 ≤ 331.4**。所以**改字号、加控件、改列数之前先跑 `量-面板四态自然高.js`**（七个态 × 中英各量一遍，给"最后一块离面板内下沿"的余量，量不到就退出码非 0），再决定动不动那两个数。
- ⚠️ 标签行那一档**算式按 1.6 而不是 WXSS 里写的 1.3**：10-08 真跑量到微信给 `view` 的默认行高约 1.6，`.md` 上那条 `line-height:1.3` 没吃进去，白差 15rpx。算式取实测那一档才不骗人。
- 展开只多一行（580 − 500 = 80）：**不再往上加**。
- 报错行**画在面板外面**（`.out-err`），所以面板不必为每一态预留那一行——这正是从现网 700rpx 压到 500 的那一笔。
- **面板顶在屏内哪一条线（"不许挡人头"那条的实测）**：收起那一档顶在 **55.0% 屏**（414.0px／线在 414.15px，容 2px 是四舍五入不是布局坏）；展开那一档顶到 **49.5% 屏**。展开有两种触发，代价不一样：**文字档是焦点撑开的，真机上键盘一定已经顶起来**，屏下半截本来就没了；**照片 6 张以上是格数撑开的，没有键盘垫着**，那一档确实盖到鼻尖以下——这是"上限 9 张"与"展开只多一行"两条一起逼出来的数。**门槛分两档（55%／49%）是我自己定的，他只拍过"不许挡人头"那句、针对的是默认那一屏。**

## 3. 三档模式与各自的控件

**只有三个标签。** 相册不再是独立一档——它是「照片」那一态左边那枚小圆。`active` 一位说清当前那一档（`'' | 'photo' | 'url' | 'write'`），页面上没有第二个 `mode` 字段。

| 档 | 卡里画什么 | 提示词（全在框里，点进去就没了） | 提交 |
| --- | --- | --- | --- |
| 照片·没选图 | 三枚圈居中：小圆相册(105) — 快门(210，白环 10) — 小圆链接(105)，每枚带一个字 | 无（这一态没有条） | 点圈直接开系统选择器 |
| 照片·已选 | 一横排小图 100rpx 见方 + ➕ 钉在最右端；序号 1…9 标在每张图左下角 | 无 | 右滑长条 |
| 链接 | 一个 `input` | `linkDesc`「公众号文章 / 网页链接」 | 右滑长条 |
| 文字 | 一个 `textarea`（收起一行 105、展开两行 160） | `manualDesc`「把原文贴在这里，摘要自动生成」 | 右滑长条 |

- **这一屏没有标题格、没有分类选择器、没有「粘贴／保存／清空／取消」那排按钮、没有四步指引。** 标题与归类在详情页「编辑」→ 亲自撰写那一页改（`pages/write/write.wxml` 两样都在，`验-统一录入条.js` 里钉着这条实据）。
- 三个标签只切视图，不顺手开相机（进来挑模式的人不该被系统选择器打断）。
- 点收起态那条胶囊 = 进「照片」（10-08 起默认档不再是文字）。

## 4. 右滑才开始提炼（那一枚长条）

轨道 110rpx 高、纸白底、**外圈 5rpx 白边**（＝快门那枚白环的同一笔，进度转成实心之后它仍在）。圆 90rpx，停在 `left: 10rpx`；行程到 `left: 456rpx`（= 轨道内宽 556 − 圆 90 − 内缩 10，JS 常量 `SLD_MAX_RPX` 与 WXSS 那三个数由静态尺子现算比对）。

四个态（效果图那份「补」排画的就是这六格）：

1. **待滑** — 圆在最左；这一格还没东西时圆转灰（`.sld-off`）、字淡一档。
2. **拖动中** — 圆跟手指走（`touchmove` 用 catch 不吃页面滚动，位移按 `windowWidth/750` 换算成 rpx，小于 3rpx 不写 setData）；轨道仍白。⚠️ 圆的位置是模板字段 `knobRpx` 绑在 `style="left:{{knobRpx}}rpx"` 上，而这一枚是 `<template is="sld">` 画出来的——**`<template is>` 不继承页面 data，清单里漏一位不会报错、只会静默不跟手**（10-08 就漏过一次：清单递的是 `knobStyle` 而 JS 里根本没这一位，结果 data 一路走到 456、屏上那枚圆始终贴在起点，四张截图里都是左边那颗）。现在两头都有静态钉（模板用到的字段必须都在清单里、清单里的必须都在页面 data 里），真跑 `D3b` 量的是**屏上那一枚的实际左沿**而不是 data 里的数。
3. **就位** — 松手时若"到位 **且** 这一格真有东西"，圆钉在最右、颜色不变、字换成 `busyExtract`；**空着滑到底要说一句规则、圆回弹**（不钉在最后）。
4. **进度** — 轨道从左边吃进实心色，宽度＝`fillPct`。这是**假进度**：服务端任务只有 `status`，没有百分比（`backend/app/services/queue.py` 的 `set_task_status`），客户端 2 秒轮一次（`utils/api.js` 的 `pollTask`）。曲线 `90 × (1 − e^(−秒/30))`，封顶 90%，接口回来才钉到 100%。站长原话「进度条不需要太精准」。
5. **完成** — 整条转实心、白环仍在、字转纸白 → 吐司 `extractSucceeded`「已存入笔记」→ 800ms 后跳详情页（这条时序与现网一字未改）。
6. **失败** — 圆回最左、轨道全白，那句错在框外说。

三档共用同一趟生命周期：`_extractBegin(kind)` → `_extractDone(noteId, patch)` / `_extractFail(err)`，进度表在成功、失败、`onHide`、`onUnload` 四处都停。

## 5. 张数与那枚 ➕

- 上限 `MAX_SHOTS = 9`（`create.js` 一处），与服务端 `models/asset.py` 的 `MAX_ASSETS_PER_NOTE = 9` 同值，由 `验-张数只有一个出处.js` 钉住。（`ingest.py` 的 `MAX_IMAGES_PER_BATCH = 10` 是"一次 OCR 收几张"，与"一篇挂几张"是两件事，不是不一致。）
- **满了挡在门口**：`left = MAX_SHOTS − 已有张数`，`left <= 0` 就不开选择器，直接吐司 `maxShots`「最多 {n} 张，先删一张再加」，➕ 同时转灰（`.th-add-dis`）。原来那一刀是 `slice(0, 9)` **静默截断**——选了没看见、界面一句都不说。
- 合并那一处**不再自己截一刀**（`count` 已经把上限交给系统选择器）。
- 一行五格是几何推出来的：9 张 + ➕ = 10 格，五列是"展开只多一行"落得下去的最小列数（四列要三行）。
- **➕ 用 `margin-left:auto` 钉在"它所在那一行"的最右端**（一行四枚时贴右沿、两行时贴第二行右沿，中间留的空是设计的一部分，不是没排齐）。效果图那一份画的是 `grid: repeat(4) + space-between`（一行四枚、拉开铺满），落码换成了"五枚靠左 + ➕ 贴右"——**换的根据就是上一条那个算式，这一处他没逐字拍过**。
- 序号那枚小圆片（`.th-no`）标在每张图左下角，「已选 N 张」那一行整个撤了（见 §3 那张表）。

## 8. 「文字」这一档送进服务端的是什么

`POST /api/ingest/text` 带 `{ title, content, translate }`：
- `content` = 他贴的原文；`translate` = 那枚「原文翻译」开关（默认关，只在这一档的展开态出现）。
- `title` = **原文第一行派生**（`titleFromText`：取第一条非空行、剥掉 `# > * -` 这类记号、截 50 字）。服务端那道 schema 要一个非空标题（`IngestTextIn.title` 是 `min_length=1`），而这一屏的标题格撤了，所以客户端必须递一个过去；落库后在详情页「编辑」改。
- 不带 `category_id`（默认 null = 未分类）。
- ⚠️ **待拍**：另一条路是让模型起的标题生效（提炼那条链本来就返回 `title`，手打这一档现在按 10-04 那条决定不用它）。那条更准，但要动后端两处（`IngestTextIn.title` 收成可选 + worker 在没给标题时用 `knowledge["title"]`）并部署一次。旧客户端仍带自己的标题，所以那条改动对现网是纯放宽。

## 10. 写这一屏的尺子时量出来的五条平台事实（动尺子前先读这段）

1. **`mp.evaluate` 里 `pg.setData(一个数组)`，服务层 data 到位、视图层不跟**。对照过：同一趟调用里 `active`（标量）跟了、`previewImages`（数组）没跟；automator 侧 `page.setData` 跟；`setData({'previewImages[0]': …})` 路径写法跟。**所以往屏上喂列表只有两条路：走真入口（桩住 `wx.chooseMedia`，success/complete 一路发完）或用 `page.setData` + `page.callMethod`**；喂完还要轮询渲染层读数（`$$(sel).length` 到目标值）再开始量几何，否则后面每一条都在给上一帧打分。
2. **`createSelectorQuery` 不认子选择器 `>`、也不认逗号表**（`.card > view, .card > textarea` 回空数组）。按类名一枚一枚 `selectAll` 才行；名单漏一枚就是"量不到却一条不响"，所以"一块都没摸到"本身要当红（`Math.max(...[])` = −Infinity 会把"没被顶出卡外"那条**跑成假绿**）。
3. **`display:none` 的节点，`boundingClientRect` 回的是"高 0 的那一份"，不是 null**；而 `page.$$(sel)` 照样回 1。判"整个不渲染"要按高度判（`!rect || rect.h < 1`）。
4. **`wx:key="*this"` 撞键，那一串 `wx:for` 整个不渲染**（四张同一个路径 ⇒ 屏上是空态）。真机上 `chooseMedia` 回来的路径各不相同，所以这不是产品问题，但**尺子造的假路径必须互不相同**。
5. **同一时刻只能有一把尺子共用 9431**：另一批在后台跑（它会 `cli quit` + 重开工具），前台这把连的会话会被半路抽掉，报回来的是一整节假红（`A1/A2/A3/A4` 从第一条就红 + 连接类报错）。看到"整节全红 + 连接崩"先怀疑会话被抢，等前一批跑完重跑一次再下结论。
