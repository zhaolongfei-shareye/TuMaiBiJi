## 1. 这一屏的骨架（收起 → 展开）

| 状态 | 画什么 | 在哪 |
| --- | --- | --- |
| 收起 | **三块**（10-10 晚拍板，正本 `docs/design/10-10两入口多方案/PNG图标.png`）：左块人物入口 308 见方（人物上半超出块顶 52rpx，下半被取景窗裁在白条上沿；块底那条白底写「记下来」+ 一行小字），右两枚计数各 382×148（图标从白条后面露出来、数字在右、名字在白条里带一枚小圆点）。**左块点一下进拍照那一档（零延迟）；换人是点右后方那枚淡灰剪影**（10-10 深夜改的口，见 §6.3） | `create.wxml` `.home-blk`，`wx:if="{{!active}}"` |

- 收起态那一组**自己 `position: fixed`**，顶落在 `min(66.3%, calc(100vh − 546rpx))`（`546 = 整组 394 ＋ 底栏 128 ＋ 最少留白 24`，三个数由尺子现读现算比对；`min()` 之前留了一行不带函数的退路给老安卓 XWEB）。原来那条 `.entry-wrap{margin-top:62vh}` 删了——"上面多一行就把整组顶下去"这条链上栽过三回。
- 右两枚那两个数**来自接口**：`api.getQuota().used` 与 `api.getMyCards().cards.length`，两个口各包各的 try（任一拉不到不许把另一格和这一屏一起拖挂），读不到画 0。点笔记那一枚 = 切到列表 tab；点卡片那一枚 = 切过去并落第二枚 tab，靠 `globalData.ixOpenCardsTab` 这一枚**一次性**标记（`index.onShow` 读一次就清，且只赢过"无条件复位"、赢不过 `keepView` 那一型）。
- **这两枚的口径＝全量，与列表页那个数不是一回事**（10-10 站长拍板：这一句写进规格，代码一个字不改）：
  - 「笔记」那枚 = `quota.py:40 used_count()` = `SELECT count(Note) WHERE user_id = 我`，**不带任何分类与搜索条件**。
  - 「卡片」那枚 = `/api/user/cards` 回的行数 = `NoteCard` 里**当前那一版**（`current()` 那道过滤），一篇最多一张；删掉留档就不计，重渲一次也只计一张。
  - 列表页右上/分类格里那些数是**筛后**的一叠（当前分类 ∩ 当前关键词），所以首页 12 而列表某一格 3 是**正常现象**，不是两处不同步。下一轮谁把这看成 bug，先看这一条。

- 展开时整组 `position: fixed`，左右内缩 `--sp-3`(24rpx)、底边 `bottom: 152rpx`（= 底栏 128 + 一条 24 的缝）。底栏几何一改，这里要跟着改（由 `验-录入面板沉底.js` 两头现读钉住）。

  原来这里是一条 `.container.entry-dock .home-swap{display:none}`（10-08 定的"只在收起态存在"），今天按他那句撤了。
  撤它不欠几何账：展开态那一组是 `position: fixed` 沉底的，不吃流内 margin，所以这一行露出来不会把面板顶高；
  收起态那一段流内高度照旧是 52rpx 那一档（下面那条账没动）。判据跟着从"展开时不占位"翻成
  **"展开态照样画，且顶边与收起态同一个数"**（差 ≤1px）——只判画没画不够，两屏各画一处就是他 11:2x 抓过的那种跳。

- **铺图时这一行抬在罩层之上**（10-09 拍甲，名单从三样变四样、10-10 又回到三样：标题、这一行、录入条）。判据在 `验-首页背景图.js`（整段捞出那条规则比名单，不用"多少个字符内出现 z-index:2"那种窗口写法——加一行就会假红）。

## 2. 两档高度（都是算出来再量过的，不是拍的）

| 档 | 高 | 什么时候在这一档 |
| --- | --- | --- |
| 收起 | **410rpx** | 默认（10-10 从 500 压进站长那圈红框） |
| 展开 | **490rpx** | 「文字」档原文框拿到焦点；或「照片」档小图 + ➕ 超过一行（>5 格） |

- 算式（静态尺子现读现算，10-10 深夜那批改完后的读数）：`面板 410 − 描边 2×2 − 上内边距 8 − 标签行 64 − 卡上边距 6 − 卡边框 2×2 − 卡内边距 2×30 − 下内边距 14` ⇒ **卡内可用 250.0rpx**（展开那一档 330.0）。标签行由"字号推出来的 77.4"改成**写死的 64**：撤掉卡里上面那一档 auto 边距省出来的高度搬给这一行（站长那句「把多出来的高度，放在三个tab部分」，见 §4 末那两条）。
- 最占地方的一态是照片那三枚圈：快门 180 + 那列间距 8 + 那行字（字号×1.35）= **220.4 ≤ 250.0**（余 29.6）。第二占的是文字展开那一叠：壳 160 + 开关 48+8 + 条 110 = **326 ≤ 330.0**（余 4）。所以**改字号、加控件、改列数之前先跑 `量-面板四态自然高.js`**（七个态 × 中英各量一遍，给"最后一块离面板内下沿"的余量，量不到就退出码非 0），再决定动不动那两个数。
- ⚠️ 上面那个"标签行按 1.6 而不是 WXSS 写的 1.2"的坑**这一批起不再进算式**——行高现在是一个定死的 `height:64rpx`，不再是字号推出来的。但那条平台事实仍然成立（微信给 `view` 的默认行高约 1.6），它现在是**上限的来源**：64 没有一次搬满（省出来的是 28.8，只取了 20.8），因为文字展开那一叠 326 只剩 4rpx 余量，行再高一点就顶出面板。两头由同一把尺子夹住（`验-统一录入条.js` 里"标签行比字高出一截"与"展开那一叠装得下"两条）。
- 卡内宽 **586**（10-10 面板内边距 32→24 让出来的 20rpx）：五列小图 564 ≤ 586 没变列数；滑动条轨道内宽 586 − 10 = 576，圆 90、左内缩 10 ⇒ 停在最右 `left: 476rpx`（旧稿 456），JS 常量 `SLD_MAX_RPX` 与这三个数由静态尺子现算比对。
- 展开只多一行（490 − 410 = 80）：**不再往上加**。
- **报错不占流内高度了**（10-10 深夜改的）：它是面板里的一枚浮层（`.hint-bubble`，`position:absolute` 在 `.panel` 内、输入框正上方），所以面板不必为每一态预留那一行。它顶在 `top:78rpx` ＝ 上内边距 8 ＋ 标签行 64 ＋ 卡上边距 6，正好贴着卡顶、不骑在标签行上；最矮那一档 52rpx，底边到 130，而框的中线在 162.5——**盖住框上沿但不挡字**。这几头都由 `验-统一录入条.js` 现读样式算，不抄这串数。
- **面板顶在屏内哪一条线（"不许挡人头"那条）**：压进红框之后按 rpx 算，收起那一档顶 **66.3%**、展开那一档顶 **61.0%**（旧稿两档是 55.0%／49.5%）。真跑那把的门槛**仍是 55%／49% 那两道地板**，不跟着往上抬——它守的是"别再长回去挡脸"，不是"就该停在这么低"；实测值由那条判据自己打出来。

## 3. 三档模式与各自的控件

**只有三个标签。** 相册不再是独立一档——它是「照片」那一态左边那枚小圆。`active` 一位说清当前那一档（`'' | 'photo' | 'url' | 'write'`），页面上没有第二个 `mode` 字段。

| 档 | 卡里画什么 | 提示词（全在框里，点进去就没了） | 提交 |
| --- | --- | --- | --- |
| 照片·没选图 | 三枚圈居中：小圆相册(105) — 快门(180，墨环 10) — 小圆链接(105)，每枚带一个字；那一排**垂直也居中**（10-10 站长那句「相册，链接高度居中对齐，目前有点往上」） | 无（这一态没有条） | 点圈直接开系统选择器 |
| 照片·已选 | 一横排小图 100rpx 见方 + ➕ 钉在最右端；序号 1…9 标在每张图左下角 | 无 | 右滑长条 |
| 链接 | 一个 `input` | `linkDesc`「公众号文章 / 网页链接」 | 右滑长条 |
| 文字 | **一层壳 ＋ 一个 `textarea` ＋ 一枚粘贴钮**（壳吃 `.field` 那套皮，收起一行 105、展开两行 160 写在壳上 `.field-write-2`；textarea 是原生组件、装不下子节点，那枚钮只能做它的兄弟） | `manualDesc`「把原文贴在这里，摘要自动生成」 | 右滑长条 |

- **这一屏没有标题格、没有分类选择器、没有「保存／清空／取消」那排按钮、没有四步指引。** 标题与归类在详情页「编辑」→ 亲自撰写那一页改（`pages/write/write.wxml` 两样都在，`验-统一录入条.js` 里钉着这条实据）。
- **粘贴钮有两枚，语义不一样**（站长 10-10 深夜「文字tab，里面输入框也要提供粘贴ICON，与链接tab一致」）：皮一致——同一个 `.field-paste`、同一支 `glyph-clipboard`、同一个 `t.paste`、都在格子里右端；语义**不一致**——链接是一行，贴进去就是替换；原文框可能已经有人打好字，贴进去只**接在后面**（`onPasteWrite`），不顶掉旧的。
- **文字那一档的字与链接那一档同一行高度**（他那句「文字tab里面的输入框里面的文字不是上下对齐」）：`<input>` 那行字由壳的 `align-items:center` 竖直居中，`<textarea>` 的字从自己内容顶顺着排，所以框给自己一份**上内边距 28rpx**＝`(壳 105 − 边框 3×2 − 行高 28×1.5) / 2`，两档字顶都离壳上沿 31.5rpx。这一档是**算出来的**，改了字号／边框／壳高就会红（尺子现读三个数比）。⚠ 配套一条：`height:100%` ＋ 内边距必须写 `box-sizing:border-box`，否则内边距加在 100% 外面、框变 129 高溢出壳，静态读不出来。
- 三枚标签的**按键面**（他 10-10 深夜「照片，链接，文字，三个Tab很难点，把按键区域扩大」）：`.modes{height:64rpx; align-items:stretch; gap:24rpx}`，每枚 `.md` 吃满这一行的高、左右各 `padding:22rpx` ⇒ 面约 100×64rpx（原来只有字那么大，约 43 高）。上限不由这一条管，由"展开那一叠装得得下"那条管。
- 三个标签只切视图，不顺手开相机（进来挑模式的人不该被系统选择器打断）。
- 点收起态那条胶囊 = 进「照片」（10-08 起默认档不再是文字）。
- ⚠ 那一排改成垂直居中之后，左右两枚下面那两个字（相册／链接）比中间那枚「拍照」**高约 11rpx**——环对环居中，字就跟着环走。他原话是"居中对齐"，稿上按圈的中心做的，这条取舍在 `docs/产品需求.md` §8.158 末尾写明过；要连字都齐得改成三列各自底边对齐，那是另一种排法。

## 4. 右滑才开始提炼（那一枚长条）

轨道 110rpx 高、**井那一档**底（`--cp-field`，与卡里那两枚小圆、输入框同一档）、**外圈 5rpx 与轨道同色**（10-10 之前那一圈是纸白＝快门那枚白环的同一笔；换浅面之后白环压白卡读不出来，改成同色一道，进度转成实心之后它仍在）。圆 90rpx，停在 `left: 10rpx`；行程到 `left: 476rpx`（= 轨道内宽 576 − 圆 90 − 内缩 10，JS 常量 `SLD_MAX_RPX` 与 WXSS 那三个数由静态尺子现算比对）。

四个态（效果图那份「补」排画的就是这六格）：

1. **待滑** — 圆在最左，**任何时候都是那一枚提炼橙**（`--cp-extract` = `#C4541F`）。这一格还没内容时**根本起不了拖**：`onSlideStart` 里 `!ready` 直接走一趟校验、说一句就 return。`.sld-off` 现在只把**旁边那句提示字**淡一档。以前"按不动"是把圆洗成灰来表达的，站长 10-10 深夜把锁从皮挪到了行为上（原话「拖动的圆ICON，要换成橙色，但如果上面的输入框里面没内容，不允许滑动圆ICON。链接与文字处理一致」）。
2. **拖动中** — 圆跟手指走（`touchmove` 用 catch 不吃页面滚动，位移按 `windowWidth/750` 换算成 rpx，小于 3rpx 不写 setData）；轨道仍白。⚠️ 圆的位置是模板字段 `knobRpx` 绑在 `style="left:{{knobRpx}}rpx"` 上，而这一枚是 `<template is="sld">` 画出来的——**`<template is>` 不继承页面 data，清单里漏一位不会报错、只会静默不跟手**（10-08 就漏过一次：清单递的是 `knobStyle` 而 JS 里根本没这一位，结果 data 一路走到 456、屏上那枚圆始终贴在起点，四张截图里都是左边那颗）。现在两头都有静态钉（模板用到的字段必须都在清单里、清单里的必须都在页面 data 里），真跑 `D3b` 量的是**屏上那一枚的实际左沿**而不是 data 里的数。
3. **就位** — 松手时若"到位 **且** 这一格真有东西"，圆钉在最右、颜色不变、字换成 `busyExtract`；半路松手一律回弹。"空着滑到底"那一支现在**进不来**（第 1 条把起拖挡住了），`onSlideEnd` 里那个 `&& this.data.ready` 留着只防"拖到一半内容被清空"那一类竞态，不当成第二条路径。
4. **进度** — 轨道从左边吃进实心色，宽度＝`fillPct`。这是**假进度**：服务端任务只有 `status`，没有百分比（`backend/app/services/queue.py` 的 `set_task_status`），客户端 2 秒轮一次（`utils/api.js` 的 `pollTask`）。曲线 `90 × (1 − e^(−秒/30))`，封顶 90%，接口回来才钉到 100%。站长原话「进度条不需要太精准」。
5. **完成** — 整条转实心、白环仍在、字转纸白 → 吐司 `extractSucceeded`「已存入笔记」→ 800ms 后跳详情页（这条时序与现网一字未改）。
6. **失败** — 圆回最左、轨道全白，那句错在**输入框上面那枚气泡**里说（几秒自己走）。

三档共用同一趟生命周期：`_extractBegin(kind)` → `_extractDone(noteId, patch)` / `_extractFail(err)`，进度表在成功、失败、`onHide`、`onUnload` 四处都停。

### 6.3 那一位人物与它的剪影（10-10 深夜换的切换方式）

他这一夜的原话是「两个人切换体验不太好，改为左右有人点击右侧人像切换，例如女人在前，男人就在右侧，用剪影淡灰缩小在右下，高度约为女的一半，在女的后面。如果点击男的，男的就切换在左边，正常高度位置，女的就缩到右边，与男的处理一致」，同夜又补「首页人物延续到笔记列表和卡片列表，放在框外面的左上角，如果首页是男的，框外面就是男的」。落码口径：

## 10. 写这一屏的尺子时量出来的九条平台事实（动尺子前先读这段）

1. **`mp.evaluate` 里 `pg.setData(一个数组)`，服务层 data 到位、视图层不跟**。对照过：同一趟调用里 `active`（标量）跟了、`previewImages`（数组）没跟；automator 侧 `page.setData` 跟；`setData({'previewImages[0]': …})` 路径写法跟。**所以往屏上喂列表只有两条路：走真入口（桩住 `wx.chooseMedia`，success/complete 一路发完）或用 `page.setData` + `page.callMethod`**；喂完还要轮询渲染层读数（`$$(sel).length` 到目标值）再开始量几何，否则后面每一条都在给上一帧打分。
2. **`createSelectorQuery` 不认子选择器 `>`、也不认逗号表**（`.card > view, .card > textarea` 回空数组）。按类名一枚一枚 `selectAll` 才行；名单漏一枚就是"量不到却一条不响"，所以"一块都没摸到"本身要当红（`Math.max(...[])` = −Infinity 会把"没被顶出卡外"那条**跑成假绿**）。
3. **`display:none` 的节点，`boundingClientRect` 回的是"高 0 的那一份"，不是 null**；而 `page.$$(sel)` 照样回 1。判"整个不渲染"要按高度判（`!rect || rect.h < 1`）。
4. **`wx:key="*this"` 撞键，那一串 `wx:for` 整个不渲染**（四张同一个路径 ⇒ 屏上是空态）。真机上 `chooseMedia` 回来的路径各不相同，所以这不是产品问题，但**尺子造的假路径必须互不相同**。
5. **同一时刻只能有一把尺子共用 9431**：另一批在后台跑（它会 `cli quit` + 重开工具），前台这把连的会话会被半路抽掉，报回来的是一整节假红（`A1/A2/A3/A4` 从第一条就红 + 连接类报错）。看到"整节全红 + 连接崩"先怀疑会话被抢，等前一批跑完重跑一次再下结论。

6. **`mp.switchTab(url)` / `mp.reLaunch(url)` 吃的是字符串**，不是 `{ url }`：传对象会被套成 `{url:{url:"…"}}` 再交给 `wx`，报回来的是一句查不出东西的 `Uncaught [object Object]`（10-10 在这把新尺子自己身上踩的，当时误以为是产品崩了）。同一句话也适用于"页面报错帧"——`Connection` 对没有 id 的帧走 `emit(method, params)`，`'error'` 没人听时 Node 会把参数直接抛出来，所以拿到 `mp` 之后先挂一个 `mp.on('error', …)`。
7. **全局样式表同名会静默补进你的盒子**：`app.wxss` 的 `.blk`（笔记列表那枚 176 见方的分类色块，带 `overflow:hidden`）命中了新写的同名组，把整组裁成 176、右列算成 0。**这类翻车静态判据一条都测不出来**（它量的是页面样式表里那些数，那些数全对），只有屏上量帧的真跑看得见——所以新类名一律带前缀，并由 `验-第一屏三块.js` §11 从源头堵。
8. **`hover-class` 那一帧 automator 量不到**：`element.tap()` 只派发一次合成点击，不走 `touchstart`／`touchend`，所以按下态的放大在自动化里永远不出现，截也截不到。静态只能钉"名字两头对得上"（markup 里挂的每一枚 hover-class 在样式表里有对应规则、且样式表里没有没人挂的孤儿），**手感和这一帧只能上真机**。
9. **尺子自己也要被钉住"没在空转"**：三条都是这一轮补的——① 色扫那种"匹配不到就是没有抄色"的写法，选择器正则少写一个分支就整组假绿，所以要先判"真扫到了 N 段"；② 判"有没有抄色相"要按**饱和度**算，只匹配 `#rrggbb` 的话 `rgba()`／三位色／八位色全从指缝里过去；③ 类名收集要连 mustache 三元分支里那几枚一起收（`{{active ? 'entry-dock' : ''}}`），但**整枚来自数据**（`{{themeClass}}`）与**拼接**（`glyph-{{sldIcon}}`）静态确实量不到，那两类改由真跑读元素的 `attribute('class')`（`验-首页背景图-真跑.js`）。
