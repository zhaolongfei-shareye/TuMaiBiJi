## 1. 逐条对照：现网是什么样 → 这次改成什么

### C1 改到当前面板内完成，不跳转
- **现网**：笔记列表面板顶那一行左端那枚井格图标（`index.wxml:71` `.ixl-ic` → `goCategories`，
  `index.js:483` `wx.navigateTo('/pages/categories/categories')`）跳一整页去管理；
  那一页有增、改名、删、↑↓ 四件事（`pages/categories/`，170 行 js）。
- **改成**：按那枚井格＝在**同一屏**里把分类那一排（`.cats`）切成"管理态"：分类名右侧长出输入框、
  每枚右上角长出 ×、可以拖动。再点空白退出管理态。**不新增页面、不跳转。**
- **验收**：管理全程 `getCurrentPages().length` 不变；`goCategories` 不再走 `navigateTo`。

### C2 分类图标右侧一枚输入框，空格分隔＝一次新增多类
- **现网**：只有那一页底部一枚「新建分类」按钮 ＋ 一个一次只填一个名字的弹窗。
- **改成**：管理态下，**面板顶那一行里、井格 icon 的右手边**挂一个输入框（他原话「在分类ICON右侧」；
  我上一版把这枚框写到"芯片那一排末尾"是读错了落点，落点按他这句走）；
  输入 `读书 旅行 育儿` ⇒ 按空格切三段，一次建三条。
  切完之后逐条走**同一个**创建接口（后端一次只收一条名字）。
  框里那一句还没落地时就先变成屏上的"待建格"（`bindconfirm` 与 `bindblur` 都算落地），
  所以点空白那一下的次序是：先 blur 把词落成格 → 再 tap 触发保存。
- 去重：同一条里重复的词只留第一次；与服务端已有的同名 ⇒ 那一条被服务端拒（`create_category`
  现在就拒同名），拒掉的那条在屏上说明是哪一条，不许整批静默失败。
- 皮复用搜索那一条 `.srch`（同一行、同一种输入框不该有两张皮），所以 `style="{{searchSkin}}"`
  那一串内联变量**不许省**：省了 `--chrome-bg` 就是 IACVT 透明，框在屏上直接消失。
- **验收**：输入三个词 ⇒ 列表回三条，且三条都排在原有分类之后（见 C7）。

### C3 已有的每枚右上角一个 ×，点 × 删除
- **现网**：删除按钮在那一整页每行的操作区里（`t.delete`），点了直接调 DELETE 接口。
- **改成**：管理态下每枚分类右上角一枚 ×。

### C3-b 删除要二次确认（他补的那一句）
- **现网**：**没有**二次确认——`onDeleteTap` 直接发 DELETE。
- **改成**：点 × 之后先问一句再删。问话要说清"删了之后这一格里 N 篇笔记会归到未分类"——
  这一句是这条链上唯一不可逆的地方（笔记不会被删，但**归好类的关系会丢**，且没有撤销口）。
  落点：`wx.showModal`（系统弹窗，不是自画的那层），确认键写「删除」，取消键写「取消」。
- **N 从哪来**：服务端 `GET /api/categories/` 每行多带一列 `note_count`（一趟 GROUP BY 给齐全部格子，
  不在循环里逐格 count）。客户端手上只有已经加载的那几十篇，拿它当 N 就是假话。
  读不到那一列（老服务端）⇒ 回落到**不报数**的现网那句 `deleteCategoryConfirm`，不编一个数。
  这一列是我自己决定加的，他没拍过 ⇒ 记在 §4。
- **负面清单**：不许做成"长按 × 才删"这种没有话术的隐藏手势；不许删完才弹一句 toast。

### C4 按压拖动排序
- **现网**：↑↓ 两枚按钮逐步挪（`onMoveUp`／`onMoveDown`）；服务端 `/api/categories/reorder`
  已经收一个 id 数组整批写 `sort_order`（`categories.py:166`）。
- **改成**：管理态下按住一枚分类拖动换位置。松手只改本机顺序，**保存那趟才发 reorder**（见 C5）。
- **落码的做法**（两处实测坑，写死在这儿，别下一次又拿旧的那套试）：
  ① `longpress` 事件在部分机型 `touches` 是空的 ⇒ `touchstart` 先把手指那一处的 `clientX` 存下来当备胎；
  ② 换过一次顺序之后**必须重新量**（数组一调序，手上那份 rect 全部过期），而排布是渲染层算的，
     `setData` 回来那一瞬量到的还是换之前的位置 ⇒ 每次换完等 30ms 再量。一次移动最多换三格。
- **没验到的那一半（要说清）**：静态尺子钉的是"三把事件挂在同一节点、换位的几何判据与请求次序"；
  **手指真按下去平台会不会把 longpress→touchmove 这套派发给这一枚**，本机没验过
  （automator 只有 `trigger`，没有触摸原语；现网包又指着 `api.agentsbin.cn`，不能拿它建格删格）。
  这一条只有真机能定，等他要走真机那一趟时一起看。
- **验收**：拖完退出管理态再进来，顺序还在（说明 reorder 真发出去了，不是只改了本机 data）。

### C5 点页面空白区自动保存
- **现网**：每一个动作（增、改名、删、↑↓）当场发一次请求。
- **改成**：管理态里的改动先落本机，点空白退出时一次批量提交：新增的按顺序 POST、
  删掉的按顺序 DELETE、顺序变了发一次 reorder。
- **落码的次序是 删 → 改名 → 建 → 排序**，理由写在 `pages/index/index.js` 那段里：
  改名与建格会被重名挡（可重来），删那一趟几乎不会失败；而只有前三步全成才发最后那一次 reorder
  （新格还没拿到身份 id 时，那份"顺序"是编出来的，不能发）。
  没成的那几条**点名**报（读的是他自己打的 `name` 那一栏，不是服务端那句 detail——detail 万一是数组，
  toast 上就出现 `[object`），人留在管理态里；先 `loadCategories()` 把成的那些落定，再把没成的贴回草稿。
  没成的新建回到末尾（他原来拖的位置随这一次失败丢掉，不假装还在）。
- **一点收尾**：他正筛着那一格被删掉 ⇒ 筛选收回「全部」重拉一次，否则屏上是一片空加一个还在筛的状态。
- **负面清单**：不做"每敲一个字就发一次"的自动保存；也不做"退出页面才保存"（他点的是空白区那一下）。

### C6 私密分类禁止删除
- **现网**：`delete_category`（`categories.py:201-211`）**只在格里还有笔记时**拒绝删那一格；
  空格删得掉。判据是分类名字面「私密」（`app/core/private_access.py`），没有标志位。
- **改成**：无条件不许删——服务端不管格里有没有笔记一律 400；客户端管理态里那枚 × **不画**在私密那一格上。
- 连带：改名与拖动也照今天的样子只管"位置"，**私密那一格的名字不改口径**（见 D-c2）。
- **验收**：拿接口直接对私密那一格发 DELETE ⇒ 400，且屏上那一格没有 ×。

### C7 新用户默认四类＝灵感／生活／工作／学习
- **现网**：注册时**零播种**。新用户分类表是空的；「私密」那一格只在设了密码之后由
  `_ensure_private_category`（`user.py:174`）跟着补出来。
- **改成**：注册那趟补四条，`sort_order` 依次 0/1/2/3。四类与「私密」是**两回事**：
  四类是默认分类、删得掉；私密那一格是那道锁的把手、删不掉（C6）。
- 只给**新用户**：存量账号不回填（回填＝往别人已经归好类的库里塞四格，那是他的库不是我的）。
- **验收**：新建账号第一次进列表，分类那一排是「全部 灵感 生活 工作 学习」（＋设了密码之后的私密）。

### C8 笔记原分类删除后自动归入未分类
- **现网**：**已经这么做**——`delete_category` 在删格之前把名下笔记的 `category_id` 置 NULL
  （`categories.py:212-216`），未分类在界面上就是"没有分类"那一档。
- **这次不动它**，只在清单里钉住"这条不许被顺手改掉"。

### C9 新增分类默认排最后
- **现网**：**已经这么做**——`create_category` 取 `sort_order = 该用户分类数`（`categories.py:86-87`）。
- **这次不动它**；C2 一次建多条时按输入里出现的先后依次排最后。

### C10 原「设置」里的分类入口关闭
- **现网**：两处入口——① 笔记列表那枚井格（这处**保留**，改成开管理态）；
  ② 「我的」页那一行 `categories: '/pages/categories/categories'`（`me.js:256`）＝他说的"原设置的分类入口"。
- **改成**：撤 ②。`pages/categories/` 那一页的文件与 `app.json` 里的注册**先留着不删**（理由见 §4）。

### C11 分类名称自动翻译
- **现网**：**零口**。全站没有"翻译"这件事的独立接口——只有一条提炼的 LLM 路
  （`services/llm.py`：`extract_knowledge` 走混元云函数，语言那一档写在 system prompt 里）。
  界面语言只有中／英两档（`utils/i18n.js` 两份字典 ＋ 首页那枚 中／EN 角标）。
- **改成**：一格分类存三个字段——`name`（他自己打的字，身份判据、重名判据、私密判据都还看它，**不动**）
  ＋ `name_zh` ＋ `name_en`（两档显示用，可空）。
  显示：界面中文 ⇒ `name_zh || name`；界面英文 ⇒ `name_en || name`。
  **译不了就维持原文**＝那一档留空，客户端自然回落，屏上不出现空字符串、也不出现 `[object]` 这种占位。
- 写入时机：新建与改名那两趟各译一次，结果存进那一行 ⇒ 之后切语言零调用、零延迟。
- 默认四类（C7）**不调模型**：那四个词的中英是常量，直接随播种写死。
- **负面清单**：
  - 不许把译文写回 `name`（那是身份，写回＝他的分类名被我改了）；
  - 不许每次渲染都去现译（一屏十几格 × 每帧一次调用＝成本与延迟都爆）；
  - 存量分类不许在读取路径上顺手补译（读接口挂上模型＝读一次慢一次，且模型挂了读接口跟着挂）；
  - 翻译失败不许把整次创建带崩：**名字先建成，那一档留空**，屏上按原文显示。
