# 后台《用户隐私保护指引》填写文案

给谁用：微信公众平台 → `mp.weixin.qq.com` → 设置 → 服务内容声明 → 用户隐私保护指引 → 修改。

为什么必须先填再提审：平台原文是"仅有在指引中声明所处理的用户信息，才可以调用平台提供的对应接口或组件。若未声明，对应接口或组件将直接禁用"。也就是说不填的后果不只是驳回——发布之后相机、相册、剪贴板这三条功能会在用户手机上直接失效。体验版目前不受这条限制（1.1.2 那轮真机验过相机相册都通），所以这个雷是发布之后才炸。

**下面的清单是按代码里实际的调用点扫出来的，不是照着模板抄的。** 每一项都给了调用位置（有的能力现在有两处调用点，都列出来了），勾之前可以自己对一遍。勾选项的**文字**以后台实际列出的为准（微信这份枚举改过几次），按含义对，不要因为我这里写的名字和后台不完全一样就换别的一项。

_2026-09-24 又按当前代码逐项重核了一遍。**有两处变了，改的时候看清楚**：①「分享形象」这一版多了从相册挑一张图当头像，所以相机和相册两项的用途说明都扩了；②写入相册的调用点行号变了（海报引擎那轮把 share.js 拆薄了），行号以这一版为准。另外全项目重扫 `scanCode` / `getLocation` / `chooseLocation` / `chooseAddress` / `choosePoi` / `getPhoneNumber` / `createRecorderManager` / `getUserProfile` / `getUserInfo` / `chooseAvatar` / `requestPayment` / `wx.authorize` 仍然零命中，没有多出第五项要声明的能力。_

## 要声明的四项

### 1. 摄像头 / 相机 —— **这一格后台加不进去，也不必加（2026-09-25 实测推翻本节原判断）**

> **结论先说**：`增加信息类型` 的弹层里「摄像头」这一项勾得上（`checked=true`），点「确认」之后表单**不会多出一行**，连着试两次一样。平台自己扫代码版本也只识别出相册写入／剪切板／选中的照片或视频三项，没识别出摄像头。
>
> **为什么对得上**：全项目没有 `<camera>` 组件、没有 `wx.createCameraContext`（`grep createCameraContext|miniprogram/` 零命中）。两处"拍照"都是 `wx.chooseMedia({ sourceType: ['camera'] })`（`create.js:206`、`profile.js:133`），微信把 chooseMedia 这一族归在**「选中的照片或视频信息」**底下，不是「摄像头」。所以当场拍照这件事写在下面第 2 项里，第 2 项的措辞已经补上了"或点「拍照」当场拍一张照片"。
>
> 原来把「摄像头」列成必填一项是**多报**：页面顶部原话是"根据法律规定，开发者仅处理实现小程序功能所必要的信息"，而"若小程序实际情况与本指引内容不符，开发者需承担由此产生的法律责任"——声明一个代码里没调的信息类型，和不声明一个调了的，是同一种错。下面这段留档，不再往后台填。

~~用途说明（粘这段）~~（已废弃，理由见上）：

> 用于「截图转笔记」里拍照识别文字的入口，以及在「我的 → 分享形象」里现拍一张照片当海报头像。前者照片只用于识别其中的文字，识别完成后不在服务器保存图片、不写入数据库；后者拍完的照片只写进这台手机的本地目录，不上传、不进入服务器。不需要此权限时，小程序其余功能（查看、搜索、编辑笔记）均可正常使用。

调用点：两处。① `miniprogram/pages/create/create.wxml:50`（`data-source="camera"`）→ `create.js:206` 的 `wx.chooseMedia({ sourceType: [source] })`；② `miniprogram/pages/profile/profile.js:133` 的 `wx.chooseMedia({ sourceType: ['album', 'camera'] })`（分享形象选头像，拍照和从相册挑走的是同一处）。

### 2. 选中的照片或视频信息（相册读取）

用途说明：

> 两个用途。一是从相册选择截图进行文字识别：图片经 HTTPS 上传到我们自己的服务器，只在进程内存中暂存，识别完立即丢弃，超过 30 分钟未提交的批次自动作废，服务器不把图片写入磁盘、不存入数据库，也没有图片对象存储。二是从相册挑一张图当分享海报上的头像：这张图只复制到本机的小程序本地目录（合计上限 10MB，用户在「分享形象」页点「去掉」或换一张时即刻删除），**不上传到服务器，服务器上没有任何用户图片**。

调用点：与上一项同样两处——`create.js:206`（截图）与 `pages/profile/profile.js:133`（头像）。全项目 `wx.chooseMedia` 只有这两处，没有第三处。**这一项现在还要兜住"当场拍照"那件事**（因为摄像头那格加不进去，理由见上一节），措辞已按这个改过。

### 3. 相册（写入）

用途说明：

> 用于把生成的分享海报图保存到您的相册，方便您转发或留存。仅在您主动点击「保存到相册」时调用；拒绝授权不影响小程序其余功能。

调用点：`miniprogram/pages/share/share.js:145` 的 `wx.saveImageToPhotosAlbum`（全项目唯一一处）。

### 4. 剪贴板

用途说明：

> 读取：仅当您在新建页的链接入口点击「粘贴」时读取一次，用于取回您自己复制的网页链接。写入：仅当您点击「复制来源链接」或复制反馈邮箱、公众号名称时，把对应内容写入剪贴板。除这些您主动触发的操作外，不读取剪贴板。

调用点：读取 1 处，`miniprogram/pages/create/create.js:103` 的 `pasteUrl()`，只往链接输入框里填；写入 4 处，`pages/detail/detail.js:175`（复制这条笔记的来源链接 `source_url`）、`pages/share/view.js:57`（扫码落地页复制来源链接）、`pages/about/about.js:159` 与 `pages/me/me.js:88`（两个同名的 `onCopy`，复制页面上 `data-value` 给的联系方式文本）。

## 其余必填字段（这三格要说清三件事，别只写一句）

> **2026-09-25 更正这一节的用法（站长拍的）**：后台这个表单**没有**"目的/方式/范围"那种自由文本格，它只有"每种信息类型 + 一个用途框"。所以下面第 2、3 格**不再单独成项**——站长原话"我们不涉及分享，我们所有操作都是用户自主行为"，把"分享出去的公开页""邀请关系与额度"写成独立的信息类型，等于宣称我们收集了本来不存在的东西。这两段留在这里当**对照口径**（小程序内《隐私》第 5、7 条要能对上），不进表单。表单里实际加的是**「发布内容」**一项，用途里带一句"用户自己选择把某一条公开出去时……我们不代替用户发布"。另外**「用户信息（微信昵称、头像）」这一项不许勾**：分享图上那行"原创作者"是用户自己在「分享形象」里填的名字（`shares.author_name`，见迁移 `b7d2f4a9c316` 的说明），不是微信昵称，我们没调过 `getUserProfile` / `chooseAvatar`。

**1）开发者处理的信息的目的、方式、范围**

> 目的：提供把链接与截图整理成个人知识笔记的服务。方式：用户主动提交内容 + 服务端文字识别（自建开源 OCR）+ 大模型摘要（腾讯混元，经微信云开发调用）。范围：微信登录标识（OpenID，仅用于把笔记归属到本人，不下发给客户端）、用户自己存进来的标题/摘要/要点/标签/分类/来源链接、用户上传用于识别的截图（只在内存暂存、识别完丢弃、不落盘不入库）。分享海报的头像与海报本身都在用户手机上本地生成，服务器不保存、也不接收任何一张用户图片。

**2）邀请关系与额度（后台一般没有现成枚举项，写在上面那格的"范围"里）**

> 用户把小程序分享给好友时，链接上带邀请人的用户序号；每人名下 100 篇笔记的基础额度，好友**真的存下他第一条笔记**时给邀请人加 10 篇——两条都算：他自己动笔写一篇，或者把分享页上那篇转存进自己的库。同一位好友只算一次，同一篇笔记也只算一次；只是点开看看不记。服务端为此只保存"谁邀请了谁、这笔账来自哪一篇笔记"两个序号，不读取昵称、头像，不调用任何用户信息接口，邀请关系只用于结这一笔额度，不用于推送或营销。

**3）分享出去的公开页（这条最容易被审核员追问，一定要写明）**

> 用户可以对某一条笔记主动生成分享。分享后，该条笔记的**标题、摘要、标签、来源链接**会通过一个免登录的公开链接对外可见（任何拿到该链接或那张小程序码的人都能看到）；用户另外主动生成并保存的卡片图上还会印出该条笔记的要点。这是用户主动操作的公开，不是我们向第三方提供数据；用户删除该条笔记后该链接立即失效（实测回 404），**修改该条笔记会同步更新公开页内容**（2026-09-23 修的：此前公开页是快照，用户把标题里的手机号删掉后那张已发出的卡片扫开仍显示旧内容），用户也可以在笔记详情里点「撤掉分享」主动关闭这一条的公开（2026-09-24 加的：关闭后原来那个链接和原来那张海报上的码当场扫不开，重新分享会换一个全新链接，旧链接不会被救活）。除用户主动分享的这一条外，其余笔记一律按登录身份隔离，越权访问返回 404。**分享者昵称也在生成分享图这一刻随快照对外可见**（扫码页上那行"原创作者：某某"就是它；用户不点生成分享图，昵称一直只留在他自己手机里）。另外扫码的人可以点「存到我的笔记」，把这份公开快照**整份抄进他自己的笔记库**——抄过去之后归他所有，原分享被撤掉或被删除都不影响那一份副本，副本上会永久留一栏"转存来源"记录原创作者与转存时间，那一栏不可编辑、只能整条删除。

_对外的四个字段以服务端 `ShareResponse` 为准（title / summary / tags / key_links），别照"关于页"的措辞写，两处不同一字就差在这里。_

## 和小程序内文本的关系

小程序里「我的 → 关于图麦笔记 → 隐私」那一栏（源码 `miniprogram/pages/about/about.js` 的 `const PRIVACY`，共十条）是给用户看的，本文是给后台的，**两边口径必须一致**，否则审核员对照时会认为其中一份不实。已逐条对上：

- 第 2 条「手机权限」写的相机、相册（含分享海报头像那张，明确不上传）、剪贴板，对应上面要声明的四项（相册拆成读与写两项）。
- 第 1 条「不收集通讯录、位置、麦克风、设备标识和浏览记录」，对应上面「不要勾的」。
- 第 4 条写明摘要会交给腾讯混元，对应"方式"那一格。
- 第 5 条「可见性与删除」写明分享出去的公开页、删除即失效，以及「撤掉分享」这条主动关闭的口子（旧链接和旧码当场扫不开，重新分享换新链接），对应上面第 3 格。
- 第 7 条「账号与额度」写的是"每人 100 篇基础、好友存下他第一条笔记（动笔或转存都算）给邀请人加 10 篇、同一篇只算一次、带来几个人不限、逐条删除与自助注销"，对应上面第 2 格。⚠ 这一格 2026-09-24 一天内改过两轮（下午按"取消 100 上限"填、当晚站长又定回"100 篇基础 + 分享得 10 篇"），**后台若已按中间那一轮填过必须再改一次**，否则声明与实际处理不一致会被硬拦；一律以本文这段为准。

改动了后台的声明范围时，记得同步改 `PRIVACY` 那一段并重新出包。
