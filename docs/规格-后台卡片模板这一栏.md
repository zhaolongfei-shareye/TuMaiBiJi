# 规格 · 后台「卡片模板」这一栏

一句话：这一栏管**哪几套卡片在被下发、叫什么、排第几、要哪个包才给**，不管卡片长什么样。

正本方案在 `docs/方案-cn后台资产管理.md` 的 P1；这一页写的是"今天真长什么样"。
站长 2026-10-15 一句「先补笔记模板管理界面」开工。

## 在哪

`https://api.agentsbin.cn/wtsj/ops` → 输管理口令 → 左栏「配置」组里那条**卡片模板**。
进去第一张卡是三个数（线上／草稿／已下架各有几套），往下**一行一套**，按排序从小到大排。

## 一行长什么样

| 位置 | 是什么 |
| --- | --- |
| 行首 `card` | 库里那个 `template_id`，与客户端 `utils/poster.js` 那套 id 同名，**只读** |
| 那枚圆角标签 | 三态之一：线上／草稿（不下发）／已下架 |
| `分组 classic` | `group_key`，出处是客户端那份分组名单，**只读** |
| `hash 6afcdbb3` | 配方算出来的 `content_hash` 前 8 位，客户端拿它当缓存键，**只读** |
| 那一句绿／灰话 | 这套今天下不下发 |
| 出图 X 张／其中当前挂着 Y 张 | 数 `note_cards` 的 `tpl`；与「数据 → 模板热度」同一出处同一口径 |
| 四个框 | 中文名、英文名、排序（小的在前）、最低包版本 —— **这一栏只有这四样能改** |
| 保存这几项 | 只把**跟刚读出来的不一样**的那几项送上去；一个字没改会当场说"这一行一个字都没改" |
| 下架这一版／上架这一版 | 只送 `status` 一项，不与四个框混在一次提交里 |
| 配方（只读，N 步） | 展开是那份 JSON 原文，纯 `<pre>`，**页面上没有任何能输入配方的地方** |

## 改完什么时候生效

- 存库即生效于用户那道口 `GET /api/poster/templates/` 的回体（顺序、叫法、套数当场跟着变）。
- 正在用的用户**不会当场变**：客户端在冷启那趟拉一次，下一次冷启读到的才是新的。
- 最低包版本由**客户端自己筛**（`utils/appInfo.js` 那个常量），服务器不按 query 参数筛——
  "谁的包够新"只有客户端知道，服务端再算一遍就是第二份会不同步的真相。

## 挡在门口的几种情况（都会退回，一个字都不写）

| 情况 | 屏上那句 |
| --- | --- |
| 排序填了非整数 | 排序格式不对 |
| 排序超出 0～9999 | 排序要在 0～9999 之间 |
| 版本号不是三段点分 | 最低版本号要写成 1.9.26 那样三段点分数字，收到的是「2.2」 |
| 名称空或超长 | 中文名 不能是空的／中文名 超了 40 字 |
| 一次提交里有一项不合格 | 整条不生效（先全部校验、后一次性落笔，不做"改一半"） |
| 同一套已有一版在线上，还想再上一版 | 这套模板已经有一版在线上（id=…，hash …）；先把那一版下架，再上这一版 |
| 状态给个闭集外的词 | 状态只认 live／draft／archived，收到的是「on」 |

**撞车那一条不自动归档在位的那一版**：归档等于替他决定"旧那版不再下发了"。
库里那条部分唯一索引（`ux_poster_templates_one_live_per_template`）是第二道牙。

## 加一套新模板走哪条路

不在这一栏。走纯数据那条：`backend/seed/poster_extra/` 放一份 JSON →
`docs/工具/跑新模板流程.sh` → 重新生成种子 → 开闸部署，正本见 `docs/流程-加一套卡片模板.md`。
这一栏只负责把已经进库的那套排上号、起个名、放上线。

## 这一栏没做的两件事

1. **配方在线编辑**——方案里的 P2，唯一一个"不发版就能改用户看到的画"的口子，没拍开。
   界面上连落点都没有（判据钉着：全页只有一枚 `textarea`，那是 Tips 那一栏的）。
2. **后台预览缩略图**——P1 原清单里有这一条，**没做**：`poster_templates` 表没有存缩略图的列，
   加一栏要迁现网库；而画面是客户端那份手工解释器画出来的，服务端画不出预览。要做得单独拍。
