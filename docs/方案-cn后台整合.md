## 1. 一句话回答

**两扇门、二十个后台接口、两套身份；其中五个接口有后端没界面——正好都是"数据分析"那一类。另有七件该有后台的事，今天一件都没有。**

| 量的 | 读数 |
|---|---|
| 后台页面（能进的门） | **2 扇**：`https://api.agentsbin.cn/admin.html`（标题「图麦克管理后台」，实测 200／23,872 B）＋ `https://api.agentsbin.cn/wtsj/ops`（标题「运营图后台 · 图麦笔记」，实测 200） |
| 后台接口 | **20 个**＝图麦克 **16**（`image-service/app/main.py:1191/1221/1286/1310/1338/1445/1456/1478/1553/1576/1636/1674/1704/1734/2632/2646`）＋ 图麦笔记 **4**（`app/api/routes/admin_ops.py:51/72/79/105`） |

## 2. 这两扇门各自能干什么（照界面真有的动作列，不美化）

**图麦克管理后台**（商业化那条线：钱、用户、订单、额度）
- 登录 / 忘记密码 / 改密码
- 总览：总用户数、今日访问、本周新增、图片处理总数、今日处理、VIP 兑换数、未使用 VIP 码、今日事件
- 用户列表 · 邀请码管理 · 支付记录 · 生成 VIP 邀请码
- 后端已经写好了但界面上没有入口：**额度漏斗**（`/admin/stats/credit-funnel`）、**API 指标**（`/admin/stats/api-metrics`）、**支付对账**（`/admin/payments/reconcile` 与 `/reconciliations`）

**图麦笔记运营图后台**（这一扇只管两张图）
- 登录（`.env` 里的 `ADMIN_TOKEN`）
- 上传（JPG/PNG，≤400KB、长边≤1920）→「发布这一张」→ 历史里点任一张就是「回滚到那一张」→「停用」（小程序退回包里那一张）
- 备注（历史里显示）、冻结状态提示（`MP_ASSETS_FREEZE=1` 时"现在怎么改都不影响线上"）
- **数据分析：零**（后端 `routes/` grep `stats`／`analytic`／`统计` 零命中；指标集在 §8.248 那份规格里，未开工）——**这句到 10-15 起不成立，见页首那条**

## 4. 整合路线（分三期，建议照这个顺序）

### 一期｜先把已有的数掏出来，不碰鉴权、不碰钱（我建议这期我直接开工）
1. **给图麦克那四个"有接口没界面"的能力补入口**——额度漏斗、API 指标、支付对账 ×2。`_trusted_admin` 的验票逻辑一行不用改，纯前端加四块卡片。**他要的"数据分析"，有一半是这件事。**
2. **我们这侧加 §8.248 的 A 档五枚**（新增笔记剔除 `preset`、来源分布、**转存量**、模板热度榜、邀请对账）。零新列、零迁移、零对外文本改动。
3. 门户先不动，两扇门各自顶部挂一枚对方的链接——**这一步只是让他少记一个网址**。

### 二期｜一次登录（这才是他最初那句"登录一次就行了"）
- 做法：**图麦克的账号当主身份**。登录成功后，除自己的票外，再签一枚带 `scope=wtsj.ops` 的短命票给运营图这一侧用；我们这侧 `admin_access.py` 改成"只认带 scope 且带 `atk` 指纹的票"，`ADMIN_TOKEN` 降级成**这台机器的应急钥匙**（口令为空一律 503 那条纪律留着）。
- 代价说清：① 两台服务要共用一枚签名钥匙，泄露面合并；② `atk` 指纹与 scope 两条判据必须在**两边都实现**，只做一边就是"换了口令对面旧票还能用到自然过期"；③ 图麦克那侧要有"签发跨线票"的写口，属于改别人的线，**要他点头**；④ 前端现在是 localStorage＋`Authorization`，统一走 cookie 就得补 CSRF——**建议维持 `Authorization`，不引入 cookie**。
- 顺手补 G7：加"第二个管理员"与按 scope 分权，否则整合完还是一把钥匙走天下。

### 三期｜补空白，按刚需排序
1. **G1 举报处置先做**（合规缺口，不是便利问题）：一张**人工**改 `hidden` 的管理口 ＋ 后台里"待核队列"，处置动作留痕。**别把当初两条决策改反**：① "一条举报就自动下架"是 `test_landing_page.py:240` 钉死不做的，要加的只是"人审之后由人按下"；② 举报页那句"撤了还收不到"的措辞在 `landing.py:71` 与 `report_ledger.py:41` 有交代，动之前先读那两处。
2. **G3 任务历史**：把 `jobs` 接上电（列都齐、零迁移），历史从今天起算。
3. G4／G5／G6 最后：模板开关与用户管理一开放就变成"能伤到真实用户"的面，要单独设计权限与审计，**不要跟这期一起顺手做**。

## 5. 三条红线（整合不许越过的）

1. **钱那侧不能降格**：图麦克后台管订单、支付、额度，必须保留"账号＋可追责"的身份，**不许为了统一登录把它换成共享口令**。
2. **两条产品线的用户数据不许同表互查**：图麦克的用户/支付与图麦笔记的笔记/分享是两套对外隐私承诺（各自的《隐私保护指引》文本不同）。整合的是**入口和登录**，不是**数据池**。
3. **后台不许出现任何能指到具体人的跨线画像**（比如"某付费用户在我们小程序里存了哪几篇"）；A 档那些指标一律只出聚合数。
