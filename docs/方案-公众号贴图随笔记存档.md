第一轮（口径）：

从这五句直接钉死的六条：

- **只存，不读内容。** 贴图不进 OCR、不进摘要／要点／标签那一步。提炼链路一个字不碰（第 1 句）。
- **存放走现网那一条，不另起炉灶。** 对象进**云开发存储**，账记进 `assets` 表，`object_key` 存 `cloud://` fileID，字节／配额／私密／公开页露图／删除全部复用现网那一套，**不新建第二套图片存放**（第 2 句）。
- **入口不新加。** 默认自动，不做"要不要存图"的开关、不做选哪几张。
- **要带来源，形状照转存那一篇。** 来源记进现成那枚 `notes.imported_from`，界面那一格读现成的 `share_author_name`（详见第五节，第 3 句）。
- **允许分发。** 因为来源已经带上了，别人那张图**可以在公开分享页露出**——我上一版列的那条"要不要允许二次分发"这一格作废，拍的是"允许"（第 3 句）。

### 我实测过的防盗链（这一条决定"能不能只存 URL 不转存"）

拿一条活的 `mmbiz.qpic.cn` 图（从掘金那篇防盗链文章里挖的），同一对象打四次：

| 请求头 Referer | 结果 |
|---|---|
| 不带 | **200，921,569 B，image/png（原图）** |
| `https://mp.weixin.qq.com/` | 200，921,569 B，同一张原图 |
| `https://juejin.cn/` | 200，**2,090 B，image/jpeg（占位图）** |
| `https://api.agentsbin.cn/` | 200，**2,090 B，占位图** |

两条结论，都直接影响写法：

1. **服务端下载可行**（不带 Referer，或把 Referer 设成 `mp.weixin.qq.com`）。
2. **"只把 URL 抄进笔记、展示时外链"这条路不成立**。而且它阴：状态码是 **200**，按状态码判成败会把那张 2KB 的占位灰图当正文图存进笔记——这是一条典型假绿。**判据不许只看状态码**，要同时校 `content-type` 是 image/*、字节数下界、以及解出来是不是真图（现成那枚 `_image_format(data)` 在 `routes/ingest.py`，可借同一个形状）。
   - ⚠ 没实测的那格：小程序 `<image>` 组件里加载这串 URL 会不会也被换成占位图（它发出去的 Referer 是 `servicewechat.com` 域，按同一策略推断是占位图）。**推断，不是结论**。反正走"转存"这条路之后展示的是我们自己的 `cloud://` 对象，这一格就不必验。

## 三、要做的是三段，落在后端一处

抓 → 存 → 登记。三段全在提炼那同一个异步任务里，顺序照下面这个走，**别把存图排在建笔记之前**（可重来的那几步排在唯一会失败的那步之后，这是这台机器上定过的规矩）。

1. **抓的时候把图的地址摘出来。** `_parse_wechat_article` 的返回体加一枚 `images: [str]`（只放 `mmbiz.qpic.cn` 系域名的绝对地址，按文档顺序去重）。`_parse_general_url`（非公众号）这一版**不做**，别顺手一起改——他只指了公众号。
2. **服务端按需下载这几张。** 这一步是新开一条出网面，安全闸门必须复用现成那两道，不许裸 `httpx.get`（见第四节）。
3. **传进云开发存储、拿回 `cloud://` fileID、把账写进 `assets`。** 通道形状照 `HUNYUAN_CF_URL` 那条（网关＋服务端 Key），在云开发侧加一个能 `uploadBuffer` 并回 `fileID` 的云函数动作；字节走这一路过去，服务端拿到 fileID 后**直接带 `note_id` 落一行**（不必先空着再 bind，服务端这一刻已经知道笔记建好了）。落点：`backend/app/tasks/ingest_tasks.py` 的 `process_url_task`（那里面 `scrape_url` 在前、`Note(...)` 在后，登记排在建完笔记那一步之后）。

### 通道为什么必须过一层云函数（不是可选项）

`assets.object_key` 存的必须是**真放进了云开发存储**才存在的 fileID。服务端今天有没有一条能直写云开发存储的凭据——**我实测的只有本机这份 `.env`：键名只有 `WECHAT_APP_ID/WECHAT_APP_SECRET`、`JWT_*`、`ADMIN_TOKEN`、`DATABASE_URL`、`REDIS_URL`、`CORS_ORIGINS`、`DEEPSEEK_API_KEY`，没有云开发存储的写凭据；服务器那台这份我没读，要另一路开工第一件事就是现读它一次**。而 `config.py` 里那两枚（`HUNYUAN_CF_URL`／`HUNYUAN_CF_KEY`）的形状是"网关地址＋API Key 打一个云函数"，**不是直写存储的密钥**。现网已经跑通的那条生产通道就是这个形状，云函数跑在环境里、天然能写存储——**所以图要进同一个桶，就得穿这一层**。

这一版要前置的一格（**我做不了，属云开发控制台的动作**）：新加／改那一个云函数并在「环境管理 → API Key 配置」给它一条网关地址与 Key，然后加进服务器 `.env`。⚠ 那条「切换为资源点计费」的红字写明**不可回退**，别在配这一格时顺手点。

### 上限与压缩（他拍的「压缩图片」「最多 9 张」落到数上）

- **张数**：`MAX_ASSETS_PER_NOTE`（9）唯一出处不改；文档顺序前 9 张，**下载阶段就只拉前 9 张**（别整篇几十张全拉回来再截），屏上明说截了几张。
- **字节**：压到现网那把尺子＝**≤500KB、长边 1920**（`imageCompress.js` 的 `BUDGET_BYTES`／`MAX_LONG_EDGE`）。⚠ 这把尺子今天是**客户端**那一头执行的（离屏 canvas 重绘＋`QUALITY_LADDER` 质量梯度），服务端**没有对应实现**——要在 Python 侧新写一份，并且：
  - 先看服务器上那套 `.venv` 真有什么能压图的库（`Pillow` 在不在要**现读 `requirements.txt` 与那台环境**，别照本机猜）；
  - 长边／预算这两个数**不许在第二处重打一遍字面量**，要给一处出处（客户端那枚在 `imageCompress.js`，服务端读不到它）——**推荐做法**：服务端另立一枚常量并在注释里指回 `BUDGET_BYTES`，判据钉"两处数值相同"，这样哪天抬预算两处一起红、不会只改一头。
  - 压完仍超 500KB 的那张：按客户端同一套语义记 `overBudget` 并照样存（那一路今天就是这么处理的：超预算不拦人），不许静默丢。
- **动图**：`sz_mmbiz_gif` 那系是动图。**这一版按原样存、不压缩动图**——⚠ **这条是我定的，他没拍过**（他只说"压缩图片"，没说要不要包括动图；压动图会掉成静帧，代价比压静图大）。要反过来只需一句"动图也压"。

## 四、安全四条（写代码时绕不过，不是待拍）

1. **SSRF 闸门要同样套在每个 `img src` 上。** 这些地址来自外部 HTML、不是他输入的。复用 `scraper.py` 的 `_validate_url`／`_is_private_ip` 那一套（含"域名解析出多个地址、只要有一个内网就整条拦"那条），**不许在这写第二份网段清单**。
2. **限体积、限张数、限超时。** 边下边数，超预算立刻断流（照 `_fetch_and_parse` 里 `MAX_RESPONSE_SIZE` 那种写法：先判字节再收全）。
3. **失败不许静默，也不许拖垮提炼。** 一条图下不动／传不上去 = 这一张记 `backup_status='failed'`（或直接不记，二选一，但**必须和现网"存图失败不挡主流程"同口径**：笔记照样建成，摘要照样出），屏上那句要说的是"有几张图没存上"，不是"抓取失败"。
4. **占位图不能当正文图存。** 见第二节那组实测：非微信 Referer 回的是 **200 + 2,090 B** 的 jpeg。判据不许只看状态码。

## 五、来源这一格（他拍的「像转存那样带上」，形状全是现成的）

他这句给的是**复用**，不是新建。现网"从别人分享页转存那一篇"已经有一套完整的来源记法，照它搬：

| 这一格 | 转存那一篇今天长这样（照它做） | 出处 |
|---|---|---|
| 存在哪 | `notes.imported_from`（一枚 JSON），钉住"抄自谁的哪篇、当时标题是什么、什么时候抄的" | `models/note.py` |
| 写了哪些键 | `share_token`／`source_note_id`／`author_user_id`／`author_name`／`title_at_import`／`imported_at` | `routes/notes.py` 的 `import_from_share` |
| 谁能改 | **编辑接口碰不到它**（不在 `NoteCreate`/`NoteUpdate` 里），已有负向钉：拿 PUT 去改 `imported_from` 改不掉 | `tests/test_share_snapshot.py:585-588` |
| 界面怎么读 | 服务端把 `imported_from.author_name` 倒进 `NoteOut.share_author_name`（转存那份优先于自己分享那一张的名字），两头都没有就**留空、不画名字、不拿"图麦"这类假名去填** | `routes/notes.py` 的 `share_author_name` 那一段 |
| 前端画在哪 | `index.js:382` `n.who = n.is_import ? (n.share_author_name \|\| '') : ''`，而 `n.is_import` 是**前端自己算的**：`n.source_type === 'share_import'`（`:378`） | `miniprogram/pages/index/index.js` |

⇒ 公众号这一路要做四件，**服务端只有"写"这一件**：

1. `_parse_wechat_article` 再取一枚**公众号名**（`og:article:author` 那类 meta、或 `#js_name` 那一格——属性名待第九节那格现读之后定），返回体加 `author`。
2. `process_url_task` 建 `Note` 时写 `imported_from`，键名**与转存那一路逐字同名**：`author_name`＝公众号名、`title_at_import`＝文章原标题、`imported_at`＝当时时间，另带一份 `source_url` 快照；`share_token`/`source_note_id`/`author_user_id` 这三键**没有对应物，就干脆不写**（不许塞空串或 0 当占位——读的那一头是 `.get("author_name")`，多写空值只会多造一种"画了个空名字"的态）。
3. `source_type` 保持现值 `wechat_article`（**不许改成 `share_import`**：那枚值在配额里有专门用途，`quota._is_his_first_note` 把它从"他自己动笔"里排出去、`credit_import` 的账也认它，改了就把 MIND 那两条账搞混）。
4. **前端改一句**：`index.js:378` 那个 `is_import` 只认 `share_import`，所以公众号那一篇现在画不出名字。要放宽成"有 `imported_from` 就画"（读 `share_author_name` 那句本身不用动）。⚠ 我上一版写的是"小程序一行不用改"，**那句现在不成立，作废**——加来源这条把它变了。

分发这一头他拍了"允许"，所以：公开分享页照现有那一条走（`shares` 快照本来就会带 `author_name`，露图张数认 `MAX_ASSETS_PER_NOTE`），**不新增开关、不给贴图另立一类**。

## 八、验收要能自证（判据形状，另一路照着立）

1. **反向钉**：拿一张 2,090 B 的占位图喂进去 → 必须被拒（只校状态码的实现会在这条红，那就是它假绿的证据）。
2. **防盗链那格**：下载请求**不许带**非微信 Referer；一条源码守卫扫这一路，出现 `Referer` 且值不是 `mp.weixin.qq.com` 就红。
3. **SSRF**：`img src` 写成 `http://169.254.0.23/...`、`http://[::]:6379/`、以及"域名解析到 10.0.0.5"三种，各拒一条（现成 `tests/test_scraper_ssrf.py` 那几例的形状可以直接复用到这一路）。
4. **上限**：一篇文章 HTML 里放 12 个图 → 只登记 9 行、只发 9 次下载、屏上有那句"只留下前 9 张"；放 3 张、其中 1 张下载失败 → 登记 2 行、笔记照建、`backup_status` 那格如实。
5. **压缩那把尺子两头同值**：服务端那个预算常量与 `imageCompress.js` 的 `BUDGET_BYTES`（500×1024）、长边与 `MAX_LONG_EDGE`（1920）逐字相等；**反向钉**：只改其中一头必须红（这条不立，将来抬预算只会抬出一套两真相）。
