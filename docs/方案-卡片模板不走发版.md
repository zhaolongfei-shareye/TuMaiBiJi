# 卡片模板不走发版 —— 技术架构方案

站长 10-04 拍：「后续如果要补充新的卡片模板，不走发版，请设计好技术架构。」
**这份只讲架构，不改代码、不碰现网、不部署。** 挑定之后再单独拆实现。

先说结论：**"不走发版"能做到的边界是"版式配方不走发版"，不是"新画法不走发版"。** 前者靠把现有画布解释器补上"配方层"就够了；后者要么发版，要么把渲染搬到服务端出图。这两条必须分开拍，混在一起会变成"以为加个接口就永久不用发版"。

---

## 一、今天为什么必须发版（读代码得到的现状）

一套卡片模板现在是**一段 JS 函数**，不是数据：

| 位置 | 现在长什么样 | 为什么它逼着发版 |
|---|---|---|
| `utils/poster.js:58-74` | `TEMPLATES` 十项、`TEMPLATE_GROUPS` 两组，硬编码在包里 | 列表就是数组字面量，加一项就得改这个文件 |
| `utils/poster.js:1663-1666` | `PLANNERS = { card: planCard, … spec: planSpec }` 十个函数 | 新增 id 必须在表里挂一个真函数 |
| `utils/poster.js:540-751` | `paintLayers(ctx, layers, images)`：`fill/grad/radial/rrect/circle/line/dots/text/image/avatar` **十种 op** | 这一层已经是数据驱动，**是好消息** |
| `utils/poster.js:1720` | `planPoster(ctx, note, templateId, profile, lang, opts)` | 出图前需要 `ctx.measureText` 实测（断行 `wrapText`、缩字 `fitSize`、竖排 `vcols`、字距 `trackingWidth`） |
| `utils/poster.js:1685` | `stripQr(plan, ctx, lang)`：关二维码时按"中心离码心近、面积≤码四倍"从图层里摘掉那几块 | 二维码那一档是**画完之后按几何反查**，不是模板自己写的 |

**要害在最后两行**：模板的高度、断行、字号是拿真 canvas 量出来的。所以"把模板做成一份写死坐标的 JSON"这条路走不通——中文/英文同一句话量出来宽度不同（现网十套各自都有 `SAMPLE_NOTE` / `SAMPLE_NOTE_EN` 两份内置笔记，就是为了这条）。

## 二、微信这条硬墙（不是我们自己设的）

官方《关于禁止小程序 JavaScript 解释器使用规范要求》：**禁止**用内置 JS 解释器（eval5、estime、evil-eval 等）动态执行 JS 代码或热更新 wxml，2022-07-06 起在审核环节处理。
所以**"下发一段模板代码让客户端跑"是被明令禁止的**，不是技术上做不到。能下发的只有**数据**。

由此得到本方案唯一成立的路子：**包内出一个"配方解释器"（写死的、可穷举的原语集合），服务端只下发配方。**

## 三、架构：三层，各层能不能"不发版"是明确的

```
第 1 层  绘制原语（op）        包内代码，穷举、封闭        改它 = 发版
第 2 层  排版原语（PRIMITIVES） 包内代码，穷举、封闭        改它 = 发版
第 3 层  配方（RECIPE）         服务端 JSON，可增可改        改它 ≠ 发版  ← 新增模板就在这一层
```

**第 1 层**：现有 `paintLayers` 那十种 op。要加第十一种（纹理、路径、SVG）就发版——这一层必须封闭，否则等于把渲染能力开放给远端。

**第 2 层**：把每个 planner 里"跟画法无关、只跟尺寸有关"的量抽成命名原语，每个原语自己完成实测：

| 原语（示例名） | 输入 | 出一层或几层 | 从哪个现有函数抽 |
|---|---|---|---|
| `fitTitle` | 文本、框、字号上下限 | 标题那叠 | `fitSize` + `wrapText` |
| `points` | key_points 数组、行宽、序号样式 | 要点那几行 | 各 planner 里重复的要点段 |
| `vcols` | 文本、列高、步长、最大列数 | 竖排列 | `poster.js:1145` |
| `plate` | 分类色 + 是否深色 | 方块/色底 | `glyphPlate` + `palette.schemeFor` |
| `qrSticker` | 位置、尺寸、墨色、引导语 | 码 + 垫底 + 那行字 | `poster.js:1278` |
| `foot` | 高度参数 | 底栏 | `footH` |
| `avatarAt` | 槽位角色 | 圆形形象图 | op `avatar` 的现算 |

**第 3 层**：一份配方 = 一个有序数组，每项是 `{ use: '原语名', at: {…}, with: {…} }`，加上画布参数（宽固定 `W=750`、大底色、是否吃分类色、码位开关）。**新模板 = 一行数据库记录**，用包内已有的原语拼出来。

`stripQr` 那条要跟着改口径：关二维码不再靠事后反查图层，而是配方里那一枚 `qrSticker` 原语按 `opts.showQr` 自己决定画码还是画那两行字。这是本方案唯一一处**动现有行为**的地方，实现时要单独钉一条尺子（十套都过一遍）。

## 四、分发、缓存与降级（照壁纸那条已经跑通的形）

1. **接口**：`GET /api/poster/templates` → `{ hash, templates: [{ id, group, label, labelEn, recipe, min_version, status }] }`。`hash` 是内容散列；客户端存上一次的值，一样就不重画选择器。
2. **包内永远留一份兜底**：现在这十套的配方内置在包里（由现有 planner 生成，等价于"包内版"）。弱网、后台没返回、返回被拦——一律走包内，**「生成笔记卡片」这颗按钮任何情况下不许变灰**。
3. **服务端校验闸门**（入库时跑，不信任任何下发值）：op 名在第 1 层白名单内、原语名在第 2 层白名单内、坐标在 0–750、字号有上下限、层数与文本总长有上限。**这一步是必须的**——脏 JSON 不用攻击，只要写错一个字段就能把画布画崩。
4. **客户端只丢弃、不猜测**：一条配方里出现不认识的 op / 原语 → **整套丢弃并回退包内那一套**，绝不做"跳过这一层继续画"。跳过会画出半张图，比整套不用更糟。
5. **灰度与回滚靠两个字段**：`min_version`（读 `utils/appInfo.js` 那个常量）决定"只有 1.9.26 以上才拿得到"，`status`（draft / live / archived）决定出不出现。新模板出问题 → 改一个 status，秒级收回来，**不发版**；这条正是今天壁纸那批的教训反过来用（旧值必须一直收得下，所以 `archived` 不删记录、只是不再下发）。

## 五、要新增的东西（清单，不含工时）

- 后端：`poster_templates` 一张表 + 一次 alembic 迁移 + 一个 GET 路由 + 一个 `validate_recipe()`；`deploy.sh` 预检补一条"表在不在、种子有没有灌"。
- 前端：`utils/poster.js` 里把十个 planner 的参数抽成第 2 层原语；加一个 `planFromRecipe()`；模板列表由"包内数组"改成"包内 ∪ 下发（按 id 覆盖）"。
- 「卡片模板」页：分组名后那个（数字）现在是数包内数组（#333），要改成数合并后的列表。
- 尺子：`验-模板配方.js`——钉三件事：① 包内十套与下发十套**逐层等价**（这条是解释器没跑偏的唯一证明）；② 下发一条改过的配方，客户端不重启就画出新样子；③ 下发脏配方 → 客户端回退包内、按钮仍可点。
- 现网探针：`backend/probes/poster_templates_live_probe.py`，拿 `deploy-test` 那个号跑（壁纸那把 16 条的形照搬）。

## 六、分阶段（每阶段都能单独停，且不破已跑通的链路）

- **P0｜先把"等价"证明下来**：抽原语 + 建表 + 下发 + 缓存 + 双端校验，**十套配方全部由包内 planner 转写成 JSON**，用户可见结果一张像素都不许变。这一阶段不发新模板，只买一件事：证明解释器可信。**P0 没绿就不许进 P1。**
- **P1｜真正的"不走发版"生效**：加第 11 套（只在服务端加一条记录），拿**已上线的那个包**实测能不能看到、能不能出图、能不能一条 status 收回来。这一步才是站长要的那件事，前面全是它的地基。
- **P2｜只在需要时才开工**：全新画法（第 1 层加 op，例如新的纹理/路径）——要么发版，要么走"服务端渲染出图、客户端只贴图"。后者是另一套架构：要服务器字体、自己实现中文断行与字距、每次出图一次后端往返、并且**私密笔记不能进这条**（沿用"私密不发正文"那道闸门），而且形象图现在只在本机，服务端拿不到。所以 P2 默认不做，除非出现"原语拼不出来"的具体那一张。

## 七、负面清单（明确不做）

- 不下发任何可执行代码；不装 JS 解释器（官方禁止，见 §二）。
- 不下发字体、SVG、模板位图。
- 不做"用户自己拖拽编辑模板"。
- P0 不撤包内那份 `TEMPLATES`——它是审核期和弱网的真相来源。
- 不让新模板绕过校验直接落库；不给客户端"字段不认识就跳过"的宽容路径。
- 不在这一批碰现网任何一条链路。

## 八、待拍三件事

1. **P0 值不值得做**：代价是把十个 planner 拆一遍（纯重构，用户看不到变化），收益是此后调版式、加同族模板都不用发版。不做的替代方案 = 每次加模板都发版（现状）。
2. **第 2 层原语先抽哪几个**：建议先抽 `fitTitle` / `points` / `qrSticker` / `plate` 四个——十套里都在重复，抽完就能拼出大多数变体。
3. **P2 那条要不要留门**：留门只在数据库字段上留 `render: 'client' | 'server'` 一个默认值，不写任何服务端渲染代码；不留门则完全按 P1 收口。
