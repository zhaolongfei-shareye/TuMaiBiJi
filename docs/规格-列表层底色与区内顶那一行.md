## 1. 底色只有一处出处：从底栏那一支派生，不许另挑色相

规则（`palette.chromeOf(壁纸)` 是唯一上游）：

```
层色 = HSL( 底栏 .bg 的 H, 底栏 .bg 的 S × 0.35, L 78 )
```

- **H 与 S 都取那一套壁纸自己底栏那一支**（`chromeOf(key).bg` 本身已经是"页面底的 H 原样、S 夹进
  [30,45]、L 20.5"），本规则只再乘一个饱和系数、并把明度抬到 78。
- **0.35 与 78 是站长点的**（原话：「饱和 饱和压到 35%／明度不动（还是你挑的 L78），只把白加进去」）。
- **禁止**再引入不属于这条派生链的色相。v27 那支 H340 的粉被打回，理由是同一屏出现两个不相干的
  色相（原话：「你为啥要用粉红？你不能用底部的 BAR 的色系来处理吗？」）。

**那枚黄为什么算"呼应首屏"：**现网 `index.js` 里那句 `tipDotStyle` 把 `TIP_DOT` 同时给了 Tips 行前面
那枚点和每一篇左边那枚分类点（`index.wxml` 的 `.xd-dot`）——它就是首屏上那两枚黄。屏上不许出现第二支黄。

⚠ **落码前先读这条：**`module.exports` 里**没有** `CREATE_SURFACE`，也没有 `PAPER`（导出表以 `lumOf`
结尾，10-08 现读）。效果图那边是用正则从 `palette.js` 源码里现读那一行，读不到就停。所以 wxss／页面
要引这两个值，只有两条路：**走 `createSkin()` 那条出口**（它已经把 `cp-panel`／`cp-ink`／`cp-ink-62`
发出来了，区内顶那一行正好全套复用），或者把 `CREATE_SURFACE`／`PAPER` 加进导出表。
**第三条路——在 wxss 里抄一遍 `#23252C`——是禁的**（色值只在一处，与 `TIP_DOT`／`chromeOf` 同一条规矩）。

## 4. 分类那一行（全部／旅游／生活／私密…）

- **撤胶囊**（现网是 `app.wxss` 的 `.chip` ＋ `index.wxss` 的 `.chip.tone`／`.cat-chips{gap:14rpx}` 那一套），
  换成与上面同一种手法：文字 + 选中一条短杠（高 4、通栏于字宽），`gap:40rpx`（撤掉底色后要拉开才不粘连）。
- **不再自带那条通栏横线**——与第 3 条是同一句分工：横线只有一条，在 tab 底下。
- 字色与短杠色吃**那一层自己的墨**（见第 6 条），**不跟黄**。
  ⚠ 这一条是效果图这一版的读法，站长点的是"笔记列表／笔记卡片那两枚底下的横杠"，**分类这行他没拍过**
  （要一起跟黄见 §11）。

## 5. 那一层的两条"边"与那条净空

站长的话是「灰底与背景之间不要有白边」。在效果图上量出来是两处，落码时**它们不是同一件事**：

1. **层顶那条 3rpx 的边** —— 它是 v23 给"深底"画的缝（`rgba(墨,.10)`），层换成浅灰之后比上面的照片底
   亮，就被读成一道白边。**撤掉。** 现网 `.sheet` 本来就没有这条边，所以这条只是"目标口径里不要加"，
   落码时**不要顺手补一条描边**。
2. **层停在浮栏上方露出的那条浅带** —— 那是效果图上一版把层写成 `bottom:150` 造成的，
   **现网结构里不存在**：`index.wxss` 的 `.sheet` 是 `flex:1` + `border-radius:40 40 0 0` +
   `overflow:hidden`，本来就铺到屏幕底，底栏是浮层。**这条不需要改代码，需要的是稿子与代码同口径**
   （效果图已改成 `bottom:0`）。

3. **最后一格不许切进浮栏**：现网 `.xlist{padding-bottom:150rpx}` 与 `.grid2{padding:22rpx 0 150rpx}`
   同一个数，注释里写的就是"滚到底时最后一条不被底栏那条胶囊压住"。**这条规矩现网已有**，
   这一版只是给它加了实测（列表 41.4px、卡片 160.4px）。

## 6. 字色档（浅面走墨，淡档由 4.5 反解）

- 判定顺序：先试纸白压得住吗（`cr(PAPER, 层色) ≥ 4.5`），压不住就整层翻成墨 `#23252C`。
  这一档四套全部**纸白压不住 → 字走墨**。
- 淡档（未选、三级字那一档）不写死：在 `.5 .55 .6 .66 .72 .78 .85 .92 1` 里取**第一个让对比 ≥ 4.5 的
  alpha**（象牙／天青落在 `.72`，樱落／雨雾落在 `.78`）。
- 半透明字要谈对比，必须先按实际底色混成实心再算（alpha 不落地就是假数）。

## 7. 已知代价（拍板当天就量下来写在这里的，别等到落码才发现）

- **白卡不是靠颜色与底分开的，是靠那圈投影**：白内框与这层的分离只有 **1.64~1.74**，门槛 3.0 不过。
- 那枚固定橙（`#E9723D`）直接压在这层上只有 1.74~1.84，也不到 3.0——但这一屏上橙只出现在白卡里面的
  "显示更多"，**不直接压层**，所以不构成问题。将来若有别的东西要直接压这层，得回到 v28 那种深度档。
- 层退到 L78 之后，"深色边框 / 白色内框"这个对比就没了，整屏靠**投影 + 那一行 `#23252C`** 分层。

## 11. 还没拍的（每条自带建议与代价；不拍就按上面"现状"继续跑）

1. **分类那一行的短杠要不要跟黄。** 建议：**先不跟**。理由是两行同色会把"哪一行是导航、哪一行是筛选"
   抹平；代价是屏上同时存在两种短杠色，看着像没做完。要改就一句话（§4 那条读法作废）。
2. **详情那一层与卡片页要不要先按同一把尺子补两屏。** 建议：**补**，落码前补。代价一次渲图（约 40 秒）。
   站长 10-08 说过"你只需要出笔记列表一种场景就行"，所以这两屏从 v29 起就没排进页面，
   生成器里那两个函数还在。
3. **`.sheet` 那条 `box-shadow: 0 -12rpx 28rpx rgba(18,20,26,.16)`（现网有）留不留。** 层变浅之后它
   是层与照片之间唯一的软过渡。建议留；代价是它和"不描边"那条读法要分清（阴影不是边）。
4. **这一档要不要跟着 2.0.0 那批一起提审。** 现状是本文全部未落码，与提审中的 2.0.0 无关；
   落码之后走 2.1.x 那一版。**这条不是设计问题，是排期问题，等他排。**
