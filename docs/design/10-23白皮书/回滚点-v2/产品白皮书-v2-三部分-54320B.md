# 第一部分 · 给用的人

## 1. 一分钟看完这个产品

图麦笔记是一个**把你已经看到的好内容，变成能用下去的笔记**的工具。

你大概有过这种时刻：读到一篇文章、看到一张图、听人讲了一个方法，当时觉得有用，随手存了。然后就想不起存在哪儿了。存下来这一步不难，难的是**存下来之后还能用上**。

图麦笔记做的就是中间这一段：

> **随手记下来 → 自动整理成清楚的笔记 → 需要时找得回来 → 排成一张能分享的图 → 别人扫一下，能把它存回他自己的笔记里**

四条它坚持的原则：

1. **不要求你先写。** 三条录入路——拍照截图、贴链接、贴文字——都是把你手上已经有的东西接进来。
2. **原文永远留着。** 自动整理出来的是标题、摘要、要点、标签，你的原文一个字不动，随时能回去核对。
3. **公开是你主动选的。** 笔记默认只属于你。要给别人看，必须你明确操作一次。
4. **整理只是辅助，不是替你判断。** 自动摘要可能不准，所以原文和出处一直在。

---

## 2. 它替谁解决问题

**学生与阅读者。** 课堂截图、文章摘录存了一堆，复习还是要重读一遍、手抄一遍、再想归到哪。图麦笔记把这三步合成一步：扔进来，出来就是带编号要点和标签的笔记，之后按关键词搜得到、按分类翻得到。

**年轻创作者。** 有观点、有资料，但要发出去还得花时间把文字排成一张好看的图。这里选好内容，挑一套卡片样式，直接出图存相册。十一套卡片不是"换个颜色"，是构图、层级和阅读节奏都不一样。

**日常记录者。** 旅行攻略、灵感、生活清单散在相册和聊天记录里。首屏一个入口，拍一张、贴一段就进来了。

---

## 3. 开始用：三条录入路

打开小程序，底部三个标签：**新建 / 笔记 / 我的**。记录从"新建"开始，一块面板里切换三种起点。

### 3.1 拍照或截图

从相册选图或直接拍。**一批最多 9 张**。系统会先读图上的文字，再走同一套整理流程。

**要知道的两件事**：读字效果受图片清晰度和排版影响，糊的、字太小的一张可能读不全；这不是商品识别，也不会替你估价——它认的是**文字**。

### 3.2 贴链接

把公众号文章或公开网页的地址贴进来，省掉复制长文那一步。

**要知道的**：需要登录、有付费墙、或者站点本身限制抓取的，会失败。失败了笔记不会凭空生成，会告诉你没成。

### 3.3 直接写或贴文字

自己写，或者把已有原文粘进来。**单次整理最多接受 12,000 字**。

这一路多一个开关，见下一节。

### 3.4 一个共同的提交动作

面板底部是**向右滑动才开始整理**，不是点按钮。这么设计的理由很实在：整理会花点时间，点按太容易误触。所以——**内容是空的拖不动；条件没满足就松手，滑块自己弹回去。** 三种起点共用这一块面板，切换入口不会把你跳走。

---

## 4. 整理出来的是什么

不管从哪条路进来，出来的都是同样四栏：

```
标题     一句话结论
摘要     这段内容在讲什么
要点     编号的几条，可长可短
标签     帮你之后归类和搜索
```

你的**原文单独留着**，和整理结果并存。想核对机器有没有理解偏，回原文看就行。

如果整理没成功，笔记照样存下来，只是少那四栏——**不会因为你贴的东西机器读不了，就把你的记录吞掉。**

---

## 5. 「原文翻译」这一枚开关，管什么不管什么

只有"直接写"这一路有它，而且要把面板展开才看得见。**默认关着。**

- **开着**：不管你贴的是英文、日文还是阿拉伯文，整理出来的标题、摘要、要点、标签**写成中文**。
- **关着**：整理结果**跟着原文的语言走**。英文原文出来就是英文笔记。

**三个容易误会的地方**：

1. **它不翻译原文。** 原文一个字都不动、不译。它只管"整理结果用什么语言写"。
2. **它不在链接和截图那两路上。** 那两路的输出语言由模型自己判断，不受这枚开关影响。
3. **它是一次性的。** 存好一篇之后开关自动归零，不会默认带到下一篇。

界面语言本身只有**中文和英文**两种，跟着你的微信语言走。"多种语言整理成中文"说的是上面这个能力，不是界面有几十种语言。

---

## 6. 记完之后怎么找回来

**笔记列表**（底部"笔记"）是你待得最久的一屏。

- **搜索**：按关键词搜标题、摘要和正文相关内容。你不必记得它当初是从哪个入口进来的。
- **分类**：把旅行、学习、工作的资料各归一堆。分类名和颜色可以自己改，可以排序。分类格里还有笔记时，那一格删不掉——防止一删把里面的东西带走。
- **列表 / 卡片两种看法**：同一批笔记，既能按文字快速扫，也能回看已经做好的卡片。
- **详情窗**：从列表点开一篇。左右滑换前后篇，遇到私密笔记会自动跳过。大图完整显示，不裁。
- **置顶**：常看的钉在上面。
- **编辑**：标题、正文、标签都能改。**配图长按拖动可以排序，第一张就是这篇的头图。**

新账号第一次打开不会是一片空白：有预置的示例笔记，也会引导你先做出一张卡片——**先看到成品，再开始记。**

## 7. 做成一张卡：十一套模板

选一篇笔记，进"分享"那一屏，挑一套模板，预览、出图、存相册。

**换模板不用跳页**：圆点横拖就能换，点模板名换整套，名字两侧有 `< >` 两枚箭头逐套走。

### 经典款（五套）

| 名字 | 长什么样 | 适合 |
|---|---|---|
| **图文卡** | 大图铺在上半，文字压在下沿 | 图本身就是要表达的东西：一次出行、一件作品、一处地方 |
| **玉版宣** | 标题先被看见，摘要与编号要点随后展开 | 把一节课、一个概念、一篇文章整理成完整知识单元。复习与回看首选 |
| **摘句** | 一条重点，独占自己的空间 | 摘录、感悟、短观点。分享时记得留出处和必要语境 |
| **叠翠** | 色块建主题，纸白内容区承接摘要与要点，头像连接上下两层 | 工作复盘、方法整理、行动提醒 |
| **规格卡** | 编号、细线、等宽元信息，条目秩序清楚 | 工具记录、出行准备、项目检查点。要快速定位细节时用 |

### 个性款（六套）

| 名字 | 长什么样 | 适合 |
|---|---|---|
| **素宣信笺** | 从右往左竖排，标题、正文、来源各占其位 | 随笔、引文、想留在纸面上的那段话。让文字慢下来 |
| **波普分格** | 同一幅形象去色、套色，组织成四格重复（不是四张独立照片） | 个人栏目、活动回顾、主题系列 |
| **网点漫画** | 网点、错位标题、硬阴影，印刷感 | 影评、设计观察、轻知识 |
| **荧光渐变** | 渐变、光晕与头像形成焦点，胶囊式要点把氛围接回内容 | 创作过程、灵感来源、数字文化记录 |
| **杂志封面** | 人物铺底，文字靠暗色渐变保持清晰 | 个人文章与栏目开篇。**只用你有权使用的肖像** |
| **纸间文艺** | 拱门、衬线与留白，有书页的节奏 | 旅行观察、生活随笔、读后感；打印出来继续批注也行 |

卡片上的**小程序码你可以选择在图上展示或不展示**。展示的话，别人扫了能进到这篇内容的公开页；不展示就只是一张图。

## 8. 分享出去之后会发生什么

这一步是产品里唯一"对外"的一层，边界要说清楚。

**你点分享、创建公开之后**：

- 系统为这一篇存一份**内容快照**——公开的是那一刻的标题、摘要、要点、标签和配图，**不是你的整个笔记库**。
- 生成一个公开入口，别人不用登录也能读。
- 同一篇笔记**只保留一张有效的码**，不会越分享越多份。

**你之后改了笔记**：**已经发出去的图片和已经被别人转走的副本不会跟着变。** 快照就是快照。

**你撤回公开**：公开入口关掉，别人再打不开。**但这收不回已经转存走的副本**——那已经是别人的笔记了。

**两件事不是一回事，别混**：

- **隐藏图上的小程序码** ≠ 撤回公开。前者只是让这张图不带入口，后者才真正关掉访问。
- **个人记录** ≠ **默认公开**。公开永远需要你做一个明确动作。

**分享出去的链接不设过期**，一直有效，直到你主动关掉。

---

## 9. 别人扫你的码，会看到什么、能做什么

- 打开是一个**公开落地页**，先读到内容，不用先注册、不用先装什么。
- 页面上有一枚**「存入笔记」**。按下去，这一篇会作为**独立副本**存进他自己的笔记库——之后他怎么改、删、再分享，都跟你无关。
- 你的**其他笔记他看不见**。他拿到的只有你公开的那一篇。
- 页面上有**举报入口**。内容有问题，可以直接报。

**这条链是双向的**：你转存别人的，和你被别人转存，是同一个机制。你的笔记被别人转存了几次，会在你列表那一格留一个标记。

---

## 10. 不想公开的，就留给自己

私密不是"把文字涂白"，是**在读取内容之前就拦下**。

- 私密是靠一个叫"私密"的分类来组织的，配六位数字密码。
- **没解锁的时候，内容根本不会传到手机上**——不是前端遮住。
- 私密笔记**不能分享**，也不能登记成卡片。
- 把一篇改成私密时，**它原来的公开入口会自动关掉**。
- 那一格里还有笔记时，分类删不掉。

密码忘了解决路径在设置里；改密码、验证、重置都在服务端完成。

## 11. 外观：心情、壁纸、背景、名片

这一层只改变"看起来是什么气氛"，**不改变任何笔记内容**。

**五档心情**（首页点「换心情」循环切换）：**墨 / 象牙 / 天青 / 樱落 / 雨雾**。切一档，面板、顶部导航条、底部标签栏一起跟着走。墨是默认档，也就是不加任何色彩倾向的那一版。

**四套壁纸**（莫兰迪色阶）：象牙 / 天青 / 樱落 / 雨雾，每套带自己的五档深浅。

**背景与亮度三档**：满月（不压）／半月（默认）／弯月（压到最暗）。字压在图上看不清时，往弯月走一档。没有个人图或运营图时会回到无图底色，不会白屏。

**名片四格**：形象图、名称、一句话。这是你分享出去的卡片上那个"作者是谁"的位置。

**哪些跟着账号走、哪些只在这台手机上**：名片的形象、名称、一句话和模板偏好会存到账号；**心情档只存本机**——换一台手机登录，心情不会跟过来。

## 12. 账号、数据与删除

**登录**：用微信号进，不需要另外注册账号密码。跨端场景支持 Apple 登录，微信身份和 Apple 身份可以用一次性六位短码合并成同一个人。

**你的数据存在哪**：笔记文字存在我们自己的服务上；图片（笔记配图、做好的卡片、名片图）存在微信云开发存储里，和你的账号绑定。

**删除是认真的**：

- 删一篇笔记，连带它的配图、卡片、分享记录和任务记录一起清。
- 注销账号会走一遍完整清理。
- 你随时可以自己清空本机数据。

**一条要如实说的限制**：图片对象只能由手机这一侧删除，服务端没有删它们的权限。所以**如果你在一台手机上删了笔记，另一台手机上还留着缓存的话，那份缓存要等它自己过期**。这一条我们记在已知缺口里（见 §30）。

**联系与举报**：落地页上有举报入口；后台对举报有保留期和处置流程。

## 13. 边界：这产品不做什么

写清楚，免得有人期待错。

- **不做手写识别。** "写"那一档是你打字或粘贴，不是识别笔迹。
- **不做商品识别、不做估价。** 拍照读的是图上的文字。
- **不做语音录入。** 这条能力已经下线。
- **不支持 HEIC 格式的图片。**
- **不做多端实时同步。** 手机是主，云端是备份与找回，不是多人协作。
- **没有团队、席位、权限管理。** 这是个人笔记工具。
- **不做内容审核豁免。** 你发布的内容会过内容安全检查；违规的会被挡下并提示。
- **卡片上的 AI 生成标识和来源信息不提供"去掉"的付费档。**
- **不承诺任何一篇内容"永久保存"。** 图片有留存周期，公开链接以你主动撤回为准。

## 14. 常见问题

**贴了链接没出笔记？** 大概率是那个地址需要登录、有付费墙，或者站点限制抓取。换"直接写"那一路，把正文粘进来。

**图上的字没读出来？** 图片太糊、字太小、或者文字是装饰性的都会读不全。截屏比拍屏好，单张比缩略图好。

**摘要不准怎么办？** 它会不准。原文一直在同一篇里，回去核对、直接编辑那四栏就行。

**换手机了笔记还在吗？** 笔记跟着微信账号在。图片大部分能回来（云端有备份），但缓存要重建。心情档只存本机，得重新选。

**别人能看到我多少东西？** 只能看到你明确公开的那一篇。其他的一律看不到。

**我发出去的内容能撤吗？** 能，关掉公开入口即可。但已经被人转存走的副本收不回。

**卡片能打印吗？** 能。纸间文艺、素宣信笺这两套就是按纸面阅读设计的。

**为什么整理要点右滑，不直接点按钮？** 因为整理会花几秒，点按太容易误触。右滑是一个"我确实要开始了"的动作。

## 15. 系统分层

```
客户端   微信原生小程序
           无 npm 依赖 · 无构建步 · 无 plugins · app.json 无 cloudfunctionRoot
           │
           │ wx.request → 唯一域名出处 https://api.agentsbin.cn/wtsj
           │ wx.cloud   → 只用云开发的「存储」，不调云函数
           ↓
服务端   FastAPI 0.115 + SQLAlchemy 2.0.36 + Alembic 1.14 + Pydantic 2.9
           异步：Redis 8.1 + RQ 2.12（队列名 default）
           限流：slowapi   身份：PyJWT（+ cryptography，为 SIWA 的 RS256）
           ↓
云函数   两只 Node 哑管道，由【后端】经 CloudBase HTTP 网关 + Bearer 长期 API Key 触发
           extract      文本进 → 四栏 JSON 出（内部 cloud.ai() → 混元）
           image_store  {cloud_path, base64} → {fileID, bytes}，上限 4MB
           ↓
模型     混元 hy3-preview（HUNYUAN_MODEL_ID 可覆盖）
```

**一条必须先知道的事实**：**小程序端没有任何 `wx.cloud.callFunction`**。两只云函数都由自建后端调用；小程序只碰云开发存储。看代码时别去找"前端调云函数"的地方，没有。

## 21. 存储与安全模型

**存在哪**：用户配图／卡片／名片在**微信云开发存储**（环境 `cloudbase-d6gzh0i0tff02943a`，`cloudUpload.js:17`）；账上存 `cloud://` fileID 而非 S3 key（`models/asset.py:36`、`note_card.py:59`）。运营图**不进云开发桶**，落服务器磁盘。

- **队列**：RQ ＋ Redis，生产端 `services/queue.py:18-19`、消费端 `worker.py:9-10`，**队列名两边都显式写 `default`**。三个长任务 `process_url_task`／`process_screenshots_task`／`process_manual_text_task`（`ingest_tasks.py:392,469,561`），入队点 `ingest.py:44-54,319-328,109-122`，均 `job_timeout=600`、`job_id=task_id`（uuid4 hex）。
- **状态回读**：Redis 键 `task:<id>`，TTL 3600 秒（`queue.py:11,31-50`）；客户端轮询 `GET /api/tasks/{task_id}`。截图原图先暂存在**进程内字典** `_batch_staging`，TTL 1800 秒、每批≤10 张、单张≤10MB、单批≤40MB、每用户≤2 批、全局≤120MB（`ingest.py:26,126-189`）。
- **幂等四层**：① RQ `job_id` 复用；② 外链贴图落账按 `object_key` 查重跳过（`note_images.py:432-434`，且屏上那句实话刻意数 `kept` 不是 `written`，`ingest_tasks.py:371-379`）；③ **数据库层五条部分唯一索引兜**（`ux_shares_one_active_per_note`、`ux_note_cards_one_current_per_note`、`ux_poster_templates_one_live_per_template`、两条 `ux_invitations_*`、`ux_mp_assets_kind_hash`），部署时逐条断言（`deploy.sh:119-273`）；④ 一次性短码"用过＋过期"两条一起判（`link_codes.py:8-13`）。**MIND 结算撞索引即视为已结过、不重试**（`services/quota.py:143-171`、`db/database.py:34-36`）。
- **重试**：只有提炼侧成建制——`MAX_RETRIES=3`、指数退避 1/2/4 秒，**且只重试可能自愈的**（429、5xx、超时、云函数显式回 `retryable:true`）；4xx（除 429）、云函数回不可重试、非 JSON 响应**都不重试**（`services/llm.py:12-13,159-216`；`TransientExtractError` `:33-38`；云函数侧负责标 `retryable`，`extract/index.js:74-94`）。access_token 失效（40001/42001/40014）清缓存后**只再打一趟**（`wechat.py:33,178-196,302-315,404-427`）。**RQ worker 级没配 `retries`，即默认不重投。**
- **超时表**：混元 `HUNYUAN_CF_TIMEOUT=90`（**必须大于云函数自身 60 秒**，`config.py:19-22`）、image_store 20 秒（`:96-98`）、抓取 30 秒＋正文 5MB＋最多 5 跳（`scraper.py:26,135`）、微信各接口 httpx 10 秒（`wechat.py:93,118,183,304`）、`code2session` 10 秒（`core/auth.py:83`）、Apple JWKS 10 秒（`core/apple_identity.py:37`）、任务 600 秒、nginx `proxy_read_timeout 30s`。
- **定时**：**仓库内没有应用层调度器**。已落地的定时只有那条每日备份 cron。举报保留期 180 天**不自动清理**，靠手工脚本 `probes/清-过期举报.py`（默认只算不删，须显式 `--执行`，`services/report_retention.py:19-22,83`）。
- **并发面**：api 与 worker 共写同一 SQLite，靠 WAL＋busy_timeout；`_load_task_user` 用 `generation` 水位线防"注销后 id 被复用、A 抓的内容写进 B 的笔记"（`ingest_tasks.py:210-235`）；`deploy.sh:491-516` 明确禁止游离于两个 unit 之外的进程抢端口／抢队列。
- ⚠ **`jobs` 表现网零写入**：全仓只在删笔记／注销时删它（`routes/notes.py:546`、`deletion.py:34,47`），`idempotency_key` **无任何赋值处**（全仓检索只命中模型定义）。**任务状态的事实只在 Redis。这一格不许写成"任务落库可审计"。**
