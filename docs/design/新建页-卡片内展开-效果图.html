深海壁纸

展开态在深色下不用改

卡片本身就是饱和色，深色壁纸只换页面底色和 tabbar；卡内控件的面色是同一组取值。
这套规则会带来四个后果，外加一条对"点截图没反应"的判断，确认一下
1

弹窗彻底删掉。现在那个"粘贴链接"浮层、以及它压在卡片上、深色下看不见遮罩的问题，一起消失。截图那条也不再依赖微信的相册/相机中间层。

2

"点空白收起"要占满整屏。实现方式是卡片区域外面铺一层透明点击区（页面根节点 bindtap + 卡片 catchtap），所以点标题、点空白、点 tabbar 都会收起。点输入框自己不收起。

3

手写不再跳页。原来点"手动撰写"是跳到单独的撰写页；按这套规则它就在卡里写完保存。好处是流程一致，代价是长文（几百字）在小卡里写会憋——如果你打算写长文，我建议卡片里只放标题+摘要，正文超过 300 字时"保存"旁边多一个"展开全屏写"。

4

动效只做高度。小程序里用 CSS transition 收 height 会抖（内容高度不固定），实际落地是"固定档位高度 + 220ms 过渡"：收起 72px、链接 232px、图片 232px（选图后 296px）、手写 320px。不做弹性/回弹动效，避免低端机掉帧。

5

"点截图没反应"这条我找到嫌疑了。现在的代码是 wx.chooseMedia({…}) 只写了 success，没有 fail 分支——相机/相册权限被拒、或者系统选择器起不来时，界面就是静悄悄什么都不发生，你看到的正是这个。改成卡内两个按钮后，拍照和相册各自加 fail 处理：拿不到权限就在卡内给一行"没拿到相机权限，去设置里打开"，而不是让你对着屏幕再点一次。
