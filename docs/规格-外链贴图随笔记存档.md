## 二、取图：两族两种形状（不许合成一套）

1. **公众号**（`mp.weixin.qq.com`）：正文 `<img>` **只有 `data-src`，`src` 是空的**（实测 26/26、3/3，
   无一条带 `src`）。`_content_images(el, base)` 按 `("data-src", "src")` 的优先级逐 `<img>` 取，
   文档顺序去重，协议补全走 `_http_image_url`（拒 `data:`，只留 http(s)）。
2. **小红书**（`xhslink.cn` 短链跳转后的末址）：笔记图**不在 DOM 里**，在
   `window.__INITIAL_STATE__` 那段 JSON：`note.noteDetailMap[<noteId>].note.imageList[].urlDefault`，
   作者名在同一段的 `user.nickname`。这段 JSON 不是严格 JSON（有裸 `undefined`），
   所以 `_xiaohongshu_extras()` 先扫引号配对截花括号（`_balanced_object`）、再把 `undefined` 换成 `null`，
   **解不开回 `{}`**（不抛、不影响正文那条）。
3. **谁走哪一族只看跳转后的末址**（`_is_xiaohongshu`）——这一枚**只选解析器，不闸下载**，
   不是域名白名单（方案第十一节那三条理由仍然成立：做成白名单就等于把"支持来源"阉了）。
   其它站这一版**一行没动**：正文图取不到就是 0 张，与做这个功能之前一样。
4. **张数与顺序**：取到几张就是几张（`total`），9 张上限只在**存**那一刀截，
   截掉的数量算出来（`ArchiveResult.truncated = total - kept - failed`）。

## 三、下载：两族防盗链的失败形状相反

| 族 | 不带 Referer | 带任何一个 Referer |
|---|---|---|
| `mmbiz.qpic.cn` | 200／683,938 B／PNG 800×1000 | **200**／2,090 B／JPEG **140×140 占位图**（状态码抓不到） |
| `sns-webpic-qc.xhscdn.com` | 200／12,046 B／1080×1444 | **硬 403** |

⇒ 三条硬规则，写在 `note_images.py` 模块头与 `tests/test_note_images.py` 的源码守卫里：
① `IMAGE_HEADERS` 里**一个 Referer 都不许有**（有源码级判据，写了就红）；
② 判据不许只看状态码——占位图那一格是 200；
③ `_inspect()` 用 Pillow **真解**：宽高与格式一律取自解出来的那张图，不照 URL 猜
（实测一条尾巴写 `/640?wx_fmt=png` 的地址回的是 JPEG、1080 宽）。

**占位图那一条只管静图**：`≤4,096 B` **且** `长边 ≤200` **且** 不是动图，三个条件同时成立才判它占位。
只管静图这一条不是理论——10-19 本机端到端实测到误杀：真文章里一张 47×91、1,242 B、25 帧的动图
被前两条命中、当成占位图丢掉了。微信那张占位是**静** JPEG，动图不可能是它。

其余形状：`follow_redirects=False` 手动跟跳（≤5 跳），**每一跳重过一遍 SSRF 闸**
（`_validate` 直接借 `scraper._validate_url`，不在这里写第二份网段清单）；
流式读、单张 `MAX_IMAGE_BYTES = 20MB`（与接口层那枚同一个数，不重打）；
`content-type` 不是 `image/*` 当场跳过；过网关那趟另有 `MAX_UPLOAD_BYTES = 4MB`（base64 解完再量，两头各一道）。

## 四、压：一把尺子两头同值

`MAX_LONG_EDGE = 1920`／`BUDGET_BYTES = 500 * 1024`／`QUALITY_LADDER = (0.7, 0.5, 0.3)`
必须与 `miniprogram/utils/imageCompress.js` 逐字相等。Pillow 吃 1–95，按 `q * 100` 折算。
三档都超预算**照样存**、只把 `over_budget` 记下来——"宁可大一点也不丢图"是客户端那把尺子写死的取舍。

- 动图（`sz_mmbiz_gif` 那一系）**原样存、不压**：压掉就成静帧。⚠ **这一条是我定的，他没拍过**（他只说「压缩图片」）。
  要反过来只需一句「动图也压」。
- 动图那一支的 `over_budget` 也照**纯字节比较**报（与客户端同一个式子）：实测那张 1078×233 的动图
  原样存就是 1,018,668 B，硬写 `False` 等于账上出现"两倍预算却记成没超"。

## 五、进桶：为什么必须穿一层云函数

`assets.object_key` 存的必须是**真进了云开发存储才存在**的 `cloud://` fileID，
而自建后端手里没有存储凭据（服务器 `.env` 现读：只有 `WECHAT_*`／`JWT_*`／`ADMIN_*`／`HUNYUAN_CF_*`／
`DATABASE_URL`／`REDIS_URL`／`CORS_ORIGINS`／`SHARE_QR_ENV_VERSION` 那些键）。
云函数跑在环境里，天然写得进用户自己上传那张图所在的那个桶。

- `cloudfunctions/image_store/index.js` 是一根**哑管道**：`{cloud_path, data(base64)}` 进 →
  `{fileID, bytes}` 出。不认身份、不碰数据库、不含业务分支（与 `../extract/index.js` 同一个纪律）。
  它自己那三道校验：路径必须 `images/` 开头／无 `..`／无空白／≤300 字符／不以 `/` 开头；
  base64 解完再量 ≤4MB；`cloud.uploadFile` 抛错回 `{error}` 而不是让它冒到网关。
- 打到它走的是**与混元同一个形状**：网关地址＋`Bearer` API Key
  （`https://cloudbase-<env>.api.tcloudbasegateway.com/v1/functions/<name>`）。
- **代码可以先上现网**：`channel_ready()` 缺任一行就整条不做、也不报错。这是刻意的——
  把这两行做成硬失败等于让下一次部署起不来（与 `APPLE_CLIENT_ID`／`ADMIN_TOKEN` 同一个理由）。

## 六、来源那一格：为什么不许动 `source_type`

`source_type` 保持 `wechat_article`／`web_article`，**不许改成 `share_import`**——
那枚值在配额里有专门用途（`quota._is_his_first_note` 把 `share_import` 排出去、
`_credit_import` 认它），改了就是把"他自己动笔"那一档算错钱。
所以列表那一格改吃服务端新加的 `NoteListItem.has_source`（`bool(imported_from.author_name)`）：

```
miniprogram/pages/index/index.js  →  n.is_import = n.source_type === 'share_import' || !!n.has_source
```

`has_source` **不进** `NOTE_BRIEF_FIELDS`（它不是能 PATCH 的字段，只在读列表那趟现场算），
`_attach_share_marks()` 里赋值。没有作者名时整份快照不写（`_source_snapshot` 回 `None`）——
宁可不画来源，也不画一句"来源："后面空的。

## 七、屏上那两句实话（截断不许静默）

详情页那排配图**下面**、面板**外面**，两句话各判各的数（`detail.js:shotsTruth()`）：

```
这篇原文有 {n} 张图，只留下了前 {k} 张。
有 {n} 张图没能存下来。
```

- 两个数都读服务端钉在 `imported_from` 里的那一份快照，**不拿本机行数倒推**：
  用户删掉一张配图之后，"原文当时有 26 张"这件事就再也问不出来了。
- 落点在 `wx:if="{{noteImages.length}}"` 那块面板**外面**：九张全没存上时那块面板根本不渲染，
  最该说的那一句恰好说不出。`docs/工具/验-贴图那两句实话.js` 的反向③钉的就是这一条。
- 中英两档四个键齐（`i18n.js` 的 `shotsTruncated`／`shotsPartlyFailed`）。
- ⚠ 这一版只上了**详情页**；首页那个详情窗没上（同一个窗口里配图那一排今天也还没上，见 §十）。
- ⚠ 通道没配时这四个计数键根本不出现在快照里 ⇒ 屏上一句都不报。这是对的（没做过的事不许说），
  但也意味着**上线那一趟之前，界面上看不见这一条链的任何痕迹**。

## 八、任务回体：四个计数怎么到客户端

`set_task_status(..., "completed", {...})` → `services/queue.py` → `routes/tasks.py`（**无 response_model**）
→ 客户端 `api.pollTask` 原样拿到。所以这四个键是**开放透传**里多带的，没有改任何接口契约：
`images_total`／`images_kept`／`images_failed`／`images_truncated`。
落点：合进 `notes.imported_from` 那一份快照（**这一枚落点是我定的**——它是"当时那一篇原文有几张"的
历史事实，跟着快照走最不容易被后来的编辑冲掉；他没指定放哪儿）。

`_archive_images()` 整段包在 try 里：存图这一趟炸了只进日志，笔记照建、摘要照出。
